# neo-pkg-bearing-analytics v1.0.0

[English](README.md) | [한국어](README.kr.md) | [日本語](README.ja.md)

Machbase Neo に蓄積した時系列データをもとに回転機械を分析する、ベアリングに特化した振動分析パッケージです。

> **人による診断を置き換えるものではありません。** 定期点検のあいだの空白を埋め、どこから見るべきかに優先順位を付け、
> 点検担当者が到着する前に、必要なスペクトルを画面に用意しておきます。
> 実測した性能と明示した限界については、[このツールが行うことと行わないこと](docs/scope.ja.md)をご覧ください。

## 概要

neo-pkg-bearing-analytics は、Machbase Neo の TAG テーブルに蓄積された振動センサーデータを、SQL や TQL を 1 行も書くことなく、すぐに対応へつなげられる設備健全性の情報に変えます。

中核は**ベアリング欠陥診断**です。1\~5 kHz の固定帯域での包絡線（エンベロープ）復調と、欠陥周波数（BPFO / BPFI / BSF / FTF）の照合によって診断します。この方式は、公開されている寿命試験（run-to-failure）データセットで検証しています。

等級が上がるのは、ベアリング欠陥の根拠があるときだけです。振動が大きいというだけでは上がりません。それは **ISO 10816 重大度** として別に表示します。回転機械に共通するパターン（アンバランス、ミスアライメント、ゆるみ）は、等級を付けずに*疑い*の所見として示します。これらを確定するには位相基準か軸方向チャンネルが必要ですが、このパッケージはそれを前提としていないためです。

ブラウザーでアプリを開くと、すべての設備がリアルタイムに等級判定されます。欠陥パターンが等級を付けるかどうかを決め、ISO 10816 ゾーンがその高さを決めます。どのタグでも掘り下げて波形・スペクトル分析を行い、ルールベースの故障診断と優先順位付きの推奨対応を確認し、ワンクリックで分析レポートを作成できます。

すべての分析は**決定論的**です。等級判定・診断・レポート作成に LLM は必要ありません。必要に応じて LLM を接続すると、詳細分析（상세분석）とレポートに文章形式の専門家所見を追加できます。

アプリは起動時に Neo インスタンスへ接続し、TAG テーブルを自動検出して実データで動作します。利用できる TAG テーブルがない場合は、モックデータで代用せず、説明メッセージとともに空の状態のままになります。画面に表示される値は、すべて DB に実在する値です。

## 対象ユーザー

- **保全・信頼性エンジニア** — 設備の状態をひと目で把握し、ベアリング欠陥を早期に捉え（アンバランス、ミスアライメント、ゆるみは疑いとして表示）、具体的な推奨対応を得られます
- **データエンジニア** — 独自のクエリ、チャート、しきい値ロジックを作ることなく、Machbase Neo 上で振動分析を提供できます

## 主な機能

- **リアルタイムモニタリング（모니터링）** — ライブのスパークラインを備えた設備カードのグリッド、欠陥パターンをゲートとする等級（良好 / 注意 / 危険 / 重大。アプリの画面では韓国語で 양호 / 주의 / 위험 / 심각 と表示）、いま等級を付けられない設備（停止、信号途絶、計測異常、回転数（RPM）またはベアリングの未入力）を数える**判定保留**（판정 보류）の件数、フィルターを兼ねる KPI サマリーバー、テーブルフィルター、ドラッグによるカードの並べ替え、絞り込み可能なイベント一覧を備えています。ヘッダーのトグルでアラーム判定のオン／オフを切り替えます。
- **詳細分析** — 選択したタグのスナップショットです。生波形、RMS / Peak-to-Peak / Crest Factor / 尖度（Kurtosis）のトレンド、欠陥帯域エネルギーのトレンド、ベアリング欠陥周波数マーカー（1× / 2× / 3×、BPFO / BPFI / BSF / FTF）付きの FFT スペクトル、包絡線、ケプストラム、スペクトログラム、帯域別の衝撃性（カートグラム）を表示し、高調波 / 側帯波の分析も行います。ベアリングの判定を左右するのは包絡線です。カートグラム、ケプストラム、スペクトログラムは状況把握のために表示するもので、意図的に等級から外しています（[このツールが行うことと行わないこと](docs/scope.ja.md)を参照）。
- **欠陥パターンによる等級ゲート** — 欠陥パターン（ベアリング欠陥周波数の位置に立つ根拠）が等級をオンにし、ISOゾーン（絶対基準。規格の定めどおり 10\~1000 Hz に帯域制限）がその高さを決めます。学習したベースライン（その設備自身の平常時に対する相対基準）と帯域エネルギー（周波数帯域ごとの相対基準）は、追跡して補助的な根拠として表示しますが、等級を上げることはありません。そのため、学習の有無にかかわらずタグの等級は同じになります。等級を決める 2 つの軸はどちらも学習を必要としないため、回転数とベアリングを入力すればすぐに等級判定が完結します。詳細分析とモニタリングは同じ規則を使います（[異常判定の仕組み](docs/detection.ja.md)）。
- **ルールベース診断** — 故障（アンバランス、ミスアライメント、ベアリングの内輪／外輪、ゆるみ、ギア）を自動で判定し、出典付きの根拠、根拠スコア、優先順位付きの推奨対応を示します。現在の測定では見分けられない故障は、低いスコアを付けるのではなく、理由とともに「測定不可」と表示します。
- **計測妥当性ゲート** — クリッピング、フラットライン、DC ドリフト、単発スパイクのパターンを検出すると、診断全体を「診断保留」状態にし、すべての候補の根拠スコアをまとめて下げます。不安定な測定はスペクトル全体に影響するためです。一定の DC オフセット（MEMS の重力軸、近接変位センサーのギャップ電圧）は注記するだけで、判定を妨げません。
- **アプリ監視／サーバー常時監視** — 開いているアプリで判定するほか、判定設定を Neo のタイマーとして登録し、アプリを閉じていてもイベントが蓄積され続けるようにできます。どちらのモードも*同じ*判定規則で動作し、監視が停止した、滞っている、あるいは判定する対象が残っていない場合はアプリが知らせます。そのため「イベントなし」が、気づかないうちに「監視が止まっている」ことを意味することはありません。1 つのアカウントで複数のタブや PC を開いても作業を分担し、判定と通知を行うのは 1 つだけです。
- **アラームとイベント** — イベントは 8 種類です。等級に関する 5 種類（観察、しきい値超過、状態継続、状態改善、正常復帰）と、監視の健全性に関する 3 種類（信号途絶、計測異常、計測復帰）があります。等級の変化は 2 回の判定サイクルにわたって連続で維持されてはじめて通知が送られ、重大度別の再通知とまとめ送信によって通知チャンネルが騒がしくならないようにしています。停止した設備は、回復とは見なさずに判定を凍結します。イベントはパッケージ用データベース（`NEO_BEARING_STORE`）内の TAG テーブルに保存され、CSV または JSON でエクスポートできます。
- **帯域エネルギートレンド** — オプションのサーバー側タイマーが、帯域別エネルギー（サブシンクロナス / 1× / 欠陥 / 高周波 / 超高周波）と包絡線の系列を抽出し、全体の RMS には表れない劣化も根拠として浮かび上がらせます。過去の区間をさかのぼって補完すれば、すぐに学習を始められます。
- **レポート作成（리포트 생성）** — キャンセル可能な進捗表示付きのワンクリック生成、選択したタグごとに 1 つの自己完結型 HTML ファイル、ページ送りできる保管庫（보관함。列は作成日時・レポート名・期間・種類）を備えています。レポートのチャートは操作できる状態のまま保存され、ホイールズーム、ドラッグ、ツールチップ、テーマに合わせた再描画が動作します。要約／全体表示の切り替えと判定フィンガープリントにより、数値が変わったのがデータの変化によるものか、判定エンジン（パッケージ）の変更によるものかがわかります。
- **柔軟な設定** — 別名を編集できる複数テーブルの選択、設備ごとの単位 / Class / RPM / ベアリング（欠陥周波数を自動計算するカタログ、または型番と形状の直接入力。すべり軸受（スリーブ）にも対応）、従動側センサーに対応したベルト駆動、ISO 機械クラス別のしきい値、ベースライン学習、Webhook 通知のルーティング、データ管理（使用量の確認と、期間指定／タグ別の整理）。
- **LLM 所見（オプション）** — Claude / OpenAI / Gemini / Ollama を接続すると、詳細分析とレポートに文章形式の専門家所見を追加できます。それ以外の機能はすべて LLM なしで動作します。

## 動作要件

- Machbase Neo 8.7.1 以降。
- 管理者（SYS）が、アプリの設定（설정）→ データソース（데이터 소스）画面からパッケージ用データベース `NEO_BEARING_STORE` を作成して各アカウントに一度だけ権限を付与し、分析対象のデータテーブルに `SELECT` 権限を付与します。
- 標準の `NAME · TIME · VALUE` カラムを持つ TAG テーブル。
- サーバー常時監視は、ROLLUP があるテーブルのみを判定します。

## 現在の状況

v1.0.0。実際の TAG テーブルのデータでのみ動作し、モック／デモモードはありません。すべての分析は決定論的で、LLM 所見のレイヤーはオプションです。通知は単一の Webhook チャンネル（Slack、Discord、Google Chat、または独自のエンドポイント）で送信されます。メールや SMS で受け取るには、n8n などの自動化ツールでその Webhook を中継します。
