# neo-pkg-bearing-analytics v1.0.0

[English](README.md) | [한국어](README.kr.md) | [日本語](README.ja.md)

Machbase Neo에 저장된 시계열 데이터를 바탕으로 회전기계를 분석하는, 베어링 중심의 진동 분석 패키지입니다.

> **사람의 진단을 대신하지 않습니다.** 정기 점검 사이의 공백을 메우고, 무엇부터 봐야 할지 순서를 매기고,
> 점검자가 도착하기 전에 필요한 스펙트럼을 화면에 띄워 둡니다.
> 실측 성적과 명시된 한계는 [이 도구가 하는 일과 하지 않는 일](https://machbase.github.io/neo-pkg-bearing-analytics/kr/scope/)을 참고하세요.

## 개요

neo-pkg-bearing-analytics는 Machbase Neo TAG table에 쌓인 진동 센서 데이터를 SQL·TQL을 한 줄도 쓰지 않고 바로 조치로 이어지는 설비 건전성 정보로 바꿔 줍니다.

중심은 **베어링 결함 진단**입니다. 1\~5 kHz 고정 대역의 포락선 복조와 결함 주파수(BPFO / BPFI / BSF / FTF) 대조로 진단하며, 이 방식은 공개 수명시험(run-to-failure) 데이터로 검증했습니다.

심각도 등급은 베어링 결함의 근거가 설 때만 오릅니다. 진동이 크다는 사실만으로는 올리지 않습니다 — 그건 **ISO 10816 심각도**로 따로 표시합니다. 회전기계 공통 패턴(불평형, 정렬불량, 기계적 풀림)은 등급을 매기지 않고 *의심* 소견으로 알려 줍니다. 이를 확정하려면 위상 기준이나 축방향 채널이 필요한데, 이 패키지는 그것을 전제하지 않기 때문입니다.

브라우저로 앱을 열면 모든 설비의 등급이 실시간으로 매겨집니다 — 결함 패턴이 등급을 매길지 정하고, ISO 10816 존이 그 높이를 정합니다. 어느 태그든 들어가 파형·스펙트럼을 분석하고, 규칙 기반 결함 진단과 우선순위가 매겨진 권고 조치를 받고, 클릭 한 번으로 분석 리포트를 만들 수 있습니다.

모든 분석은 **결정론적**입니다. 등급 판정·진단·리포트에 LLM은 필요하지 않습니다. 원하면 LLM을 연결해 상세분석과 리포트에 서술형 전문가 소견을 덧붙일 수 있습니다.

앱을 실행하면 Neo에 연결해 TAG table을 자동으로 찾고 실데이터로 동작합니다. 사용 가능한 TAG table이 없으면 목데이터로 대체하지 않고 안내 문구와 함께 빈 상태로 남습니다 — 화면에 보이는 값은 모두 DB에 실제로 있는 값입니다.

## 누구를 위한 패키지인가요?

- **정비 / 신뢰성 엔지니어** — 설비 상태를 한눈에 살피고, 베어링 결함을 일찍 잡고(불평형·정렬불량·풀림은 의심으로 표시), 지금 할 일과 구체적인 세부 조치를 받습니다
- **데이터 엔지니어** — 쿼리·차트·임계값 로직을 따로 만들지 않고 Machbase Neo 위에서 진동 분석을 제공합니다

## 주요 기능

- **실시간 모니터링** — 실시간 스파크라인이 붙은 설비 카드 그리드, 결함 패턴이 켜는 등급(양호 / 주의 / 위험 / 심각), 지금 등급을 매길 수 없는 설비(정지 · 신호 두절 · 계측 이상 · RPM이나 베어링 미입력)를 세는 **판정 보류** 수, 필터를 겸하는 KPI 요약 바, 테이블 필터, 끌어다 놓아 바꾸는 카드 순서, 걸러 볼 수 있는 이벤트 목록을 제공합니다. 헤더의 토글로 알람 판정을 켜고 끕니다.
- **상세분석** — 선택한 태그의 스냅샷입니다. 원시 파형, RMS / Peak-to-Peak / Crest Factor / 첨도(Kurtosis) 추이, 결함 대역 에너지 추이, 베어링 결함 주파수 마커(1× / 2× / 3×, BPFO / BPFI / BSF / FTF)를 얹은 FFT 스펙트럼, 포락선, 켑스트럼, 스펙트로그램, 대역별 충격성(커토그램)을 보여 주고, 하모닉 / 측대역 분석도 함께 합니다. 베어링 판정은 포락선이 이끕니다. 커토그램·켑스트럼·스펙트로그램은 맥락을 보여 주려고 띄울 뿐 일부러 등급에서 뺐습니다([이 도구가 하는 일과 하지 않는 일](https://machbase.github.io/neo-pkg-bearing-analytics/kr/scope/) 참고).
- **결함 패턴 게이트 등급 판정** — 결함 패턴(베어링 결함 주파수 자리에 서는 근거)이 등급을 켜고, ISO 존(절대 기준, 규격이 정한 대로 10\~1000 Hz로 대역 제한)이 그 높이를 정합니다. 학습된 베이스라인(자기 평소 대비 상대 기준)과 대역 에너지(주파수 대역별 상대 기준)는 추적해 근거로 보여 주지만 등급을 올리지는 않습니다. 그래서 학습 여부와 관계없이 태그의 등급은 같습니다. 등급을 정하는 두 축은 모두 학습이 필요 없어, RPM과 베어링만 입력하면 바로 등급 판정이 완성됩니다. 상세분석과 모니터링은 같은 규칙을 씁니다([이상 판정 원리](https://machbase.github.io/neo-pkg-bearing-analytics/kr/detection/)).
- **규칙 기반 진단** — 결함(불평형, 정렬불량, 베어링 내륜/외륜, 풀림, 기어)을 자동 판정하고, 출처를 밝힌 근거와 근거 점수, 지금 할 일 · 세부 조치(할 일과 이유)를 함께 보여 줍니다. 현재 측정으로 가릴 수 없는 결함은 낮은 점수를 주는 대신 사유와 함께 "측정 불가"로 표시합니다.
- **계측 유효성 게이트** — 클리핑, 플랫라인, DC 드리프트, 단발 스파이크 패턴이 보이면 진단 전체를 "진단 보류" 상태로 두고 모든 후보의 근거 점수를 함께 낮춥니다. 흔들리는 측정은 스펙트럼 전체에 영향을 주기 때문입니다. 일정한 DC 오프셋(MEMS 중력축, 근접 변위센서의 갭 전압)은 적어 두기만 하고 판정을 막지 않습니다.
- **앱 감시 또는 서버 상시 감시** — 열려 있는 앱에서 판정하거나, 판정 설정을 Neo 타이머로 등록해 앱을 닫아도 이벤트가 계속 쌓이게 할 수 있습니다. 두 방식은 *같은* 판정 규칙으로 동작하고, 감시가 멈췄거나 지연되거나 더 판정할 대상이 없으면 앱이 알려 줍니다 — 그래서 "이벤트 없음"이 조용히 "감시가 죽었음"을 뜻하는 일은 없습니다. 한 계정의 여러 탭이나 PC는 일을 나눠 맡아, 판정과 알림은 하나만 합니다.
- **알람과 이벤트** — 이벤트는 여덟 가지입니다. 등급 이벤트 다섯 가지(관찰, 임계 초과, 상태 지속, 상태 개선, 정상 복귀)와 감시 상태 이벤트 세 가지(신호 두절, 계측 이상, 계측 복귀)입니다. 등급 변화는 두 회차 연속 유지돼야 알림이 나가고, 심각도별 재알림과 묶음 발송으로 채널이 시끄러워지지 않게 합니다. 정지한 설비는 정상 복귀로 읽지 않고 판정을 멈춥니다. 이벤트는 패키지 데이터베이스(`NEO_BEARING_STORE`)의 TAG table에 저장되며 CSV나 JSON으로 내보낼 수 있습니다.
- **대역 에너지 추세** — 선택 기능인 서버 측 타이머가 대역별 에너지(서브동기 / 1× / 결함 / 고주파 / 초고주파)와 포락선 계열을 추출해, 전체 RMS로는 보이지 않는 열화도 근거로 드러냅니다. 과거 구간을 소급해 채우면 바로 학습을 시작할 수 있습니다.
- **리포트** — 중단할 수 있는 진행 흐름과 함께 원클릭으로 생성하고, 선택한 태그마다 자립형 HTML 파일 하나를 만들며, 보관함은 페이지로 넘겨 봅니다(생성일시 · 리포트명 · 기간 · 유형). 리포트 차트는 살아 있습니다 — 휠 줌 · 드래그 · 툴팁이 동작하고 테마에 맞춰 다시 그려집니다. 요약/전체 보기 전환이 있고, 판정 지문이 남아 숫자가 바뀐 것이 데이터가 달라져서인지 판정 엔진(패키지)이 바뀌어서인지 알려 줍니다.
- **유연한 설정** — 별칭 편집을 포함한 다중 테이블 선택, 설비별 단위 / Class / RPM / 베어링(결함 주파수를 자동 계산하는 카탈로그, 또는 품번과 형상 직접 입력, 저널(sleeve) 베어링 지원), 종동측 센서를 지원하는 벨트 구동, ISO 기계 Class별 임계값, 베이스라인 학습, 웹훅 알림 라우팅, 데이터 관리(사용량 확인과 기간별 / 태그별 정리).
- **LLM 소견 (선택)** — Claude / OpenAI / Gemini / Ollama를 연결하면 상세분석과 리포트에 서술형 전문가 소견이 덧붙습니다. 그 밖의 모든 기능은 LLM 없이 동작합니다.

## 요구 사항

- Machbase Neo 8.7.3 이상.
- 앱을 쓰는 계정마다 Neo API 토큰(Neo 콘솔의 방패 아이콘(Security) 패널에서 **New token**으로 발급)을 준비해 브라우저마다 한 번 앱에 입력합니다 — [API 토큰 입력](https://machbase.github.io/neo-pkg-bearing-analytics/kr/first-setup/#api-토큰-입력) 참고.
- 관리자(SYS)가 앱의 설정 → 데이터 소스 화면에서 패키지 데이터베이스 `NEO_BEARING_STORE`를 만들고 계정마다 한 번 권한을 주며, 분석할 데이터 테이블에는 `SELECT` 권한을 줍니다.
- 표준 `NAME · TIME · VALUE` 컬럼을 가진 TAG table.
- 데이터 테이블에 ROLLUP 설정 권장 — 없어도 동작하지만 원본 데이터를 직접 집계해 추이 그래프가 최근 구간(상세분석·리포트는 최근 2시간)으로 줄고, 서버 상시 감시에서는 빠집니다. 앱 설정 화면에 해당 테이블이 표시됩니다.
