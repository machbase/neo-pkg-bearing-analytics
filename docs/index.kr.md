# 진동 데이터 분석 기술 문서

**한국어** | [English](./index.en.md)

neo-pkg-vibe-analytics는 Machbase Neo TAG table에 쌓인 진동 센서 데이터를 SQL·TQL 작성 없이 설비 건전성 진단으로 바꿔 주는 패키지입니다.

브라우저로 앱을 열면 모든 설비가 ISO 10816 심각도 존 기준으로 실시간 등급이 매겨지고, 태그별 파형·스펙트럼 분석, 규칙 기반 결함 진단과 권고 조치, 원클릭 분석 리포트 생성까지 한 화면에서 이어집니다.

모든 분석은 **결정론적**입니다. 등급 판정·진단·리포트에 LLM은 필요하지 않습니다. LLM은 리포트와 이벤트에 서술형 전문가 소견을 덧붙이는 **선택 기능**으로만 연결됩니다.

## 설치

Machbase Neo 좌측 사이드 패널의 패키지 목록에서 `neo-pkg-vibe-analytics`를 선택하고 `Install` 버튼을 누르면 설치됩니다. 설치가 끝날 때까지 잠시 기다립니다.

### 제거

좌측 패널에서 `neo-pkg-vibe-analytics`를 선택하고 **Uninstall**을 누르면 패키지가 제거됩니다. 그동안 쌓인 이벤트·베이스라인·리포트 등 데이터는 보존됩니다. 이 패키지가 등록하는 타이머(감시·대역 추출·감시자)는 패키지 밖에 있으므로 제거 시 함께 정리됩니다. 다만 이 정리는 기본 포트(5654)로만 시도하므로, 다른 포트로 Neo를 운영한다면 제거 전에 앱에서 알람을 꺼 주십시오 — 그러면 앱이 먼저 타이머를 지웁니다.

## 동작 방식

앱을 실행하면 Neo에 연결해 TAG table을 자동으로 찾고 실데이터로 동작합니다. 사용 가능한 TAG table이 없으면 안내 문구와 함께 빈 상태로 남습니다 — 목데이터로 대체하지 않으므로, 화면에 보이는 값은 항상 DB에 실제로 있는 값입니다.

분석은 전부 패키지 내부에서 결정론적으로 계산됩니다. RMS·FFT·포락선·첨도·베어링 결함 주파수 같은 신호처리와 ISO 10816 등급 판정은 외부 호출 없이 브라우저와 패키지 코드 안에서 처리됩니다.

## 화면 구성

상단에 세 개의 주 탭과 설정(⚙) 진입점이 있습니다. 헤더 오른쪽에는 알람 토글과 테마 전환이 함께 있습니다.

| 탭 | 용도 |
| :--- | :--- |
| 모니터링 | 설비 카드 그리드, 심각도 등급, KPI 요약, 이벤트 목록, 알람 토글 |
| 상세분석 | 선택 태그의 스냅샷 — 파형·추이·FFT·포락선·켑스트럼·스펙트로그램·결함 대역 탐색, 규칙 기반 진단 |
| 리포트 생성 | 진동 분석 리포트 생성·미리보기·보관함 |
| 설정 | 데이터 소스 · 설비 정보 · 판정 기준 · 알람 설정 · LLM 연동 |

## 이상 판정

한 태그는 세 가지 관점에서 동시에 판정되고, **가장 나쁜 결과가 그 설비의 등급**이 됩니다.

| 기준 | 질문 | 학습 필요 |
| :--- | :--- | :---: |
| ISO 존 | 국제 규격 기준으로 절대적으로 높은가? | 아니오 |
| 베이스라인 | 이 설비의 평소와 비교해 높은가? | 예 |
| 대역 에너지 | 특정 주파수 대역만 유독 높아졌는가? | 예 |

ISO 존만으로는 고주파가 지배하는 센서에서 베어링이 나빠져도 화면이 계속 양호로 보입니다. 세 기준을 함께 쓰는 이유입니다. 자세한 내용은 [이상 판정 원리](./detection.kr.md)에 있습니다.

## 감시 방식

알람 판정은 두 가지 방식 중 하나로 동작합니다. **설정 → 알람 설정**에서 고릅니다.

| 방식 | 판정 주체 | 앱을 닫으면 |
| :--- | :--- | :--- |
| 앱 감시 (기본) | 브라우저에 열린 앱 | 판정이 멈춥니다 |
| 서버 상시 감시 | Neo 타이머 | 계속 판정하고 이벤트를 쌓습니다 |

두 방식은 같은 판정 규칙을 쓰므로, 모드를 바꿔도 같은 데이터에서 같은 결과가 나옵니다. 자세한 내용은 [알람과 이벤트](./alarms.kr.md)를 참고하세요.

## LLM 프로바이더 (선택)

리포트·이벤트에 서술형 소견을 덧붙일 때만 사용합니다. 네 가지 프로바이더를 지원합니다.

| 프로바이더 | API | 로컬 |
| :--- | :--- | :---: |
| Claude | Anthropic API | 아니오 |
| OpenAI | OpenAI API | 아니오 |
| Gemini | Google Gemini API | 아니오 |
| Ollama | Ollama REST API | 예 |

연결하지 않아도 등급 판정·진단·리포트는 모두 정상 동작합니다.

## 저장되는 데이터

패키지는 다음을 Neo에 만들어 씁니다. 설정 저장·알람 판정 과정에서 자동으로 생성됩니다.

| 이름 | 종류 | 내용 |
| :--- | :--- | :--- |
| `NEO_VIBE_EVENTS` | LOG table | 이벤트 이력 (자동 삭제 없음) |
| `NEO_VIBE_MONSTATE` | LOOKUP table | 태그별 판정 상태 (연속성·재알림 판단용) |
| `NEO_VIBE_BASELINE` | LOOKUP table | 학습된 정상 상태 (μ·σ) |
| `NEO_VIBE_BAND` | TAG table | 대역 에너지 추세 (대역 감시를 켠 경우) |
| `/vibration-reports` | 파일 | 생성된 리포트 HTML |

설정은 DB가 아니라 패키지 안의 JSON 파일(`cgi-bin/config/`)에 저장됩니다 — 데이터 소스·설비 정보·판정 기준·알람·LLM이 각각 한 파일입니다. 패키지를 제거하면 이 설정 파일은 함께 지워지지만, 위 표의 이벤트·베이스라인·리포트는 남습니다.

## 기본 작업 순서

1. Neo에서 패키지를 설치하고 앱을 엽니다.
2. **설정 → 데이터 소스**에서 분석할 TAG table과 태그를 선택합니다.
3. **설정 → 설비 정보**에서 단위·RPM·베어링 모델·ISO Class를 등록합니다. (권장)
4. **설정 → 판정 기준**에서 머신 클래스와 임계값을 확인하고, 필요하면 정상 상태를 학습시킵니다.
5. **설정 → 알람 설정**에서 감시 방식과 평가 주기·윈도우를 정하고 알람을 켭니다.
6. **모니터링** 탭에서 설비 상태를 확인합니다.
7. 이상 징후가 보이는 카드를 눌러 **상세분석**으로 들어갑니다.
8. **리포트 생성**에서 대상 태그와 기간을 골라 분석 리포트를 만듭니다.
