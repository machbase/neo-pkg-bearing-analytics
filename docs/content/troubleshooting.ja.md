#

アプリの画面は韓国語です。ここではメッセージを日本語訳で示し、必要に応じて韓国語の表記を併記します。

## データベースにアクセスできないという案内だけが表示される

ログインしたアカウントに、保存先（`NEO_BEARING_STORE`）の権限が付与されていない状態です。管理者（SYS）が設定 → データソースの **パッケージ利用アカウントの権限**（패키지 사용 계정 권한）一覧で、そのアカウントの行の **権限付与**（권한 주기）を押せば解決します。付与されたかは、その行の状態（권한 있음）で確認できます。
付与された後に `状態確認`（상태 확인）を押すと、再読み込みせずにそのまま続行できます。

SYS でログインしているのにこの案内が表示される場合は、データベースがまだ作成されていません。同じカードの `作成`（만들기）を押します。

## サーバー監視をオンにしたのにイベントが1件も発生しない

まず、モニタリング画面の最上部にある監視状態の警告を確認します。

- **「判定対象が0件です」** — タイマーは動いていますが、すべてのタグをスキップしています。よくある原因は **データテーブルの権限** です。一覧や画面は表示されていても、サーバー監視はそのテーブルを直接照会するため、登録したアカウントに `SELECT` 権限がないと、何のエラーも出さずに0件で終わります。管理者に `GRANT SELECT ON MACHBASEDB.SYS.<テーブル> TO <アカウント>;` を依頼してください。テーブルにROLLUPがない場合や、新しいデータが入ってこない場合も同じ警告が表示されます。
- **「N台をスキャンしましたが、欠陥パターンを測定できたタグが0件です」** — 判定は動いていますが、等級をオンにする軸が空の状態です。RPM・ベアリングモデルがないか、判定ウィンドウのサンプルが不足しています。**設備情報を開く** ボタンで移動して入力します。
- 警告がない場合は、下記の [イベントが記録されない](#イベントが記録されない) を確認します。等級イベントは抽出周期（既定10分）ごとに、しかも2回連続してはじめて確定するため、オンにしてすぐには発生しません。

## タイマー一覧に同じ名前が複数ある

Neo はタイマー名の重複を防ぎません。アプリは登録前に同じ名前のタイマーをすべて削除し、本当に削除されたかを確認しますが、一覧の取得が失敗している間（例：DB負荷）に生じた重複は、その時点では防げません。
負荷が解消した後に **サーバー監視をオフにしてから再びオンにすると**、自動的に整理されます。急ぐ場合は Neo のタイマー画面から直接削除します。
**停止してから削除する** 必要があります。停止せずに削除だけすると、実行され続けることがあります。

## 「設定を読み込めませんでした」（설정을 불러오지 못했습니다）画面が表示される

アプリの起動時に、保存された設定を読み込めなかった状態です。この場合、アプリはタブを開きません。既定値で画面を表示したまま保存すると、実際の設定を上書きしてしまうためです。

- **設定を読み込めませんでした** — たいていは一時的な接続の問題です。設定はDBにそのまま残っているので、**再試行** を押します。
- **<領域>の設定を読み込めません** — 保存中に接続が切れ、その領域（例：設備情報）の設定の一部が破損した場合です。再試行しても同じ結果であれば、**<領域>のみ既定値で開く** を押します。残りの設定は保存どおりに読み込まれ、その領域の設定画面に移動します。押すだけでは何も保存されないため、その領域を設定し直してから保存してください。

## 設備カードが1つも表示されない

- アプリが「DBでTAGテーブルが見つかりませんでした」と表示する場合は、Neoには接続できたもののTAGテーブルがない状態です。Neoの接続状態とTAGテーブルの有無を確認します。この場合、モックデータで代替しないため、画面は空のままになります。
- テーブルはあるのにカードがない場合は、**設定 → データソース** でまだテーブルを選択していません。分析するテーブルを選択して保存します。
- 「表示するテーブルが1つも選ばれていません」と表示される場合は、モニタリング画面の **テーブルフィルター** ですべて非表示にしています。**すべて表示** を押します（監視はそのまま動いています）。
- 「データ読み込み失敗」と表示される場合は、選択したテーブルの照会中にエラーが発生しています。メッセージに原因も併せて表示されます。
- 「データを読み込めませんでした」と表示される場合は、選択したテーブルを照会できなかった状態です。選択はそのまま残っており、自動的に再試行します。下記の「データを再読み込みできませんでした」を参照してください。

## 「データを再読み込みできませんでした」（데이터를 다시 불러오지 못했습니다）バナーが表示される

設定を保存した後や新しいタグが検出されたときに、データを読み直す途中でテーブルの照会が失敗した状態です。

- 監視は止まりません。**最後に読み込んだデータで監視を続けながら**、自動的に再試行します（10秒から間隔を2倍ずつ延ばし、最大5分）。
- その間、**新しく選んだテーブルは監視されません**（バナーに名前が表示されます）。選択から外したテーブルは、保存した時点で監視から外れます。
- 選択はすでに保存されているため、保存し直す必要はありません。再試行が1回成功するとバナーが消え、通常の監視に戻ります。待ちたくない場合は **今すぐ再試行** を押します。
- 失敗が続く場合は（3回目からバナーに案内が付きます）、バナーに記載されたテーブルが削除されていないか、権限が回収されていないかを確認し、必要に応じて **設定 → データソース** で選択を外して保存します。
- 失敗している間は、サーバー監視タイマーを作り直しません。不完全な一覧でタイマーを修正すると、読み込めなかった設備がサーバー監視からも外れてしまうためです。

## タグが一部しか表示されない

読み込み上限のためです。**テーブルあたりタグ60個**、**全体で設備100台** までしか読み込みません。クエリの殺到を防ぐための制限です。上限にかかったタグには、データソースの別名表で **監視除外**（감시 제외）バッジが付きます。

分析対象のテーブルだけを選択して範囲を絞るか、対象を分けて確認します。

## データソースでテーブルを選択できない

一覧で薄く表示され、チェックできないテーブルは、カラム構成が `NAME · TIME · VALUE` ではないテーブルです（理由も併せて表示されます）。このアプリは標準のカラム名のみを照会するため、まだサポートしていません。

## データソースに追加したばかりのタグが表示されない

- データソースの一覧は、画面を開いた時点のものです。タグを新しく追加した場合は、設定画面を開き直して一覧を更新します。
- モニタリング画面の上部にデータソース変更のバナーが表示されている場合は、**再読み込み** を押します。

## プリセット（1時間・6時間など）が無効になっている

そのタグのデータがプリセットの長さより短いという意味です。

- 押してみると「データが不足しています」という案内が表示されます。
- **全体** プリセットで確認すると、そのタグのデータの全区間を見ることができます。
- データがさらに蓄積されると、プリセットは自動的に再び有効になります。

## 詳細分析がリアルタイムで更新されない

正常です。詳細分析は、開いた時点で固定される **スナップショット** です。最新の状態を見るには、**更新** を押すか、詳細分析をいったん閉じて開き直すか、タグを切り替えて再キャプチャします。

## 「信号異常 — センサー点検が必要」（신호 이상 — 센서 점검 필요）警告が表示される

クリッピング（飽和）・フラットライン・DCドリフト・単発スパイクのように、**測定そのものが疑わしいパターン** が検出された状態です。このとき診断は **診断保留** 状態になり、すべての欠陥候補の根拠スコアがまとめて下がります。

- 信頼度は特定の候補だけでなく **すべて** 下がります。測定が揺らぐとスペクトル全体が影響を受けるため、一部だけを下げると、検証されていない候補がかえって1位に浮上してしまいます。
- 飽和した信号から読み取った振幅は、実際より **低く** 出ます。その値は実際の振幅の下限とみなしてください。
- 機械を疑う前に、センサー・ケーブル・マウンティング・接地をまず確認してください。
- 警告ボックスがなく、灰色の「DC 성분」（DC成分）の案内だけであれば、異常ではありません。平均値は大きいものの一定しているセンサー（MEMS加速度計の重力軸・近接変位センサー）であり、判定はそのまま進みます。判定を止めるのは、平均値が揺らぐ **DCドリフト** だけです。

## カードに「判定保留」（판정 보류）バッジが表示される

その設備には現在、等級を付けていないという意味です。バッジにマウスを重ねると、理由と直前の確定等級が表示されます。

| 理由 | 意味 | 対処 |
| :--- | :--- | :--- |
| 判定不可（판정 못 함） | RPMやベアリング形状がないため、欠陥パターンを組み立てられません。ジャーナル（sleeve）ベアリングもこれに該当します | 設備情報でRPM・ベアリングモデルを入力（ジャーナルベアリングは等級の対象外です） |
| 欠陥パターン初回測定待ち | アプリを開いた直後のように、まだ一度も測定していません | 初回測定が終われば解除されます（通常は数秒、タグが多いともっとかかります） |
| 欠陥パターン測定失敗 | 元の波形を読み込めなかったか、サンプルが不足していました。直前の等級を維持します | 次の判定回で再測定します。続く場合はそのタグのデータ収集を確認 |
| 判定待ち（판정 대기） | 最初の判定回を待っています | しばらく待ちます |
| 停止（정지） | 設備が止まっているため、判定を凍結しました | 対処不要 — 運転が再開されれば判定も再開 |
| 信号途絶（신호 두절） | データが入ってきません | 収集経路を確認 |
| 計測異常（계측 이상） | 波形が信頼できません | センサー・ケーブル・マウンティングを確認 |

測定できなかった回を「パターンなし = 良好」と読むと、アラーム中の設備が誤って「正常復帰」と確定してしまうため、アプリは判定を保留して直前の状態を維持します。

## アプリを開き直したらアラームがオフになっている

- ヘッダーのアラーム表示は、押した時点ですぐに保存されます。開き直したときにオフになっている場合は、**設定タブのアラームスイッチ** でオンにして保存しなかったか（**破棄して移動** を含む）、保存に失敗した可能性があります。保存に失敗するとエラーが表示され、表示が元に戻ります。
- ヘッダーのアラーム表示を押して、再びオンにします。別途保存する必要はありません。

## ヘッダーのバッジが「앱 · 보기 전용」（アプリ・閲覧専用）と表示される

同じアカウントで別のタブやPCにアプリが開かれており、そちらが判定・通知を担当しています。正常です。通知が重複して送られないよう、1か所だけで判定します。

- このタブでも、設定の保存・学習・レポートはそのまま行えます。保存すると、担当タブが10秒以内に反映します。
- 担当タブを閉じると、1分以内にこのタブが引き継ぎ、バッジが **앱** に変わります。

## 「다른 계정으로 로그인되었습니다」（別のアカウントでログインされました）という案内が表示される

同じブラウザーで、Neoコンソールのログインが別のアカウントに切り替わりました。この画面は以前のアカウント用のため、保存・判定・照会をすべて停止しています。

- 新しいアカウントで使うには、**새로고침**（再読み込み）を押します。
- 以前のアカウントで使い続けるには、そのアカウントで再ログインします。案内が消え、そのまま動作を続けます。

## 詳細分析に、回転数がスペクトルで測定した値と異なるという警告が表示される

入力したRPMとスペクトルの回転ピークが、2%を超えて食い違っています。よくある原因は、同期速度（1800・3600）を入力した場合です。

- 欠陥パターンは入力値で照合し、許容誤差が1%であるため、そのままにすると欠陥を見逃すおそれがあります。
- 銘板の定格回転数を確認して修正するか、**実測値 N rpm で保存** ボタンを押します（すぐに保存されます）。実測値は測定時点の負荷を基準とした値です。
- **ベルト従動側のセンサー** の場合、警告は「従動軸回転数 … プーリ換算（または入力値）が … 異なります」と表示されます。ベルトのスリップや、プーリ径（外径ではなく **ピッチ径** になっているか）を確認してください。この場合、実測値保存ボタンはモーターRPMではなく **従動軸回転数** 欄に保存します。
- 2極電動機のように回転ピークが系統周波数（60・50 Hz）と重なる場合は実測を行わないため、この警告も表示されません。銘板値を正確に入力してください。

## 時刻が数時間ずれて見える

画面の時刻は **設定 → データソース → 表示タイムゾーン** に従います。既定値はこのブラウザーの時刻なので、別の地域で開くと、その地域の時刻で表示されます。

- 全員が同じ時刻を見る必要がある場合は、表示タイムゾーンを工場の現地時刻などに固定して保存します。
- データ自体はタイムゾーンと無関係に照会されるため、表示がずれて見えるだけで、欠けているデータはありません。
- サーバー通知の文面に含まれる時刻は、サーバー監視を登録したときのオフセットを使います。サマータイムが切り替わった後は、アプリを一度開くと新しいオフセットで再登録されます。

## イベントが記録されない

まず、画面の最上部に **監視状態の警告** が表示されていないか確認します。監視そのものが止まっているケースが最も多く、ほとんどはその場所にある **再登録** ボタンで解決します。

警告がない場合は、次の点を確認します。

- **アラームがオンになっているか** を確認します。判定はアラームがオンの間だけ動作します。
- **アプリ監視モードの場合は、アプリが開いている必要があります。** アプリを閉じても監視を続ける必要がある場合は、**サーバー常時監視** に切り替えます。
- **良好が続いている間は記録しません。** 注意以上と、悪い状態からの復帰だけが記録されます。
- **悪い状態のまま良くなっていく途中段階**（重大 → 危険 など）は、個別には記録されません。代わりに、状態改善イベント1件で代表されます。
- **等級は2回連続してはじめて確定します。** 1回だけ出たものは `観察` としてのみ残ります。
- **RPM・ベアリングモデルが空欄だと、等級イベントはまったく発生しません。** 等級をオンにする軸は欠陥周波数グリッドであり、回転数や幾何形状がないとグリッドを作れません。カードには **判定保留**（判定不可）と表示されます。
- **振動が高いだけの状態では、イベントは発生しません。** ベアリング欠陥の根拠が成立してはじめて等級が上がります。アンバランス・ミスアライメント・ゆるみは、詳細分析に「ベアリング欠陥の兆候なし・振動レベル … 区間 — アンバランス・ミスアライメント・ゆるみなど、ベアリング以外の原因の点検を推奨」（베어링 결함 징후 없음 · 진동 수준 … 구간 — 불평형·정렬불량·풀림 등 베어링 외 원인 점검 권장）と表示されるだけです。
- **ベースライン・帯域はイベントを生成しません。** 逸脱しても根拠表に表示されるだけです。
- **等級の判定は抽出周期ごと（既定10分）に1回です。** 悪化したばかりの設備は、次の回まで待たないとイベントが発生しません。

## 「判定対象が0件です」（판정 대상이 0개입니다）警告

タイマーは正常に動いていますが、監視対象のタグを1つも判定できていない状態です。タイマーの状態だけを見ると正常に見えるため、アプリが別途警告を表示します。

- 監視タグに **新しいデータが入ってきていないか**、データ収集側（センサー・収集器・取り込みパイプライン）を確認してください。
- サーバー常時監視の場合は、そのテーブルに対する **`SELECT` 権限** と **ROLLUP** の有無も確認してください。上記の [サーバー監視をオンにしたのにイベントが1件も発生しない](#サーバー監視をオンにしたのにイベントが1件も発生しない) を参照してください。

## 設備が停止したのに「正常復帰」（정상 복귀）通知が来ない

正常な動作です。判定値が普段の20%未満に下がると、アプリはこれを **設備停止** とみなして判定を凍結します（カード：停止バッジ）。

振動の欠陥は自然に治ることはないため、説明のつかない低下は、たいてい設備が止まったか、センサーの信号を失ったことを意味します。ここで「正常復帰」を通知すると、設備が修理されたと誤解されてしまいます。

凍結中は直前の状態をそのまま維持するため、再稼働しても、以前に悪かったという事実はそのまま残っています。

## 状態が短い間隔で良くなったり悪くなったりする

直近2時間にしきい値超過が3回以上繰り返されると、カードに **等級反復 N回** バッジが付きます。

- 欠陥の根拠が採択ラインの付近を行き来している状態です。負荷が変わると欠陥信号がオン・オフすることがあり、欠陥の初期段階である可能性もあります。
- 等級は欠陥パターンが決めるため、RMS区間を長くしてもこの反復は減りません。
- バッジを押すと、最後に悪化した時点の詳細分析が開きます。欠陥の根拠と包絡線（エンベロープ）スペクトルで、実際の欠陥かどうかを確認してください。

## サーバー常時監視なのに特定のタグだけイベントがない

そのテーブルに **ROLLUPがない可能性** が高いです。サーバー監視はロールアップがあるテーブルだけを判定し、ロールアップがないテーブルのタグは除外します。設定 → データソースの一覧でそのテーブルに **ROLLUPなし**（ROLLUP 없음）バッジが付いているか、設定 → アラーム設定に除外の警告が出ているかを確認します。

該当するテーブルにロールアップを作成するか、そのタグはアプリ監視で確認します。

## 判定基準画面に「同じ設備 / 別の設備」（같은 설비 / 다른 설비）の確認が表示される

削除したタグが同じ名前で再び現れ、その名前で学習された基準が残っているという意味です。

同じ設備を一時的に外して戻したのであれば **同じ設備 — 維持** を、同じ名前で別の設備を接続したのであれば **別の設備 — 初期化** を選択します。複数ある場合は、上部の **すべて同じ設備 — 維持** で一度に回答できます。

確認するまで、そのタグのベースライン・帯域の根拠は停止します。古い基準をそのまま使うと、新しい設備が静かなときは異常を捉えられず、うるさいときは逸脱表示が出続けるのに、画面にはただ「学習済み」と表示されてしまうためです。等級判定（欠陥パターン・ISOゾーン）は、その間も動作し続けます。

## 帯域学習で分母が埋まらない（例：4/9）

正常です。各タグ行の `4/9 계열 학습됨`（4/9 系列学習済み）の分母は、そのタグで **測定可能な系列の数** であり、タグごとに異なります。（見出し行の `학습됨 X/Y` は、学習を終えたタグ数 / 全タグ数です。）

- 上位帯域は1 kHz以上を対象とします。センサーのサンプルレートが低いと、その帯域は **そもそも測定されません**。
- 包絡線の系列は、サンプルレートやマウンティング上限が低いと除外されます。
- 包絡線の欠陥周波数（BPFO・BPFI・BSF）系列は、**ベアリング型番があってはじめて** 蓄積されます。設備情報で型番を入力すると、その時点から蓄積が始まります。
- 学習状態の横のツールチップに、系列ごとに除外された理由が表示されます。

学習されていない系列は根拠の表示から外れ、残りの系列で正常に動作します。

## 帯域のサンプルが不足して学習できない

帯域値は抽出タイマーが周期ごとに1つずつ蓄積するため、学習に必要な量が集まるまで時間がかかります。

- **過去データの補完** で、すでにDBにある生データをさかのぼって計算すれば、すぐにサンプルを確保できます。
- **抽出周期を短くすると**、以降のサンプルがより早く蓄積されます。
- 帯域学習期間を延ばすと、その分より多くのサンプルが学習対象になります。

現在のサンプル数と学習可否は、帯域学習期間の横に表示されます。

## アラーム設定を変更したのにサーバー監視が古い基準で判定する

サーバー監視とアプリの判定は、どちらも **保存した設定で動作します。** 設定を変更した後に **保存** を押してはじめて新しい基準が反映され、保存前はモニタリング画面も以前の基準で表示されます。別のタブに移動するときに **破棄して移動** を選ぶと、編集した値は破棄されます。

## 通知が届かない

1. **設定 → アラーム設定 → 通知** で、チャンネルがオンになっていて、送信先（Webhook URL）が入力されているか確認します。
2. **テスト送信**（테스트 발송）を押して、送信経路だけを個別に検証します。ここで失敗する場合は、URLかネットワークの問題です。
3. **重大度別の通知** で、その重大度の通知方式が **即時** になっているか確認します。既定値は、注意・危険・重大・監視異常の **4行すべて即時** です。誰かが「通知しない」に変更していないか確認します。
4. 通知方式が **通知しない** の場合、イベントは記録されますが、通知は送信されません。
5. 送信チャンネルはWebhookのみです。メール・SMSが必要な場合は、n8nのような自動化ツールの受信URLを入力して中継します。[アラームとイベント]({{< relref "alarms" >}}) を参照してください。
6. それでも届かない場合は、まず **イベント自体が発生したか** を確認します。イベントがない場合は送信ではなく判定の問題なので、上記の [イベントが記録されない](#イベントが記録されない) に進んでください。`観察` イベントは、もともと通知されません。
7. **信号途絶・計測異常だけが届かない場合は**、重大度表の **監視異常** の行を確認します。等級の3行とは別のスイッチです。
8. 一度に複数台が途絶したのに通知が **1件だけ** 届いた場合は正常です。同じ回に同じ種類・等級のイベントが5件以上あると、まとめて送信します。個別の履歴はすべてイベント一覧にあります。
9. 画面に「サーバー監視が通知設定を読み込めず、イベントN件を通知できませんでした」と表示されている場合は、**通知設定を開く** → 通知設定を保存し直します。

## イベント一覧に古いイベントが表示されない

- 一覧には、フィルターに合うイベントのうち直近 **200件** までしか表示されません。種類・タグのフィルターで絞り込むと、より古いものまで表示されます。
- データソースで選択を外したテーブルのイベントは、一覧から外れます（削除はされません）。
- 全履歴は **保存**（エクスポート）で期間を指定し、CSV・JSONで確認します。選択を外したテーブルのイベントも含まれます。

## イベントファイルのダウンロード時に「安全でないファイル」という警告が出る

ブラウザーがCSV・JSONのダウンロードに対して表示する一般的な警告です。ファイル自体の問題ではなく、ダウンロードを続行すれば正常に保存されます。

## 診断が不正確に感じられる

- **設備情報** にRPM・ベアリングモデルを登録したか確認します。ないと等級そのものが出ません。
- **単位** がセンサーと合っているか確認します。空欄のままだと速度（mm/s）とみなされるため、加速度・変位センサーでは値が誤って換算され、等級の高さが狂います。
- **マウンティング方式** を指定したか確認します。マグネットマウントは通常2\~5 kHzで共振しますが、この帯域は欠陥パターンを測定する1\~5 kHzと重なります。マウンティングを指定すると、上限より上の帯域が帯域別の衝撃性・帯域エネルギーの根拠で区別して表示されますが、欠陥パターン自体は固定帯域で計算するため、**マグネットマウントの設備で欠陥パターンが検出されたら、まずセンサーの取り付け状態を確認** してください。
- ゾーン境界が設備に合っているかを **判定基準** で確認します。等級の高さは、Class別の速度（mm/s）境界で決まります。加速度（`g`）・変位（`μm`）の行は、その単位のセンサーの推移表示用の参考値です。
- 正常状態を学習しておくと、「平常比」の根拠が根拠表に併せて表示されます（等級は変わりません）。
- 診断は、単一チャンネル・単一方向の測定から、位相情報なしで計算されます。欠陥メカニズムは仮説であり、確定には多軸・位相の測定が必要です。

レポートの欠陥候補に「この測定では確認できない」と表示された項目がある場合は、その理由欄に、どの情報がないため判定できなかったのかが記載されています。該当する項目を **設備情報** に入力すると、その候補が判定対象に入ります。

## ベースライン学習が失敗する

メッセージによって原因が異なります。

- **「定常状態のサンプル N個（最低30個必要）」** — 学習区間から停止・起動区間を除いた残りのサンプルが不足しています。サンプルはRMS区間単位でまとめて数えるため、学習期間を延ばすか、アラーム設定のRMS区間を短くするか、データがさらに蓄積されてから再試行します。
- **「学習区間が停止↔運転の2つのレベルに分かれています」** — ウィンドウの大部分が停止区間です。そのまま学習すると停止状態が正常の基準になり、機械を動かすだけで逸脱と表示されてしまうため、学習を拒否します。連続運転が大部分を占める期間を選んで、学習し直します。

学習に成功しても、案内に `제외 12개(정지 8·과도 4)`（除外12件：停止8・過渡4）のように除外の内訳が表示されることがあります。これは正常な動作で、除外した後に残ったサンプルで基準を作成したという意味です。

## 2つのレポートの数値が異なる

レポートに残る **判定フィンガープリント** を比較します。

- フィンガープリントが **同じ** であれば、判定エンジンは同一です。再現性情報のしきい値（Thresholds）欄も同じなら、**データが変わった** ということです。
- フィンガープリントが **異なる** 場合は、その間にパッケージ（判定エンジン）が変更されています。ユーザーが変更したしきい値は、フィンガープリントではなくThresholds欄に表示されます。

## LLM所見が生成されない

- **設定 → LLM連携** にプロバイダーが1つ以上設定されているか確認します。Claude · OpenAI · Gemini はAPIキーが、Ollama はURLが必要です。
- **接続テスト** で、キーまたはURLが正しいか確認します。
- 詳細分析・レポートのプロバイダーのドロップダウンで、使用するプロバイダーが選択されているか確認します。
- モデル名を直接入力した場合は、そのプロバイダーに実際に存在するモデルか確認します。空欄にしておくと既定のモデルを使います。
- LLM所見はオプション機能です。連携しなくても、ルールベースの診断とレポートは正常に動作します。
