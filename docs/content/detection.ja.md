#

この文書では、アプリが**何を測り、どの基準で等級を付け、いつイベントを残すのか**を説明します。

設定画面の各項目と通知の受け取り方は[アラームとイベント]({{< relref "alarms" >}})にあります。この文書は、それらの設定が実際に何を変えるのかを理解したい方のためのものです。

## 一行でまとめると

> **欠陥パターンが等級をオンにし、ISOゾーンがその高さを決めます**。
> ベアリングの欠陥周波数の位置に根拠が立たなければ、振動がどれほど高くても等級は良好です —
> その代わり、「振幅は高い」という事実を画面が別途記載します。

**詳細分析と常時監視は同じ規則を使います**。違うのはウィンドウの長さと周期だけです。

## 全体の流れ

監視は**2つの周期**で動きます。一方は速くて軽く、もう一方は遅くて重い処理です。

```
                     生の振動データ
                            │
          ┌─────────────────┴─────────────────┐
          │                                   │
   判定周期ごと(既定 3秒)              抽出周期ごと(既定 10分)
    区間RMSを1つ                     FFT → 包絡線 → 欠陥周波数グリッド
          │                                   │
          ├── 運転 / 停止                     ├── 欠陥パターン(ゲート)
          ├── 信号途絶                        ├── ISOゾーン(高さ) ← 同じ波形
          ├── 計測異常                        └── 帯域エネルギー(根拠)
          └── ベースライン逸脱(根拠)                    │
                    │                                  ▼
                    │              等級 = パターンがオンにしたときだけ上がる
                    │                                  │
                    └──── 判定凍結 ─────────────────────┤
                          (停止・途絶・計測異常)       ▼
                                                2回連続で確認
                                                       │
                                                       ▼
                                                イベント記録 → 通知
```

**等級イベントは右側の軸からしか出ません**。左側の軸が行うのは、判定を**止める**こと（停止・途絶・計測異常）と**根拠を埋める**こと、そして監視状態のイベント（信号途絶・計測異常・計測復帰）だけです。

### なぜ2つの周期なのか

| | 速い軸 | 遅い軸 |
| :--- | :--- | :--- |
| 計算 | 区間RMS 1回 | 生波形 → FFT → 包絡線 |
| 重さ | 軽い | 重い（生波形を周波数分析） |
| 答えること | 「今回っているか・信号が来ているか」 | 「何が傷んだか」 |

欠陥パターンは生波形を周波数分析する必要があるため、数秒ごとに回すには重すぎます。タグが多いと、計算が周期を超えてしまいます。

そして**その必要もありません**。ベアリングの欠陥は時間・日の単位で進行します。秒単位で起こる事故は、10分周期でも10秒周期でもどのみち事後です — それは監視ではなく保護継電器の役割です。

### なぜ等級イベントを片方の軸からだけ出すのか

ベースライン・帯域はイベントを出しません。理由は2つです。

**① 時間軸が違います**。ベースラインの判定値は速い軸の区間RMSですが、等級は遅い軸の欠陥パターンが決めます。2つを同じイベントの流れに混ぜると、**イベント時刻が何を指すのかがあいまいになり**、再通知間隔にも2つの周期が入り混じります。

**② 軸が増えると誤警報が掛け算で増えます**。帯域は複数の系列をそれぞれの限界値と比べ、1つでも超えればオンにする構造のため、それ自体で誤検知が多くなります。

2つの軸の値は**消えずに根拠として残ります**。カードと根拠表にそのまま表示され、「どの帯域が動いたか」で原因を絞り込むのに使われます。通知が行かないだけです。

> **代償ははっきりしています**。ベースラインは誤検知が最も少ない軸ですが、通知からは外れました。ベアリング欠陥ではない原因（アンバランス・ミスアライメント・ゆるみ）で振幅だけが上がるケースは、**人が画面で確認する**必要があります。下の[限界と代替策](#限界と代替策)をご覧ください。

## 速い軸の判定値 — 区間RMS

速い軸の判定値は、**ある区間全体のRMS値1つ**です。最も新しく入ってきた1点ではありません。

振動は瞬間ごとに揺れ動くため、1点で判定すると値がずっと揺れ続けます。その代わりに「直前10秒の区間」のように、一定の長さのデータを1つの実効値にまとめて見ます。

ここで**RMS区間**と**判定周期**は別の設定です。

| 設定 | 意味 | 既定値 | 設定場所 |
| :--- | :--- | :--- | :--- |
| RMS区間 | どれだけの長さのデータを1つとして見るか | 直前10秒 | アラーム設定（알람 설정） |
| 判定周期 | どれくらいの頻度で判定するか | 3秒ごと | アラーム設定（알람 설정） |
| 抽出周期 | 欠陥パターンをどれくらいの頻度で計算するか | **10分ごと** | 判定基準 → 帯域エネルギー推移（판정 기준 → 대역 에너지 추세） |

前の2つは、RMS区間を3秒\~1時間、判定周期を1秒\~1分の範囲から選びます。抽出周期は10分・30分・1時間から選び、タグが多くて1回分の計算が長くかかる場合は、それより短い周期を選べないようにブロックされます。

区間が**長いほど**、短い揺れが1つの状態にまとめられます — 反応が遅くなる代わりに安定します。区間が判定周期より短いと、その間のデータが判定に入らないため、画面が警告します。

負荷が周期的に変わる設備なら、その変動周期より長い区間を設定するのがよいでしょう。短いと、負荷の変化そのものが停止・逸脱として検出されてしまいます。

## 欠陥パターン — 等級をオンにする軸

### 何を見るのか

ベアリングは傷んだ箇所によって**転がりの周期が決まっています**。回転数とベアリングの幾何形状（転動体数・転動体径・ピッチ径・接触角）が分かれば、その周期を計算できます。

| 名前 | 何か | おおよその値 |
| :--- | :--- | :--- |
| **BPFO** | 外輪欠陥 | 回転周波数 × 転動体数 × 0.4 |
| **BPFI** | 内輪欠陥 | 回転周波数 × 転動体数 × 0.6 |
| **BSF** | 転動体欠陥 | 回転周波数 × 2\~3 |
| **FTF** | 保持器 | 回転周波数 × 0.4 |

欠陥があると、その周波数と高調波（2×・3×・4×）の位置にエネルギーが立ちます。**そのグリッドと実際のスペクトルを照合する**のがこの軸です。

### どう見るのか — 包絡線

欠陥による衝撃は**低周波振動として直接は現れません**。衝撃がベアリング・ハウジングの高周波共振をたたき、その共振が欠陥の周期で**たたかれた分だけ大きくなったり小さくなったり**します。信号は高周波ですが、情報はその大きさの変化（包絡線、エンベロープ）にあります。

```
   生波形 → 1~5 kHz帯域だけ残す → 振幅変化(包絡線)を抽出 → 低周波スペクトル
                (バンドパス)                           (ここにグリッドを当てる)
```

**帯域は1\~5 kHzに固定**されています。最も衝撃的な帯域を自動で選ぶ方式（カートグラム）は、公開データでの検証でアンチエイリアシングのノイズやインバーターの電気成分の帯域に引っかかり、検出率が大きく下がりました。そのためカートグラムは詳細分析の**帯域別衝撃性**（대역별 충격성）チャートに参考として表示するだけで、判定には使いません。

サンプルレートが低く1\~5 kHz帯域が成り立たないセンサーは、全帯域で復調します。この場合は根拠が弱く、初期のベアリング欠陥は捉えられないという案内がカードのツールチップに付きます。

> **大型設備の注意** — 1\~5 kHzは、検証に使った小型\~中型の試験台の共振帯域です。実際にこの帯域によく現れるのは**加速度計のマウンティング共振**（取り付け方式によって数kHz）で、ベアリングのリング自体の曲げモードは設備が大きくなるほど**低く**なります。大型の低速設備では帯域が合わない可能性がありますが、検証データにそのような設備がないため、**どちらの方向に外れるのかはまだ分かっていません**。

### いつオンになるのか

グリッド位置のエネルギーが周辺のノイズレベルの何倍かで、スコア（グリッドスコア）を出します。そのスコアが採択しきい値を超えると、ゲートがオンになります。

| | ウィンドウ長 | 採択しきい値 |
| :--- | :--- | :--- |
| **詳細分析** | 100回転以上（最大22秒） | 4.0 |
| **常時監視** | **25回転** | **3.0** |

監視が短いウィンドウを使う理由は、サーバーの計算コストです。ウィンドウが短いとスコアが全体的に低く出るため、しきい値も一緒に下げています。その代償として、監視は詳細分析より検出がやや少なくなります（公開データ基準で検出率 65% → 60%）。

監視は**合図を出す役割**で、確定は詳細分析が100回転以上の長いウィンドウで行います — 見逃しさえしなければ短くても構いません。

### 判定できない場合

回転数やベアリングの幾何形状が分からなければ、グリッドを作れません。このとき等級は**上がりません** — ただしそれは「正常」ではなく「判定不可」です。

画面はこれを隠しません。モニタリングのカードは等級の代わりに**判定保留**（판정 보류、つまり判定不可）と表示し、詳細分析は「判定基準 n/N（… 未適用）」と表示し、設備情報画面は**判定不可**（판정 불가）バッジで知らせます。ジャーナル（sleeve）ベアリングも転動体がないため、これに該当します。

> **回転数は推定しません**。誤った回転数でグリッドを立てると、気づかないうちに誤った等級が出てしまうためです。

## ISOゾーン — 高さを決める軸

ISO 10816規格が定めた振動重大度ゾーン（A 新規設備レベル → B 長期運転可 → C 制限運転 → D 損傷のおそれ）です。ゾーンは振動の大きさの尺度なので、等級語（良好・注意・危険・重大）では呼びません。設備のClass（設備情報）によって境界値が変わります。

| Class | A↔B | B↔C | C↔D |
| :--- | ---: | ---: | ---: |
| Class I（小型 ≤15kW） | 0.71 | 1.8 | 4.5 |
| Class II（中型 15–75kW） | 1.12 | 2.8 | 7.1 |
| Class III（大型・剛性基礎） | 1.8 | 4.5 | 11.2 |
| Class IV（大型・柔軟基礎） | 2.8 | 7.1 | 18.0 |

単位はmm/s（速度RMS）で、ISO 10816の基準値です。値は判定基準画面で直接変更できます。Classを空欄にすると、Class IIとして判定します。

**加速度（g）・変位（μm）センサーも、値を速度に換算して上記のClass境界で判定します**。判定基準画面のg・μmの行（既定 0.5/1.0/2.0 g、12/25/50 μm）は、規格が定義した値ではなく一般的な参考値で、その単位のセンサーのRMS推移の基準線と期間統計の表示、サーバー監視がISO値をどれだけの頻度で測り直すかを決めることにだけ使われ、等級には使われません。そのため単位を空欄にすると（速度とみなされます）、加速度・変位センサーの等級の高さがずれてしまいます。

> **帯域制限** — ISOゾーンの判定は、10–1000 Hzの区間だけを残して測ります。規格のゾーン境界そのものが、その帯域で測定した値として定められた数値だからです。高周波成分が多いセンサーでは全帯域の値とISO値がかなり異なることがありますが（カードの数値にマウスを乗せると両方が表示されます）、この場合はゾーン判定に使う方が規格に合った値です。

### ISOを独立した軸にしない理由

ISOゾーンだけで警報をオンにすると、公開データ383件で検証したとき、正常な設備の69%が警報として検出されました。欠陥パターンをゲートとして使うと3%です（検出は少し減ります）。マシンクラスを誤って選んでも誤検知がほとんど変動しないのも副次的な利点です — ISOが警報をオンにしないからです。

この69%は実機設備の誤検知率ではなく、検証に使った加速寿命試験台の特性によって出た値です。詳しくは[このツールが行うことと行わないこと]({{< relref "scope#軸を組み合わせるとどうなるか" >}})にあります。

### 高さを測る波形

監視では、ISO値を**欠陥パターンを測ったまさにその波形**で測ります。速い軸の最新のISOを使うと等級が数秒ごとに動き、10分周期のパターンと時間軸がずれてしまいます。

パターン計算のときにISOを測れなかった場合は、速い軸の値で代用します — 等級を0に落とすことはしません。

## 根拠の軸 — 等級を作らない2つ

### ベースライン — 平常時との比較

設備が正常なときの状態を学習しておき、そこからどれだけ外れたかを見ます。

```
限界値 = 平常レベル(μ) + k × 平常の変動幅(σ)
```

絶対値がまだAゾーンでも、**平常時よりはっきり上がっていれば**捉えます。`k`は感度です — 小さいほど敏感で、大きいと確実なときだけ反応します。

平常時の変動がほとんどない非常に安定した設備では、限界値が平常レベルに近づきすぎることがあるため、**少なくとも平常時の+20%は上がらなければ**逸脱とみなしません。

逸脱しても**等級は上がらず、イベントも出ません**。カード（数値にマウスを乗せる）と根拠表に「平常比急増」（평소 대비 급증）と表示されます。学習方法は[初期設定 › ベースライン学習]({{< relref "first-setup#ベースライン学習" >}})にあります。

### 帯域エネルギー — 周波数帯域別

全体のRMSでは見えない変化を捉えます。ベアリングの欠陥が進行しても全体の振動はほとんど動きませんが、その欠陥が現れる周波数帯域だけを見ると何倍にも跳ね上がります。

帯域は回転周波数（1×）を基準に5つの区間に分けます。このうち超高周波は1\~2・2\~4・4\~8・8 kHz+の4帯域に細分されるため、実際に蓄積される周波数帯域は8つです。

1×は抽出のたびに波形から実測します。**入力RPMの±5%以内のピークだけ**を1×とみなし、系統周波数（設定の50/60 Hz）のピークは除外し、見つからなければ入力RPMを使います。詳細分析の実測1×と同じ規則です。範囲をさらに広げると、ベルトでつながったモーターのように別の回転体のピークを1×として捉え、帯域境界が丸ごとずれてしまいます。そのため入力RPMが実際と5%を超えて異なると、帯域境界も誤ったものになります — RPMは定格回転数で正確に入力してください。

| 帯域 | 範囲 | 主に現れるもの |
| :--- | :--- | :--- |
| サブシンクロナス | 2 Hz \~ 0.5× | オイルホワール・ゆるみ・ベルト |
| 1×帯域 | 0.5× \~ 1.5× | アンバランス・ミスアライメント |
| 欠陥帯域 | 1.5× \~ 10×（最大 1 kHz） | ベアリング欠陥周波数・ギア |
| 高周波 | \~ 1 kHz | 初期のベアリング欠陥 |
| 超高周波 | 1 kHz以上（1\~2・2\~4・4\~8・8 kHz+） | 衝撃性・摩擦 |

帯域ごとにベースラインと同じ方式で正常基準を学習し、**限界値の何倍か**を根拠表に記載します。マウンティング方式の有効上限を超える帯域の逸脱は「**暫定**」（잠정）と表示されます — 値が上がったのは事実ですが、設備の振動なのかセンサー取り付け部の共振なのかを区別できないという意味です。

> サンプルレートが低いセンサーでは上位の帯域が測定範囲を外れて学習されず、ベアリングの型番がなければ包絡線の欠陥周波数系列は蓄積されません。学習されなかった系列は除外され、画面には「4/9 계열 학습됨」（4/9系列 学習済み）のように表示されます。

### なぜ学習する軸をゲートに入れないのか

これは詳細分析で特に重要です。学習する軸をゲートに入れると、**同じタグでも学習済みかどうかによって異なる等級**が出てしまい、検証でも誤検知が大きく増えました。

1回限りの分析は「今この信号が何のように見えるか」に答えるツールなので、学習状態に縛られてはいけません。

### Crestは等級を上げません

Crest（ピーク/実効値の比）も等級には入りません。振幅が低い区間では分母が小さく、スパイク1つでも大きく跳ねるためです。

その代わり**判定文言**に反映されます。振幅は正常でもCrestが基準を超えると、判定は「正常運転」と断定しません。基準はノイズだけではほとんど超えない線に設定されており、期間が長く分・時間単位にまとめられたデータで見るときは衝撃性を判断しません（負荷変動だけで最大値が大きくなるため）。

低いRMSに高いCrestという組み合わせは、**局所欠陥の初期のシグネチャであると同時に、計測スパイク（ESD・ケーブル・接触）のシグネチャ**でもあります。この値1つでは区別できないため、等級は動かさず事実だけを記載します。両者を分けるのは、衝撃が**繰り返されるかどうか**です — 包絡線で欠陥周波数にそろっていれば欠陥、ばらばらなら計測側の問題です。推奨文言がこの確認を指示します。

計測異常（クリッピング・DCドリフトなど）が発生している状態では、その警告文言が優先されます。すでに計測の確認を指示しているためです。

## 等級の決定

```
等級 = 欠陥パターンがオンになったか?  →  いいえ : 良好
                                      →  はい   : ISOゾーン A・B → 注意 / C → 危険 / D → 重大
```

パターンがオンになったのにISOがAゾーンなら、**注意**です。原因を名指ししておきながら等級が良好のままだと、画面が自ら矛盾してしまうからです。

等級を上げなかった軸も**事実は残します**。画面が「良好」とだけ伝えると、うそになってしまいます。

| 状況 | 等級 | 画面が知らせる内容（要旨） |
| :--- | :--- | :--- |
| パターン ○・ISO C | 危険 | 外輪欠陥の根拠・振動の大きさ Cゾーン |
| パターン ○・ISO A | **注意** | 外輪欠陥の根拠・振動の大きさはまだAゾーン |
| パターン ✕・ISO C | **良好** | **ベアリング欠陥の兆候なし・振動の大きさ ISO C区間** — アンバランス・ミスアライメント・ゆるみなど、ベアリング以外の原因の点検を推奨 |
| パターン ✕・ベースライン逸脱 | 良好 | ベアリング欠陥の兆候なし・平常比急増 |
| パターン ✕・帯域逸脱 | 良好 | ベアリング欠陥の兆候なし・帯域の逸脱 |
| 回転数・幾何形状 未入力 | 付けない | **判定保留（判定不可）** |

3行目がこの設計の核心となるトレードオフです。**ベアリング以外の故障では等級が上がりません** — このツールはベアリング診断ツールであり、アンバランス・ミスアライメントは位相（タコ）・軸方向チャンネルがなければ原理的に判別できないためです。隠さずに文言で明らかにします。

## イベント

判定結果のうち、**状態が変わった瞬間だけ**がイベントとして残ります。同じ状態が続いている間は記録しません。

| 種類 | いつ発生するか | どの軸か |
| :--- | :--- | :--- |
| **観察**（관찰） | 良好から初めて外れた回 — **確定前、通知なし** | 遅い軸（パターン） |
| **しきい値超過**（임계 초과） | 同じ等級が**2回連続**して確定したとき | 遅い軸（パターン） |
| **状態継続**（상태 지속） | 悪い状態が続くとき、再通知周期ごと | 遅い軸（パターン） |
| **状態改善**（상태 개선） | アラームレベルからは外れたが、まだ良好ではないとき | 遅い軸（パターン） |
| **正常復帰**（정상 복귀） | 完全に良好に戻ったとき | 遅い軸（パターン） |
| **計測異常**（계측 이상） | クリッピング・DCドリフト・フラットラインなどが1分続くとき | 速い軸 |
| **計測復帰**（계측 복귀） | 計測異常が解消し、正常な状態が5分続くとき | 速い軸 |
| **信号途絶**（신호 두절） | データが入ってこないとき | 速い軸 |

下の3つは振動の等級ではなく、「**監視が正しく行われているか**」を知らせます。画面が最後の値を持ったまま正常に見え続けることが、最も悪い失敗だからです。

**ベースライン・帯域はイベントを出しません**。状態は引き続き追跡され、根拠表に表示されます。

### 改善と復帰の違い

1回の異常事態の中で良くなっていく過程は、2つの段階に分かれます。

| | 意味 | 対応 |
| :--- | :--- | :--- |
| 状態改善 | 差し迫った危険は去った | 優先度を下げる、緊急対応を解除 |
| 正常復帰 | 完全に正常である | 作業指示を終了 |

2つを分ける理由は、実務上の対応が異なるためです。また、ゾーン境界付近で運転する設備はなかなか完全な良好に到達しませんが、そうした設備でも「改善した」という信号は受け取れる必要があります。

各段階は1回の異常事態ごとに**1件だけ**記録されます。重大 → 危険 → 注意 → 良好と段階的に良くなっても、改善1件、復帰1件です。

### 記録のルール

- **良好が続いている間は何も記録しません**。悪い状態から戻った正常復帰だけが1件残ります。
- **まだ悪い状態のまま良くなっていく途中の段階**（重大 → 危険など）は別途記録しません。状態改善で代表されます。
- **初めて見るタグがすでに悪い場合**、その回で`観察`がすぐに記録され、次の回も同じなら確定します。最初の回ですぐに確定しないのは、監視をオンにした瞬間に悪いタグすべてが一斉にアラームを出さないようにするためです。
- **イベントは自動では削除されません**。履歴もデータなので保存されます。

### イベント値の読み方

速度（mm/s）センサーの等級イベントの値は、**等級の高さを決めたISO値**（欠陥パターンを測ったまさにその波形で測った値）です。加速度・変位センサーは判定区間の元の単位のRMSを記録し、等級の根拠（ISOゾーン・欠陥パターン）は詳細欄に文言として残します。ただしISO値は等級をオンにした軸ではないため（ゲートは欠陥パターンです）、値だけを見ると誤解するおそれがあります。「なぜこの等級なのか」には、欠陥パターンの根拠が答えます。

| どこで | 何が見えるか |
| :--- | :--- |
| モニタリングのイベント一覧の「詳細」（상세）欄 | 速度センサー：`ISO値 · 基準(超えたゾーン境界)` / 加速度・変位センサー：`元の単位の値 · ISO <ゾーン> 구간 · 결함 패턴 <部位>` / 信号途絶：`N분 무수신`（N分間受信なし） / 計測異常・復帰：理由（例：`플랫라인`（フラットライン）、説明はマウスを乗せると表示） |
| エクスポート（CSV・JSON）の「詳細」列 | 欠陥パターンのグリッドスコア・部位・回、計測異常の理由（通知文言には値・基準と、加速度・変位センサーであればISOゾーン・部位だけが載ります） |

エクスポートファイルの「詳細」の例：

```
観察          격자 3.2 · 외륜(BPFO) · 1회차 — 확정 전        （グリッド 3.2・外輪・1回目、確定前）
しきい値超過  격자 3.2 · 외륜(BPFO) · 2회 연속 확정         （2回連続で確定）
状態継続      격자 4.1 · 지속 재알림                         （継続の再通知）
正常復帰      격자 2.2 · 4시간 20분 만에 복귀                （4時間20分後に復帰）
```

## 確定 — 2回連続

等級が変わってすぐにアラームが出るわけではありません。**同じ判定が2回連続**して初めて確定します。悪くなるときも、良くなるときも同じです。ただし、良くなるときは段階的に下がっていく回も続けて数えます — 危険 → 注意 → 良好と下がると、良好の回で復帰が確定します。

```
1回目   グリッド 3.2 → 注意    観察イベント・通知なし
2回目   グリッド 3.2 → 注意    しきい値超過・通知送信
3回目   グリッド 2.1 → 良好    (まだ復帰ではない)
4回目   グリッド 2.0 → 良好    正常復帰・通知送信
```

1回でも元に戻ると連続が途切れ、最初から数え直します。判定は抽出周期で回るため、確定は分ではなく**回**で数えます。

### 2回である理由

公開されている全寿命試験データを実際の監視周期で再生してみると、欠陥はたいてい「**最初の単発 → 長い空白 → 連続区間**」という形をとっており、最初の単発の時点で現場に行っても何も見つかりませんでした。同じ性質の単発は、健全なベアリングでもよく発生しました。

2回連続を求めると、単発まで確定する場合より誤警報が大きく減り、警報のタイミングはむしろ本当の信号が始まるところに合います。数値は[このツールが行うことと行わないこと › 時間軸での成績]({{< relref "scope#時間軸での成績--全寿命試験" >}})にあります。

> **単発も痕跡は残ります**。確定に至らなかった単発は`観察`イベントとして履歴に残ります。通知が出ないだけです。

### 計測異常は時間基準のまま

信号途絶・クリッピング・DCドリフトは**速い軸**で判定するため、回という概念がありません。スパイク1回で「センサー故障」が出ないように1分の継続を求め、復帰には5分を求めます。これは設定では変更しません。

### DC — 一定のDCはブロックしません

MEMS加速度計の垂直軸（重力 1 g）や近接変位センサー（ギャップ電圧）は、正常な状態でも平均値が振動の振幅よりはるかに大きくなります。判定値は帯域フィルター・平均除去を経ているためこのDCの影響を受けず、**一定のDCは判定をブロックせず**、詳細分析とレポートに参考として記載するだけです（「DC 성분」（DC成分）の灰色の案内 — 警告ボックスとは別のものです）。

ブロックするのは**1秒平均が揺れるとき**です（平均の揺れが振動の振幅の半分を超え、判定RMSが膨らむほどの場合）。センサーのバイアス・ケーブルの異常や、マグネットマウントが回転して重力成分が変わる場合がこれに当たります。

- 回転数があり、1秒に10回転以上（600 rpm以上）のときだけ確認します。低速機では実際の振動が1秒平均を揺らすためです。
- 1回転あたりのサンプルが4個未満の遅い値のタグ（1秒に数回記録されるトランスミッターの値など）は確認しません。こうしたタグはそもそも波形分析の対象ではありません。

## 停止と信号途絶

値が急に下がったからといって、良くなったわけではありません。

- **設備停止** — 判定値が平常運転レベルの20%を下回ると停止とみなし、判定を**凍結**します。振動の欠陥は自然には治らないため、説明のつかない低下はたいてい設備が止まったか、センサーを失ったかのどちらかです。このとき「正常復帰」の通知が出ると、設備が修理されたと誤解してしまいます。凍結中は直前の状態を保持するため、再稼働すると以前悪かったという事実がそのまま残っています。カードには**停止**（정지）バッジが付きます。
- **信号途絶** — 新しいデータが判定周期の6倍（最小1分）を超えて入ってこないと途絶とみなし、イベントを残します。カードには**信号途絶**（신호 두절）バッジが付き、グラフが薄く表示されます。

## サンプルが足りないタグ

欠陥パターンは**回転数基準のサンプル数**でウィンドウを取ります — 時間ではありません。

タイムスタンプがまばらなタグ（再生データ・間欠収集）は、同じ時間内に入ってきたサンプルが少なくなります。この場合はウィンドウを広げて読み直し（最大2回）、それでもサンプルが4,096個に満たなければ、その回のパターン判定をスキップします。それより多ければ、足りないなりに短いウィンドウで判定します。多すぎる場合は最新側だけを使います — ウィンドウが長くなると運転状態が混ざるためです。

スキップした回はカードに**判定保留**（판정 보류、欠陥パターン測定失敗）と表示され、直前の等級が保持されます。気づかないうちに「良好」と見えてしまわないようにするためです。

## ベースライン学習

正常運転区間の**平常レベル**（μ）と**平常の変動幅**（σ）を学習します。スパイクに左右されない中央値方式を使い、停止・起動区間は自動的に除外し、停止が大部分を占める区間は学習を拒否します。

学習は**自動ではやり直しません**。欠陥が進行している最中に再学習すると、その欠陥を正常として取り込んでしまうためです。整備をした場合や運転条件が変わった場合は、そのときに人が改めて学習させるのが正しいやり方です。

同じ名前で別の設備を接続した場合の確認（同じ設備 — 維持 / 別の設備 — 初期化）、学習が拒否される場合など、詳しい内容は[初期設定 › ベースライン学習]({{< relref "first-setup#ベースライン学習" >}})にあります。確認するまではそのタグのベースライン・帯域の根拠だけが止まり、欠陥パターンとISOゾーンは学習が不要なため、引き続き動作します。

## 帯域エネルギーの抽出

帯域ごとの値は生データを周波数分析して得られるため、**サーバーの帯域抽出タイマー**が抽出周期ごとに計算して蓄積します。

- 計算はサーバーで行われます。アプリを閉じていても推移は続きます。
- 停止した設備の古い区間を拾わないよう、常にそのタグの最新データ時刻を基準に計算します。
- 欠陥パターンは同じ周期で測りますが、帯域抽出とは別です。アプリ監視ではアプリが、サーバー常時監視ではサーバー監視タイマーが測ります。**帯域抽出をオフにしても等級判定は続きます**。

### 過去データの補完

学習に必要なサンプルがたまるには時間がかかります。すでにDBに生データがあれば、**過去データの補完**（과거 데이터 채우기）でさかのぼって計算できます。

計算方式はタイマーと同じなので、補完した値とその後に蓄積される値を続けて学習しても構いません。進捗状況と予想所要時間が表示され、途中で止めても補完した分はそのまま使われます。

## 詳細分析と監視の違い

同じ規則ですが、**ウィンドウ・周期・時点**が異なります。

| | 詳細分析 | 常時監視 |
| :--- | :--- | :--- |
| 等級の式 | パターンがオンにし、ISOが高さを決める | **同一** |
| パターンのウィンドウ | 100回転以上（最大22秒） | 25回転 |
| 採択しきい値 | 4.0 | 3.0 |
| いつ | 人が期間を選んだとき | 抽出周期ごとに自動 |
| どの時点 | 期間内の複数の地点（最大8か所）のうち**最も悪いところ** | 現在 |
| 学習の要否 | 不要 | 不要（根拠の表示にのみ使用） |

### なぜ詳細分析は複数の地点を測るのか

期間の**終わり**だけを測ると、その瞬間の状態が期間全体を代表してしまいます。実際に、外輪が破損したベアリングで、選択したウィンドウの終わりがすでに停止区間だったため、等級が良好と出た事例がありました。

そこで期間を分割して各地点で判定し、**最も悪いもの**を使います。データがない地点はそれより前のデータに寄せ、重複は除去します。どの地点が選ばれたかは、等級の横の「判定基準時刻」（판정 기준 시각）に表示されます。

「1時間を選ぶと、その1時間のうち最も状態が悪かった瞬間」が等級になります — 全期間の最悪ではありません。

## 限界と代替策

| 求めること | 現状 | 代替策 |
| :--- | :--- | :--- |
| 振幅の上昇を通知で受け取る | 根拠の表示のみ | カード・根拠表を定期的に確認 |
| ベアリング以外の故障（アンバランス・アライメント）の判定 | 行わない | 位相・軸方向チャンネルが必要 — 原理的な限界 |
| 秒単位の対応 | 行わない | 保護継電器・インターロックの領域 |
| 内輪欠陥の早期検出 | **検出できない** | [故障タイプ]({{< relref "faults" >}})を参照 |

## 判定フィンガープリント

生成されたレポートには、**判定フィンガープリント**（판정 지문）が一緒に記録されます。判定エンジンのルールと固定定数から計算された短い文字列です。ユーザーが変更したしきい値はフィンガープリントに含まれず、レポートの再現性情報欄（Thresholds）に別途記載されます。

2つのレポートの数値が異なるとき、その原因を切り分けます。

- フィンガープリントが**同じ** → 判定エンジンは同一 — しきい値欄も同じなら、**データが変わった**
- フィンガープリントが**異なる** → その間に**パッケージ（判定エンジン）が変わった**
