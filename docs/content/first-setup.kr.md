#

## API 토큰 입력

앱은 Neo 콘솔 로그인과 별도로 **계정마다 발급한 API 토큰**으로 서버에 접속합니다. 보이는 테이블, 저장되는 설정, 서버 감시 타이머가 모두 이 토큰 계정의 권한으로 동작합니다.

### 토큰 발급

1. Neo 웹 콘솔에 앱을 쓸 계정으로 로그인합니다.
2. 방패 아이콘(**①**)을 누른 뒤, **TOKENS** 옆의 **+** 버튼(**②**)을 누릅니다.
3. 토큰 이름(**③**, 예: `bearing-analytics`)을 입력하고 **Issue token**(**④**)을 누릅니다. 만료일은 **NotAfter**에서 정할 수 있습니다(기본 10년).

   ![Neo API 토큰 생성](../static/images/neo-token-create.png)

4. 발급된 토큰(`nt_`로 시작)을 복사 버튼(**⑤**)으로 복사합니다.

   ![Neo API 토큰 복사](../static/images/neo-token-copy.png)

> 토큰 문자열은 발급할 때 한 번만 표시됩니다. 잃어버렸다면 새로 발급합니다.

### 앱에 입력

1. 앱을 열면 설정 화면에 **유저 정보** 카드만 나옵니다. 토큰이 확인되기 전에는 데이터 소스 등 다른 설정과 모니터링·상세분석·리포트 화면을 보여 주지 않습니다. 복사한 토큰을 입력칸(**⑥**)에 붙여 넣고 **확인·저장**(**⑦**)을 누릅니다.

   ![앱에 API 토큰 입력](../static/images/app-token-input.png)

2. 확인되면 **접속 계정**과 가려진 토큰이 표시되고, 앱이 그 계정으로 동작합니다.

   ![토큰 확인 뒤 유저 정보](../static/images/app-token-ok.png)

- **콘솔에 로그인한 계정의 토큰만** 받습니다. 다른 계정의 토큰이면 "○○ 계정의 토큰입니다"라며 저장하지 않습니다.
- 토큰은 **이 브라우저에만** 계정별로 저장됩니다. 다른 브라우저나 PC에서는 다시 입력합니다.
- 토큰이 폐기·만료되면 입력 화면으로 돌아갑니다. 새 토큰을 넣으면 이어서 동작합니다. 서버 상시 감시 타이머는 토큰이 아니라 계정에 묶여 있어 토큰을 폐기해도 멈추지 않으며, 같은 계정의 새 토큰으로 계속 관리됩니다.
- 바꾸거나 지우려면 같은 카드의 **토큰 변경** · **토큰 지우기**를 누릅니다. 지우면 그 브라우저의 조회·판정·알림 기록이 멈춥니다(서버 상시 감시 타이머는 계속 돕니다).
- 토큰이 확인되기 전에는 어떤 데이터도 조회하지 않습니다.

## 시작하기 전에 — 저장소와 권한

이 앱은 **입력한 API 토큰의 계정으로** 동작합니다. 보이는 테이블과 저장되는 설정이 계정마다 따로입니다.
그래서 처음 한 번은 관리자(SYS)의 준비가 필요합니다.

| 누가 | 무엇을 |
| :--- | :--- |
| SYS | 설정 → **유저 정보** 카드에서 `만들기` — 전용 데이터베이스 `NEO_BEARING_STORE`를 만듭니다 |
| SYS | 같은 카드의 **패키지 사용 계정 권한** 목록에서 그 계정 줄의 **권한 주기** (계정마다 한 번) |
| SYS | 분석할 데이터 테이블 권한 — `GRANT SELECT ON MACHBASEDB.SYS.<테이블> TO <계정>;` |

권한을 못 받은 계정에는 "데이터베이스에 접근할 수 없습니다"라는 안내와 `상태 확인` 버튼만 보입니다.
권한을 받은 뒤 그 버튼을 누르면 새로고침 없이 이어집니다.

목록에는 계정마다 권한 상태(**권한 있음** · **일부만 있음** · **권한 없음**)와 그 계정이 등록한 이 패키지 타이머 수가 표시됩니다. 더 쓰지 않는 계정은 **권한 회수**로 되돌립니다. 설정·이벤트·학습값은 지우지 않으므로 다시 권한을 주면 그대로 이어집니다. 회수하기 전에 그 계정으로 알람과 대역 추출을 꺼 두십시오 — SYS는 다른 계정의 타이머를 대신 끌 수 없어, 남은 타이머는 회수 뒤 매 회차 실패합니다.

계정 자체를 지울 때(퇴사 등)는 **지우기 전에** 그 계정으로 로그인해 알람과 대역 추출을 끄고, 방패 아이콘(Security)의 **TOKENS**에서 그 계정의 토큰을 전부 폐기하십시오. Neo는 계정을 지워도 그 계정의 API 토큰과 타이머를 지우지 않습니다 — 남은 토큰으로 워크스페이스 파일을 읽고 쓸 수 있고, 같은 이름으로 계정을 다시 만들면 옛 토큰과 타이머가 새 계정에 그대로 붙습니다. 또 이 앱을 쓴 계정은 전용 데이터베이스에 설정 표(`NEO_BEARING_STORE.<계정>.CONFIG`)를 갖고 있어, SYS가 그 표를 먼저 지워야 계정이 지워집니다 — 계정이 가진 표가 남아 있으면 Neo가 계정 삭제를 거부합니다.

계정이 Neo 콘솔에 **로그인조차 못 한다면** 기본 데이터베이스 접속 권한이 없는 것입니다(`ERR-2835`).
이건 이 패키지가 아니라 Neo 자체의 전제조건입니다 — `GRANT CONNECT ON DATABASE MACHBASEDB TO <계정>;`

## 설정 화면

앱을 처음 열면 모니터링 화면에 "저장된 설정이 없습니다" 안내와 **설정 시작** 버튼이 나옵니다. 버튼을 눌러 **설정** 화면에서 분석 대상을 지정합니다. 설정은 왼쪽의 여섯 개 섹션으로 나뉩니다.

| 섹션 | 내용 | 필수 |
| :--- | :--- | :---: |
| 데이터 소스 | 유저 정보, 표시 시간대, 분석할 TAG table 선택, 별칭 | 예 |
| 설비 정보 | **RPM · 베어링 모델**(등급에 필수) · 단위 · Class · 계측·구동 정보 | **예** |
| 판정 기준 | 존 경계(임계값), 베이스라인 학습, 대역·결함 패턴 추출 | 선택 |
| 알람 설정 | 감시 방식, 판정 주기·RMS 구간, 알림 | 선택 |
| LLM 연동 | 상세분석·리포트 소견용 프로바이더 | 선택 |
| 데이터 관리 | 저장 용량 확인, 기간·태그별 데이터 삭제 | 선택 |

왼쪽 섹션 이름 옆에는 손볼 항목 수가 배지로 붙습니다 — 설비 정보의 **판정 불가 N**(RPM이나 베어링이 없어 등급을 못 매기는 태그)·**미설정 N**, 판정 기준의 **미학습 N**·**재학습 N**. 섹션마다 배지는 하나만 보이며, 급한 쪽이 먼저입니다(판정 불가가 미설정보다, 미학습이 재학습보다). 손볼 항목이 남아 있으면 헤더의 ⚙ 버튼에도 주황 점이 표시됩니다.

설정을 바꾸면 화면 아래에 "저장하지 않은 변경사항이 있습니다" 안내가 뜨고, **저장**을 누르면 실데이터가 다시 적재됩니다. **바꾼 값은 저장해야 반영됩니다** — 저장 전에는 모니터링 화면·앱 판정·서버 감시 모두 이전 설정으로 동작합니다. 저장하지 않고 다른 탭으로 나가려 하면 확인 창이 뜹니다(**취소** · **버리고 이동** · **저장 후 이동**). **버리고 이동**을 고르면 편집한 값이 버려지고 저장된 설정으로 돌아갑니다.

몇몇 버튼은 누르는 즉시 그 값 하나만 저장합니다.

- 헤더의 알람 켜기/끄기
- 추출 주기 변경 창의 **적용**
- 리포트·상세분석의 LLM 프로바이더 선택
- 상세분석 회전수 경고의 **실측값 N rpm으로 저장**

설정 탭에서 저장하지 않은 다른 편집은 이때 함께 저장되지 않습니다.

## 표시 시간대

**설정 → 데이터 소스**의 **표시 시간대**에서 화면에 찍히는 시각의 기준을 고릅니다. 기본값은 브라우저 시간입니다.

- 카드·차트·이벤트 목록·날짜 선택·"오늘"의 기준·리포트·알림 문구의 시각이 모두 이 시간대를 따릅니다.
- 데이터 조회는 시간대와 무관하게 같은 순간을 봅니다. 서버와 브라우저의 시간대가 달라도 조회 결과는 같습니다.
- 공장 현지 시간으로 보고 싶다면 그 지역을 고르고 저장합니다. 리포트에는 만든 시간대가 함께 적히고, 리포트 안 차트도 그 시간대로 표시됩니다.

## 데이터 소스

가장 먼저 어떤 데이터를 분석할지 고릅니다.

1. Neo에서 감지된 table 목록이 종류 배지와 함께 표시됩니다.
2. 분석할 table을 선택합니다. **여러 개를 동시에 선택**할 수 있습니다.
3. 선택한 table의 태그가 아래 별칭 표에 나타납니다.

처음에는 아무것도 선택되어 있지 않습니다. 실제로 분석할 table만 직접 선택합니다.

### 컬럼 구성

Machbase TAG table의 표준 컬럼명(`NAME` · `TIME` · `VALUE`) 기준으로 조회합니다. 다른 컬럼명을 쓰는 TAG table은 아직 지원하지 않으며, 목록에서 흐리게 표시되고 선택할 수 없습니다(사유가 함께 표시됩니다).

### ROLLUP

추이 그래프와 서버 감시는 TAG table의 **ROLLUP**(미리 집계해 둔 요약)으로 빠르게 조회합니다. 롤업이 없는 table도 선택할 수 있지만, 원본 데이터를 직접 집계하므로 다음이 제한됩니다.

- 상세분석·리포트의 추이 그래프는 고른 기간 중 **최근 2시간**만 표시합니다. 롤업 단위 칸에 `원본 집계`가 붙고, 그 아래 안내가 뜹니다.
- 모니터링 화면이 처음 불러오는 추이도 최근 약 500만 행 분량으로 줄어듭니다.
- **서버 상시 감시에서 빠집니다.** 앱 감시로는 판정됩니다.

목록에서 롤업이 없는 table에는 **ROLLUP 없음** 배지가 붙고, 그 table을 선택하면 무엇이 제한되는지 오른쪽에 안내가 뜹니다. 긴 기간을 보려면 table에 롤업을 만드십시오.

### 별칭

태그는 `별칭 (태그명)` 형태로 표시됩니다. 원래 태그명이 길거나 코드성이면 별칭을 지정해 알아보기 쉽게 만들 수 있습니다. 별칭은 모니터링 카드·상세분석·리포트·알림 문구에 함께 쓰입니다. 비워 두면 원래 태그명(`NAME`)이 그대로 표시됩니다. 태그가 많으면 검색으로 찾습니다.

### 적재 상한

쿼리 폭주를 막기 위해 **table당 태그 60개**, **전체 설비 100개**까지 적재합니다. 상한에 걸려 빠진 태그는 별칭 표에 **감시 제외** 배지가 붙고, 모니터링 화면 위에도 안내가 뜹니다. 분석 대상 table만 선택해 범위를 좁히는 편이 좋습니다.

### 데이터 소스 변동 감지

선택한 table이나 태그가 DB에서 제거되거나 비면, 모니터링 화면 상단에 변동 감지 배너가 뜹니다. **다시 불러오기**로 갱신하거나 **무시**로 닫을 수 있습니다.

## 설비 정보

각 태그가 어떤 설비인지 알려 주어야 등급이 나옵니다. 아직 아무것도 설정하지 않은 태그에는 주황 점이 표시됩니다.

![설비 정보 설정 화면](../static/images/settings-equipment.png)

> **RPM과 베어링 모델은 필수입니다.** 등급을 켜는 결함 패턴은 결함주파수 격자로 계산하는데, 회전수와 베어링 기하가 없으면 그 격자를 만들 수 없습니다. 둘 중 하나라도 비면 그 태그는 **등급이 오르지 않습니다** — 그건 "정상"이 아니라 "판정 못 함"입니다. 화면에서는 이렇게 보입니다.
>
> - 모니터링 카드: 등급 대신 **판정 보류** 배지(마우스를 올리면 "판정 못 함")
> - 설비 정보 목록: **판정 불가** 필터와 왼쪽 **판정 불가 N** 배지
> - 상세분석: "판정 기준 n/N (… 미적용)"
>
> 나머지 항목(단위·Class·계측·구동)은 비워 두어도 판정이 돌아갑니다. 다만 비운 단위는 **mm/s(속도)**, 비운 Class는 **Class II**로 간주합니다.

| 항목 | 설명 |
| :--- | :--- |
| **RPM** | 베어링이 달린 축의 실제 운전 회전수. 결함주파수 격자의 기준입니다 — **비우면 판정이 안 됩니다**(추정하지 않습니다) |
| **베어링 모델** | 카탈로그에서 고르면 형상값과 결함 주파수가 자동 계산됩니다 — **비우면 판정이 안 됩니다** |
| 단위 | `mm/s`(속도) · `g`(가속도) · `μm`(변위). 센서가 저장하는 물리량입니다. 비우면 mm/s로 간주하므로, **가속도·변위 센서는 반드시 맞는 단위를 고르십시오** — 틀리면 값을 잘못 환산해 등급 높이가 틀어집니다 |
| Class | 설비 Class(I\~IV). 등급 높이를 정하는 ISO 10816 존 경계가 이 값으로 정해집니다. 비우면 Class II |

각 항목 이름 옆의 <kbd>?</kbd>에 마우스를 올리면 그 값이 무엇인지, 어디서 확인하는지, 비워 두면 어떻게 되는지가 표시됩니다. 목록 위의 **전체 · 판정 불가** 필터로 손볼 태그만 걸러 볼 수 있습니다.

**모르는 항목은 비워 두세요.** 그 항목으로 판정하는 결함만 "이 측정으론 볼 수 없음"으로 남고 나머지 진단은 그대로 진행됩니다. 추측해서 채우면 그 추측이 판정 근거가 되므로 오히려 위험합니다. (단위는 데이터를 넣을 때 이미 정해진 값이므로 계측 담당자에게 확인하면 됩니다.)

### RPM — 정확히 넣는 법

RPM은 추정하지 않습니다. 회전수가 틀리면 결함주파수 격자가 통째로 어긋나는데도 화면은 평소처럼 등급을 내기 때문입니다. **명판에서 확인해 정확히 넣거나, 비워 두고 "판정 못 함"으로 남기십시오.**

정확히 넣는다는 것은 **베어링이 달린 축의 실제 운전 회전수**를 넣는다는 뜻입니다.

- 명판의 **정격 회전수**(예: 4극 60 Hz 전동기면 1750)를 넣고, 동기속도(1800)는 넣지 마십시오. 결함 패턴은 이 값으로 결함 주파수를 계산해 **1% 허용오차**로 대조하므로, 동기속도처럼 2\~3% 틀리면 결함을 놓칩니다.
- 상세분석이 스펙트럼에서 회전수를 재어 입력값과 **2% 넘게 다르면** 경고와 함께 **실측값 N rpm으로 저장** 버튼을 띄웁니다. 누르는 즉시 저장되며, 실측값은 그 순간의 부하 기준이라 부하가 크게 바뀌는 설비는 평소 운전점에서 다시 확인하십시오.
- 실측값을 대조에 바로 쓰지 않는 이유 — 공개 데이터로 검증했을 때 실측 대조는 검출을 늘리지 못하고 정상 오탐만 늘렸습니다. 회전 피크가 약한 설비(가속도 센서 등)는 실측 자체가 잘 안 됩니다.
- **벨트 구동**이면 모터의 정격 회전수를 넣습니다. 센서가 벨트 반대편(팬·펌프 등) 베어링에 붙어 있으면 설정 버튼 → 벨트 제원의 **센서 위치를 종동측**으로 고르십시오 — 앱이 풀리비로 종동축 회전수를 환산하고, 잰 종동축 회전수를 넣으면 그 값을 씁니다(아래 계측·구동 정보).
- **감속기(기어)** 출력축에 붙은 센서면 그 축의 회전수(모터 회전수 ÷ 감속비)를 넣습니다.

### 베어링과 결함 주파수

베어링 모델을 카탈로그에서 선택하면 형상값(볼 수·볼경·피치경·접촉각)이 자동 입력되고 BPFO / BPFI / BSF / FTF 결함 주파수가 RPM과 함께 계산됩니다. 표 오른쪽의 **설정** 버튼을 누르면 계산된 값을 확인할 수 있습니다.

- **카탈로그에 없는 베어링** — 베어링 칸에서 **직접 입력**을 고르면 그 행의 설정 패널이 자동으로 열리고 **품번 칸에 커서**가 놓입니다. 품번과 볼 수 `n`, 볼경 `Bd`, 피치경 `Pd`, 접촉각 `φ`를 입력합니다. 직전에 카탈로그 품번을 골라 두었다면 그 품번과 형상값이 칸에 미리 채워지고 **그 값이 그대로 저장**되므로, 비슷한 품번에서 시작해 다른 칸만 고치면 됩니다.
- **품번 칸** — 실제 품번(예: `SKF 22218 E`)을 적어 둘 수 있습니다(40자까지). 표의 베어링 모델 칸에는 `SKF 22218 E (직접)`, 상세분석과 리포트에는 `SKF 22218 E (직접 입력)`처럼 표시되며, 판정에는 쓰이지 않습니다.
- **롤러 베어링(22218·23124·NU312 등)** — 목록에 없습니다. 같은 품번도 제조사·설계 접미사(E·CC·CA)마다 롤러 수가 달라, 한 값으로 넣으면 결함 주파수가 어긋나 결함을 놓칩니다. 제조사 카탈로그 값을 직접 입력하십시오. 예전 목록에서 골라 두었던 설비는 자동으로 직접 입력으로 바뀌고 품번 칸에 옛 품번, 형상 칸에 옛 값이 옮겨져 있습니다(판정 결과는 그대로). 패널에 주황 안내가 보이면 카탈로그 값으로 확인하십시오.
- **저널(sleeve) 베어링** — 구름요소가 없어 BPFO/BPFI/BSF/FTF가 정의되지 않습니다. 그래서 결함 패턴을 세울 수 없어 **등급이 오르지 않고, 카드는 늘 '판정 보류'**(판정 못 함)로 보이며 설비 정보의 **판정 불가**에 포함됩니다. 상세분석의 규칙 기반 진단은 1×·2× 회전주파수 기준으로 진행됩니다.

베어링을 등록하면 상세분석 FFT에 결함 주파수 마커가 표시되어, 어떤 피크가 어떤 결함인지 대조할 수 있습니다.

### 여러 태그에 한 번에 적용

표 오른쪽의 복사 버튼을 누르면 그 행의 값을 다른 태그에 복사하는 창이 열립니다. 한 설비의 X/Y/Z 채널처럼 RPM·베어링·마운팅이 같은 태그를 한 번에 채울 때 씁니다.

- **복사할 항목** — 채워진 값만 칩으로 나타나고, 눌러서 끄고 켭니다. 단위 · Class · RPM · 베어링 · 품번과 형상 네 칸(직접 입력일 때) · 계측(마운팅) · 구동 · 센서 위치 · 풀리 지름 · 벨트 길이 · 종동축 회전수 · 날개수/잇수.
- **대상** — 같은 설비(이름 앞부분이 같은 태그) · 같은 테이블 · 지금 목록 중에서 고릅니다.

### 계측·구동 정보

표 오른쪽의 **설정** 버튼을 누르면 결함 주파수·형상값과 함께 계측·구동 정보를 입력하는 칸이 열립니다. 버튼에 표시되는 `n/N`은 입력 완성도입니다.

| 항목 | 진단에서 하는 일 |
| :--- | :--- |
| 마운팅 방식 | 센서 부착 방식별로 믿을 수 있는 주파수 상한을 정합니다 — 스터드 10 · 접착 5 · 자석 2 · 핸드프로브 1 kHz |
| 구동방식 | 직결 · 벨트 · 기어. 벨트면 아래 벨트 제원 줄이 나타납니다 |
| 날개수 · 잇수 | 날개수 × 회전주파수 = 베인 통과 주파수(기어면 잇수 × 회전주파수 = 메시 주파수) |
| 벨트 제원 | 풀리 **피치 지름** D1(구동·모터 쪽)·D2(종동 쪽)와 벨트 길이. 피치 지름은 벨트가 감기는 위치의 지름으로 풀리 각인·카탈로그 값입니다(바깥지름보다 조금 작음). 지름 두 개로 종동축 회전수가, 길이까지 있으면 벨트 자체 결함(균열·결손)의 주파수가 계산됩니다 |
| 센서 위치 (벨트) | **모터측**(기본) · **종동측**. 센서가 벨트 반대편(팬·펌프 등) 베어링에 붙어 있으면 종동측을 고르십시오. 종동측이면 결함 패턴·결함 주파수·대역·회전수 경고가 **종동축 회전수**로 계산되고, 표의 RPM 칸에 "종동" 꼬리표가 붙습니다 |
| 종동축 회전수 (종동측일 때) | 타코미터 등으로 잰 종동축 회전수를 넣습니다. 비워 두면 RPM × D1 ÷ D2로 환산합니다 |

> 종동축 회전수가 1\~2%만 틀려도 결함은 잡되 부위(외륜·내륜·볼)를 자주 틀립니다. 풀리 바깥지름으로 환산하면 몇 % 틀리기 쉬우니, 피치 지름을 쓰거나 잰 회전수를 입력하십시오.

전부 선택 입력입니다. 다만 **마운팅 방식은 되도록 지정하는 편이 좋습니다.**

가속도계는 부착 방식에 따라 믿을 수 있는 주파수 상한이 크게 다르고, 특히 자석 마운트는 보통 2\~5 kHz에서 스스로 울립니다(공진). 마운팅을 지정하면 그 상한 위의 대역이 다음과 같이 따로 다뤄집니다.

- 상세분석의 **대역별 충격성(커토그램)** 탐색 범위에서 빠집니다.
- 대역 에너지 근거에서 상한 위 대역의 이탈은 **(잠정)** 으로 표시됩니다 — 값이 오른 것은 사실이지만 설비 진동인지 센서 부착부 공진인지 구분할 수 없다는 뜻입니다.
- 리포트의 진단 근거에 제외된 대역이 함께 인쇄됩니다.

비워 두면 상한 없이 전 대역을 그대로 신뢰합니다.

> 등급을 켜는 결함 패턴은 마운팅 설정과 상관없이 **1\~5 kHz 고정 대역**에서 계산합니다. 자석 마운트의 공진은 이 대역과 겹칠 수 있으니, 자석 마운트 설비에서 결함 패턴이 잡히면 센서 부착 상태부터 확인하십시오.

### 전원 계통주파수

전기적 결함은 계통주파수의 2배(60 Hz 계통이면 120 Hz)에서 나타나며, 회전수가 변해도 움직이지 않는 것이 기계적 결함과의 구분점입니다. 국내는 60 Hz 단일 계통이라 기본값으로 고정되어 있고, 설정 칸은 평소 표시되지 않습니다. 입력된 RPM이 다른 계통의 동기속도(50 Hz면 3000·1500·1000 rpm 계열)에 맞으면 경고와 함께 선택 칸이 나타납니다.

## 판정 기준

등급 자체는 **결함 패턴이 켜고 ISO 존이 높이를 정합니다**([이상 판정 원리]({{< relref "detection" >}})). 이 화면에서는 다음을 설정합니다.

| 설정 | 하는 일 | 등급에 영향 |
| :--- | :--- | :---: |
| 존 경계(임계값) | 등급의 높이(주의·위험·심각)를 가르는 ISO 10816 경계 | 예 |
| 베이스라인 학습 | 설비별 정상 상태를 배워 "평소 대비 급증"을 근거로 표시 | 아니오 |
| 대역·결함 패턴 추출 | 대역 에너지 추세를 쌓고, 결함 패턴을 재는 주기를 정함 | 주기만 |

### 머신 클래스와 존 경계

머신 클래스를 고르면 그 클래스의 존 경계(mm/s RMS)가 미리보기로 표시됩니다. 실제 판정에는 **각 태그의 Class**(설비 정보)가 쓰입니다.

**클래스별 임계값** 표에서 값을 직접 수정할 수 있고, **기본값으로 초기화**로 되돌릴 수 있습니다. 표에는 두 종류의 행이 있습니다.

| 행 | 기본값 | 쓰이는 곳 |
| :--- | :--- | :--- |
| Class I\~IV (속도 `mm/s`) | **ISO 10816 기준값** | **등급의 높이.** 가속도·변위 센서도 속도로 환산해 이 행으로 판정합니다 |
| 가속도 `g` · 변위 `μm` | 일반 참고값 | 그 단위 센서의 RMS 추이 기준선과 기간 통계 표시. 등급에는 쓰이지 않습니다 |

### 베이스라인 학습

설비가 정상일 때의 상태를 학습시키면 "평소 대비" 근거가 한 층 추가됩니다.

정상 운전 구간 RMS의 중심(μ)과 평소 변동(σ)을 학습해, 한계를 넘으면 **평소 대비 급증**으로 표시합니다. 절대값이 ISO A 구간이어도 잡아냅니다. 다만 이 축은 **등급도 이벤트도 만들지 않습니다** — 카드와 근거표에서 눈으로 확인하는 근거입니다.

| 설정 | 값 | 설명 |
| :--- | :--- | :--- |
| 정상 학습 기간 | 최근 1시간 / 6시간 / 24시간 | 길수록 다양한 정상 상태를 포함해 기준이 견고해집니다 |
| k (σ 배수) | 숫자 | 이탈 판정 민감도. `k=3`이면 정상 데이터의 약 99.7%가 한계 안에 들어옵니다. 확신이 없으면 3을 그대로 두세요 |

- 태그별로 **학습**하거나 **전체 학습**으로 한 번에 처리합니다. 학습된 값은 **삭제**할 수 있습니다.
- 데이터가 학습 기간보다 짧으면 있는 만큼만 학습합니다.
- 학습은 알람 설정의 **RMS 구간과 같은 단위**로 이루어집니다. 판정에 쓰는 값과 같은 방식으로 배워야 그 기준이 실제 판정값의 분포를 설명하기 때문입니다. 구간을 바꾸면 기준도 다시 학습하는 편이 좋습니다.
- 미학습 태그가 있으면 화면 상단에 개수가 표시됩니다. 학습 전에도 등급 판정은 정상 동작합니다.

#### 기준이 오래됐을 때

학습한 지 한 달이 넘은 태그가 있으면 화면 상단에 알림이 뜨고, 각 행에 학습 시점 배지가 붙습니다.

앱은 **자동으로 재학습하지 않습니다.** 결함이 자라는 중에 다시 배우면 그 결함이 정상 기준으로 흡수되기 때문입니다. 정비를 했거나 운전 조건이 바뀌었다면 그때 직접 **학습**을 눌러 갱신하십시오.

#### 태그를 지웠다 다시 만든 경우

학습값은 `테이블:태그` 이름을 키로 저장되므로, 같은 이름으로 다른 설비를 붙이면 옛 기준이 그대로 적용됩니다. 새 설비가 더 조용하면 이상을 못 잡고, 더 시끄러우면 이탈 표시가 계속 뜨는데 화면에는 그냥 "학습됨"으로 보입니다.

앱이 이 상황을 감지하면 해당 행에 **같은 설비 — 유지** / **다른 설비 — 초기화** 선택이 나타납니다. 여러 개면 위쪽 **확인 대기 N개** 줄의 **모두 같은 설비 — 유지**로 한 번에 답할 수 있습니다(초기화는 되돌릴 수 없어 행마다 따로 누릅니다). 확인 전까지 그 태그의 베이스라인·대역 근거는 멈추며, 등급 판정(결함 패턴·ISO 존)은 그동안에도 계속 동작합니다.

#### 학습 데이터가 깨끗하지 않을 때

학습 구간에는 보통 정상 운전만 들어 있지 않습니다. 그래서 학습은 다음 세 가지를 자동으로 처리합니다.

**순간 스파이크에 흔들리지 않습니다.** 중심과 변동을 평균·표준편차가 아니라 중앙값 계열로 추정합니다. 스파이크 몇 개만 섞여도 표준편차 방식은 한계를 크게 부풀려, **이탈을 잡으라고 만든 기준이 오히려 이탈을 덮습니다.** 중앙값 방식은 표본의 절반이 오염돼도 유지됩니다.

**정지·기동 구간은 제외합니다.** 운전 수준의 20% 아래로 떨어진 구간(정지·아이들)과 앞뒤로 급변하는 구간(기동·정지 램프)을 학습에서 뺍니다. 무엇을 제외했는지는 학습 완료 안내와 상태 줄에 `제외 12개(정지 8·과도 4)` 형태로 표시됩니다.

**정지가 대부분인 구간은 학습을 거부합니다.** 창의 대부분이 정지면 "정지 상태"가 정상으로 학습되어, 기계를 돌리기만 해도 이탈로 표시됩니다. 이 경우 학습이 실패하고 정상 운전이 대부분인 기간으로 다시 학습하라는 안내가 뜹니다.

여기에 더해, 거의 흔들리지 않는 신호에서는 한계가 μ에 너무 붙지 않도록 **최소 μ의 1.2배**로 유지합니다.

> 이 처리는 결함이 이미 진행 중인 기간을 걸러 주지는 못합니다. 그 구간으로 학습하면 결함 상태가 정상 기준이 됩니다. **정상 운전이 확실한 기간**을 고르는 것은 여전히 사용자의 몫입니다.

### 대역·결함 패턴 추출

판정 기준 화면 맨 아래 **대역 에너지 추세** 카드에 있습니다. 두 가지 일을 합니다.

- **추출 주기**는 **결함 패턴을 재는 주기**이기도 합니다. 등급은 이 주기마다 한 번 바뀔 수 있고, 등급 확정(두 회차 연속)의 회차 길이도 이 주기입니다. 대역 추출을 꺼 두어도 이 주기는 적용됩니다. 기본 10분, 10분 · 30분 · 1시간 중에서 고릅니다.
- **대역·결함 패턴 추출** 스위치를 켜면, 전체 RMS는 거의 안 움직이는데 특정 주파수 대역만 뛰는 변화 — 대표적으로 초기 베어링 결함 — 를 보여 주는 **대역 에너지 추세**를 서버에서 계산해 쌓습니다. 이 값은 등급을 만들지 않고 근거로만 표시됩니다.

대역은 회전주파수(1×) 기준으로 다섯 구간(서브동기 · 1× 대역 · 결함 대역 · 고주파 · 초고주파)으로 나뉘고, 초고주파는 1\~2 · 2\~4 · 4\~8 · 8 kHz+ 네 대역으로 세분되어 모두 8개 대역이 쌓입니다. 베어링 품번이 있으면 포락선 계열(주기성·BPFO·BPFI·BSF)도 함께 쌓입니다.

설정은 세 단계입니다.

1. **대역 추출** — 스위치를 켜고 추출 주기를 정합니다. 주기를 바꾸면 확인 창에서 이전 구간을 어떻게 할지(그대로 둠 · 새 주기로 다시 계산 · 대역 베이스라인 초기화) 고르고 **적용**합니다. RPM이 없는 태그는 추출 대상에서 빠집니다.
2. **과거 데이터 채우기** — 표본이 쌓이길 기다리지 않고, 이미 DB에 있는 원시 데이터로 과거 구간을 소급 계산합니다. 진행률과 예상 소요 시간이 표시되며, 중간에 멈춰도 채운 만큼은 그대로 쓰입니다.
3. **정상 기준 학습** — 표본이 충분해지면 대역별로 학습합니다. 전체 RMS 학습과 같은 방식이며, 같은 자동 필터가 적용됩니다.

**채널별 학습 상태** 머리줄의 `학습됨 X/Y`는 학습을 마친 태그 수 / 전체 태그 수입니다. 각 태그 줄에는 `4/9 계열 학습됨`처럼 계열 수가 표시되는데, 분모는 그 태그에서 측정 가능한 계열 수입니다 — 샘플레이트가 낮거나 마운팅 상한이 낮으면 상위 대역·포락선 계열이 빠지고, 베어링 품번이 없으면 결함주파수 계열이 빠지며, 이는 정상입니다. 학습되지 않은 계열은 근거 표시에서 빠집니다.

> 대역 학습도 **정상 운전이 확실할 때** 하십시오. 결함이 이미 진행 중이면 그 결함이 정상 기준이 됩니다.

## LLM 연동

상세분석과 리포트에 서술형 소견을 덧붙이려면 프로바이더를 하나 이상 설정합니다. 이 기능은 선택이며, 연결하지 않아도 나머지는 모두 동작합니다.

1. 프로바이더(Claude · OpenAI · Gemini · Ollama)를 고릅니다.
2. **API 키**와 **모델**을 입력합니다. 모델을 비워 두면 프로바이더별 기본 모델을 씁니다.
3. Ollama는 API 키 대신 **Ollama URL**을 입력합니다.
4. **연결 테스트**로 설정이 올바른지 확인합니다.

여러 프로바이더를 설정해 두고, 상세분석·리포트 화면의 드롭다운에서 그때그때 골라 쓸 수 있습니다. 연결 테스트는 검증용일 뿐, 기능을 켜는 조건은 "설정이 존재하는가"입니다.

> 소견의 논조와 판정 규칙은 [사용 방법 › LLM 소견]({{< relref "usage#llm-소견-선택" >}})에 정리되어 있습니다.

## 데이터 관리

이 패키지가 만든 표의 크기를 확인하고 정리하는 곳입니다. 오른쪽 위 **새로고침**으로 현황을 다시 읽습니다. 삭제한 데이터는 되돌릴 수 없습니다.

| 항목 | 표시 | 할 수 있는 일 |
| :--- | :--- | :--- |
| 이벤트 이력 | 건수 · 기간 · 감시 대상 밖 건수 | **기간 삭제…**(기간 안 모든 태그) · **태그별 정리…** |
| 대역 에너지 추이 | 행 수 · 기간 · 감시 대상 밖 행 수 | **기간 삭제…**(학습 구간 포함 주의) · **태그별 정리…** |
| 판정 상태 | 행 수 · 감시 대상 밖 행 수 | **안 쓰는 데이터 정리**(확인 없이 즉시 — 다음 판정 때 다시 만들어지는 데이터) |
| 학습값 | 각주로만 표시 | 재학습이 같은 자리를 덮어써 늘지 않습니다. **판정 기준으로 이동**에서 관리합니다 |

- **기간 삭제**는 두 단계입니다. 먼저 지울 기간을 고르고, 다음 화면에서 지워질 양을 확인한 뒤 **표 이름(`EVENTS` 또는 `BAND`)을 직접 입력**해야 삭제 버튼이 켜집니다. 이벤트를 지우면 그 기간을 다룬 리포트를 다시 만들 수 없으니, 먼저 [이벤트 내보내기]({{< relref "usage#이벤트-내보내기" >}})로 저장해 두기를 권합니다.
- **태그별 정리**는 데이터는 남아 있는데 지금 감시하지 않는 태그(철거했거나 데이터 소스에서 뺀 설비)가 있을 때만 나타납니다. 그 태그의 대역 추이·이벤트 이력·판정 상태를 함께 지웁니다. 기간 삭제는 다른 태그까지 지우므로, 특정 설비만 지울 때는 이쪽을 씁니다.
