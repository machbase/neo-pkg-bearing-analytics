# 알람과 이벤트

**한국어** | [English](./alarms.en.md)

알람은 선택한 태그를 주기적으로 판정해 상태 변화를 **이벤트**로 남기고, 설정한 채널로 알리는 기능입니다. 설정은 **설정 → 알람 설정**에 있습니다.

헤더의 알람 표시를 누르면 알람을 켜고 끌 수 있습니다. 이 상태는 저장되어 앱을 다시 열어도 유지되며, 서버 상시 감시 모드일 때는 표시에 모드 배지가 함께 붙습니다.

> 어떤 계산으로 등급과 이벤트가 나오는지는 [이상 판정 원리](./detection.kr.md)에서 다룹니다. 이 문서는 설정과 운영을 다룹니다.

## 감시 방식

먼저 판정을 **누가** 수행할지 고릅니다.

| 방식 | 판정 주체 | 앱을 닫으면 |
| :--- | :--- | :--- |
| 앱 감시 (기본) | 브라우저에 열린 앱 | 판정이 멈춥니다 |
| 서버 상시 감시 | Neo 타이머 | 계속 판정하고 이벤트를 쌓습니다 |

### 앱 감시

앱이 열려 있는 동안 판정 주기마다 선택 태그를 판정합니다. 별도 준비 없이 바로 동작하지만, 창을 닫으면 그동안의 판정은 이루어지지 않습니다.

상시 감시가 필요 없거나, 설정을 시험해 보는 단계라면 이쪽이 편합니다.

### 서버 상시 감시

**저장**하면 현재 판정 설정이 Neo 타이머로 등록되어, 앱을 닫아도 판정이 계속됩니다. 이 모드에서 앱 화면은 결과를 **표시만** 하고 판정은 서버가 담당합니다.

판정 규칙은 두 방식이 동일하므로, 모드를 바꿔도 같은 데이터에서 같은 결과가 나옵니다.

알아 둘 점:

- **설정을 바꾸면 다시 저장해야 반영됩니다.** 타이머는 저장 시점의 설정으로 동작합니다.
- **ROLLUP이 있는 테이블만 판정합니다.** 롤업이 없는 테이블의 태그는 서버 감시에서 조용히 제외되므로, 그런 태그는 앱 감시로 확인합니다.
- **서버 모드를 끄면 타이머가 삭제됩니다.** 패키지를 제거할 때도 함께 정리됩니다.
- **감시할 태그가 없으면 타이머를 만들지 않습니다.**

## 판정 주기와 구간

> **먼저 알아 둘 것 — 감시는 두 주기로 돕니다.**
>
> | | 하는 일 | 주기 |
> | :--- | :--- | :--- |
> | 빠른 축 | 운전/정지 · 신호 두절 · 계측 이상 · 진폭 추적 | 아래에서 정하는 **판정 주기**(기본 10초) |
> | 느린 축 | **결함 패턴 — 등급과 이벤트는 여기서 나옵니다** | **패턴·대역 추출 주기**(기본 10분) |
>
> 아래 설정은 **빠른 축**을 정합니다. 등급이 실제로 바뀌는 것은 느린 축이라,
> 판정 주기를 1초로 줄여도 알람이 더 빨리 오지는 않습니다.
> 자세한 것은 [이상 판정 원리](./detection.kr.md)에 있습니다.

알람 설정의 첫 항목은 한 문장으로 되어 있습니다.

> 직전 **[RMS 구간]** 구간의 데이터를 **[판정 주기]** 마다 판정

| 설정 | 선택지 | 뜻 |
| :--- | :--- | :--- |
| RMS 구간 | 3초 · 10초 · 30초 · 1분 · 5분 · 10분 · 30분 · 1시간 · 직접 입력 | 한 번 판정할 때 얼마나 긴 데이터를 볼지 |
| 판정 주기 | 1초 · 3초 · 5초 · 10초 · 30초 · 1분 | 얼마나 자주 판정할지 |

- 구간이 **길수록** 짧은 출렁임이 하나로 합쳐져 오경보가 줄고, 대신 반응이 느려집니다.
- 구간이 판정 주기보다 짧으면 그 사이 데이터가 판정에 들어가지 않습니다 — 이 조합은 선택할 수 없게 막히고 경고가 표시됩니다.
- 부하가 주기적으로 변하는 설비라면 그 변동 주기보다 긴 구간을 잡으십시오. 짧으면 부하 변화가 이상으로 잡힙니다.
- 태그 수가 많고 주기가 짧으면 부하 경고가 표시됩니다.

이 설정은 알람뿐 아니라 **모니터링 카드의 현재 등급**에도 그대로 적용됩니다. 화면에 보이는 등급과 알람이 판정한 등급은 항상 같은 정의를 씁니다.

## 알림

알람을 **언제** 낼지(진입 확인·복귀 유지)와 **어디로 어떻게** 보낼지(채널·심각도별 방식·재알림)를 한곳에서 설정합니다.

### 언제 낼지 — 진입·복귀 시간

순간 스파이크와 경계 오르내림(플래핑)으로 인한 소음을 줄이는 설정입니다.

| 설정 | 선택지 | 뜻 |
| :--- | :--- | :--- |
| 진입 확인 시간 | 즉시 · 30초 · 1분 · 2분 · 5분 | 등급이 **나빠진** 상태가 이 시간 이상 지속돼야 알람 |
| 복귀 유지 시간 | 즉시 · 1분 · 5분 · 10분 | 정상으로 돌아온 뒤 이 시간 이상 유지돼야 복귀 알람 |

알람이 예상보다 적게 온다면 진입 확인 시간을, 너무 자주 온다면 복귀 유지 시간을 먼저 확인하십시오.

> **판정이 10분 주기라 이 설정의 뜻이 달라졌습니다.** 진입 확인 시간이 10분보다 짧으면
> 사실상 "다음 회차에 바로 확정"입니다 — 그 사이에 등급 판정이 한 번도 일어나지 않기 때문입니다.
> 실제로 지연을 주려면 추출 주기의 **배수**로 잡으십시오(추출 10분 + 진입 20분 = 2회차 연속 확인).
> 복귀 유지 시간은 그대로 유효합니다 — 등급이 경계를 오르내릴 때 복귀 알림이 반복되는 것을 막습니다.

### 어디로 보낼지 — 알림 채널

발송 채널은 **웹훅** 하나입니다. URL을 보고 대상 서비스를 판별해 메시지 형식을 맞춰 보내므로, 아래 서비스는 URL만 넣으면 됩니다.

| 대상 | 메시지 형태 |
| :--- | :--- |
| Discord | 심각도별 색 막대가 붙은 카드 (주의 호박 · 위험 주황 · 심각 적색 · 복귀 녹색) |
| Slack · Microsoft Teams · Google Chat | 텍스트 3줄 (제목 · 값 · 시각) |
| 자체 엔드포인트 (그 외 URL) | 제목 · 본문 텍스트 · HTML 본문 · 구조화된 이벤트 데이터 전부 |

URL을 넣고 **테스트 발송**을 누르면 실제로 한 건 보내 연결을 확인할 수 있습니다.

> **웹훅 URL은 비밀번호와 같습니다.** URL을 가진 사람은 누구나 그 채널에 게시할 수 있습니다. 유출됐다면 해당 서비스에서 웹훅을 삭제하고 새로 만드십시오 — 삭제 즉시 옛 URL은 무효가 됩니다.

이메일·문자(SMS)로 받아야 한다면 웹훅을 **자동화 도구로 중계**합니다. n8n·Node-RED·Zapier·Google Apps Script 같은 도구의 웹훅 수신 URL을 채널에 넣으면, 자체 엔드포인트용 페이로드에 메일 제목(`subject`)과 HTML 본문(`body`)까지 담겨 가므로 받은 쪽에서 바로 메일·문자로 변환할 수 있습니다.

### 심각도별 알림

심각도마다 알림 여부와, 비정상이 이어질 때 다시 알릴 주기를 정합니다.

| 열 | 선택지 | 뜻 |
| :--- | :--- | :--- |
| 알림 방식 | 즉시 · 알림 안 함 | 이 심각도의 이벤트를 보낼지 |
| 지속 시 재알림 | 끔 · 30분 · 1시간 · 2시간 · 6시간 | 비정상 상태가 계속될 때 다시 알릴 주기 |

- 기본값은 **위험·심각만 즉시**이고 주의는 알림 안 함입니다.
- **알림 안 함**이어도 이벤트는 기록됩니다 — 발송만 건너뜁니다. 재알림 이벤트도 마찬가지로 이력에는 항상 남습니다.
- **복귀 알림**은 주의·위험·심각 중 하나라도 즉시로 되어 있으면 발송됩니다. 알람을 받았다면 해제도 알아야 하기 때문입니다.
- 채널은 켜져 있는데 모든 심각도가 알림 안 함이면 화면에 경고가 표시됩니다.

## 웹훅 설정 가이드

### Discord

서버 관리 권한이 있는 채널에서 진행합니다. 알람 전용 채널(예: `#진동-알람`)을 하나 만들어 거는 것을 권합니다 — 대화 채널에 섞이면 알람을 되짚기 어렵습니다.

1. 채널 옆 **⚙️ 채널 편집** 클릭
2. 왼쪽 메뉴 **연동** (Integrations)
3. **웹후크 → 새 웹후크** — 이름·아바타는 자유 (예: `진동 감시`)
4. **웹후크 URL 복사**

URL은 `https://discord.com/api/webhooks/…` 형태입니다. 앱의 웹훅 칸에 붙여넣고 테스트 발송으로 확인합니다.

알림은 심각도 색 막대가 붙은 카드로 도착합니다. 발송 제한은 웹훅당 2초에 5건 수준으로, 정상 운영에서는 닿지 않습니다.

### Google Chat (스페이스)

**Workspace(회사·조직) 계정 전용**입니다 — 개인 `@gmail.com` 계정의 Chat에는 웹훅 메뉴가 없습니다. 웹훅은 스페이스에만 달 수 있습니다 (DM 불가).

1. [chat.google.com](https://chat.google.com) → **스페이스 → + 스페이스 만들기** (예: `진동-알람`)
2. 스페이스 이름 클릭 → **앱 및 통합** (Apps & integrations)
3. **웹훅 → 웹훅 추가** — 이름 입력 (예: `진동 감시`), 아바타 URL은 비워도 됨 → **저장**
4. 생성된 **URL 복사**

URL은 `https://chat.googleapis.com/v1/spaces/…` 형태입니다. 발송 제한은 스페이스당 분당 60건입니다.

웹훅 메뉴가 안 보이면 개인 계정이거나, Workspace 관리자가 웹훅을 꺼 둔 경우입니다 (관리 콘솔 → Chat 설정에서 허용 필요).

### Slack

Slack은 웹훅이 "앱" 안에 들어 있어 앱을 하나 만들어야 합니다. 5분 정도 걸립니다.

**1) 앱 만들기 — [api.slack.com/apps](https://api.slack.com/apps)**

1. 워크스페이스 계정으로 로그인 → **Create New App**
2. **From scratch** 선택
3. 앱 이름 입력 (예: `진동 감시`) → 붙일 **워크스페이스 선택** → **Create App**

**2) Incoming Webhooks 켜기**

여기서부터는 방금 만든 **앱의 설정 화면 안**입니다. [api.slack.com/apps](https://api.slack.com/apps)는 앱 목록 페이지라 메뉴가 없으니, 목록에서 앱 이름을 클릭해 들어갑니다.

1. 왼쪽 사이드바 **Features → Incoming Webhooks** (안 보이면 **Basic Information** 페이지의 "Add features and functionality" 아코디언을 펼치면 같은 화면으로 가는 카드가 있습니다)
2. 토글을 **On**으로
3. 아래쪽 **Add New Webhook to Workspace** 클릭
4. 알람 받을 **채널 선택** (예: `#진동-알람`) → **허용**
5. 생성된 **Webhook URL 복사**

URL은 `https://hooks.slack.com/services/T…/B…/…` 형태입니다.

**우회로** — 앱을 만들지 않으려면: Slack 클라이언트에서 워크스페이스 이름 → **도구 및 설정 → 앱 관리** → 검색창에 **"Incoming WebHooks"** → **Slack에 추가** → 채널 선택. Slack이 레거시로 표시하지만 동작은 같습니다.

알아 둘 점:

- 발송 제한은 **초당 1건** 기준으로, 세 서비스 중 가장 빡빡합니다.
- 무료 플랜은 **90일 지난 메시지가 숨겨집니다.** 알람 이력은 Slack이 아니라 앱의 이벤트 목록에서 되짚으십시오 — 이벤트는 자동 삭제되지 않습니다.
- 채널을 여러 개 쓰려면 **Add New Webhook to Workspace**를 반복하면 채널마다 별도 URL이 나옵니다. 단, 앱의 웹훅 칸은 하나이므로 심각도별로 다른 채널에 보내는 것은 지원하지 않습니다.

## 대역 에너지 감시 (선택)

전체 진동은 거의 안 움직이는데 특정 주파수 대역만 뛰는 변화 — 대표적으로 초기 베어링 결함 — 를 잡으려면 대역 에너지 감시를 켭니다. **설정 → 판정 기준 → 대역 에너지 추세**에 있습니다.

사용 순서는 다음과 같습니다.

1. **대역 추출**을 켜고 추출 주기를 정합니다 (10분 · 30분 · 1시간).
2. 표본이 부족하면 **과거 데이터 채우기**로 이미 DB에 있는 원시 데이터를 소급 계산합니다.
3. 표본이 충분해지면 **학습**으로 계열별 정상 기준을 만듭니다.
4. 학습된 계열이 한계를 넘으면 카드와 근거표에 **한계 대비 배수**로 표시됩니다.

> **대역은 알림을 내지 않습니다.** 8개 계열을 각각 한계와 대보고 하나라도 넘으면 켜는 구조라
> 그 자체가 작은 다중비교이고(단독 오탐 13%), 판정 시간축도 등급과 다릅니다.
> 대역 값은 알림이 아니라 **"어느 대역이 움직였나"로 원인을 좁히는 근거**로 씁니다.
> 같은 이유로 베이스라인 이탈도 알림을 내지 않습니다 — 표시만 됩니다.

주파수 대역 8개에 더해 **포락선 계열**(주기성, 베어링 품번이 있으면 BPFO·BPFI·BSF 결함주파수)도 함께 쌓이고 같은 방식으로 판정됩니다. 채널별 학습 상태는 `학습됨 4/9`처럼 표시되는데, 분모는 그 태그에서 **측정 가능한 계열 수**입니다 — 샘플레이트가 낮으면 상위 대역이 빠지고, 베어링 품번이 없으면 결함주파수 계열이 빠지며, 이는 정상입니다.

> 학습은 **정상 운전이 확실할 때** 하십시오. 결함이 이미 진행 중이면 그 결함이 정상 기준이 됩니다.

## 이벤트

판정 결과는 Neo에 이벤트로 쌓이며, 앱을 다시 열거나 타이머가 다시 돌아도 이어집니다.

이벤트는 **모니터링** 탭 아래쪽 목록에서 확인합니다. 기간 칩과 태그·유형 필터로 좁혀 볼 수 있고, 각 행을 누르면 그 시점의 상세분석으로 이동합니다.

유형별 의미와 기록 규칙은 [이상 판정 원리](./detection.kr.md)를 참고하십시오.

- 목록은 최근 **200건**까지 표시합니다. 전체 이력은 **저장**(내보내기)에서 기간을 지정해 CSV·JSON으로 받습니다.
- 이벤트는 자동으로 삭제되지 않습니다. 철거한 설비의 이력은 **설정 → 데이터 관리 → 태그별 정리**에서 지웁니다.

## 감시 상태 확인

"이벤트가 없다"에는 두 가지 뜻이 있습니다 — 설비가 정상이거나, 감시가 돌지 않거나. 앱은 이 둘을 구분해 화면 상단에 알립니다.

| 표시 | 뜻 | 조치 |
| :--- | :--- | :--- |
| 감시 타이머가 등록되어 있지 않습니다 | 서버 감시가 등록되지 않음 | **다시 등록** 버튼 |
| 서버 감시가 멈춰 있습니다 | 타이머가 정지 상태 (사유 함께 표시) | **다시 등록** 버튼 |
| 마지막 판정이 N분 전입니다 | 타이머는 돌지만 판정이 멈춤 | **다시 등록** 버튼 |
| 판정 대상이 0개입니다 | 감시 태그에 새 데이터가 없음 | 데이터 수집 상태 확인 |
| 대역 추출이 멈춰 있습니다 | 대역 감시 타이머 정지 | **다시 등록** 버튼 |
| 앱 판정이 N분 동안 멈춰 있습니다 | 앱 모드에서 브라우저가 판정을 지연 | 탭을 다시 열거나 새로고침 |

또한 판정값이 짧은 간격으로 악화·개선을 반복하면 **플래핑 안내**가 표시됩니다. 이는 설비 이상이라기보다 RMS 구간이 그 설비의 부하 변동 주기보다 짧다는 신호이므로, 안내에 나온 값 이상으로 구간을 늘리십시오.

## 확인 순서

알람이 의도대로 도는지 볼 때는 이 순서로 확인합니다.

1. 헤더 알람 표시가 **켜짐**인지, 서버 모드라면 배지가 붙어 있는지.
2. 화면 상단에 감시 상태 경고가 없는지.
3. **모니터링 → 이벤트** 목록에 판정 결과가 쌓이는지. 유형·태그 필터로 좁혀 봅니다.
4. 알림이 안 오면 채널 **테스트 발송**으로 발송 경로를 먼저 분리해 확인합니다.
5. 테스트는 오는데 실제 알람이 안 오면 **심각도별 알림 방식**과 **진입 확인 시간**(그 시간만큼 지속돼야 확정)을 확인합니다.
6. 서버 모드에서 특정 태그만 조용하면 그 테이블에 ROLLUP이 있는지 확인합니다.
7. 진동은 분명히 높은데 아무 알람도 없으면 **회전수와 베어링 품번**이 채워져 있는지 확인합니다 — 둘 중 하나가 비면 결함 패턴을 계산할 수 없어 등급이 오르지 않습니다. 카드의 커버리지 표시에 나타납니다.
