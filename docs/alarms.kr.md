# 알람과 이벤트

**한국어** | [English](./alarms.en.md)

알람은 선택한 태그를 주기적으로 판정해 상태 변화를 **이벤트**로 남기고, 설정한 채널로 통지하는 기능입니다. 설정은 **설정 → 알람 설정**에 있습니다.

헤더의 알람 표시를 누르면 알람을 켜고 끌 수 있습니다. 이 상태는 저장되어 앱을 다시 열어도 유지되며, 서버 상시 감시 모드일 때는 표시에 모드 배지가 함께 붙습니다.

> 어떤 계산으로 등급과 이벤트가 나오는지는 [이상 판정 원리](./detection.kr.md)에서 다룹니다. 이 문서는 설정과 운영을 다룹니다.

## 감시 방식

먼저 판정을 **누가** 수행할지 고릅니다.

| 방식 | 판정 주체 | 앱을 닫으면 |
| :--- | :--- | :--- |
| 앱 감시 (기본) | 브라우저에 열린 앱 | 판정이 멈춥니다 |
| 서버 상시 감시 | Neo 타이머 | 계속 판정하고 이벤트를 쌓습니다 |

### 앱 감시

앱이 열려 있는 동안 판정 주기마다 선택 태그를 판정합니다. 별도 준비 없이 바로 동작하지만, 창을 닫으면 그동안의 판정은 이루어지지 않습니다.

상시 감시가 필요 없거나, 설정을 시험해 보는 단계라면 이쪽이 편합니다.

### 서버 상시 감시

**저장**하면 현재 판정 설정이 Neo 타이머로 등록되어, 앱을 닫아도 판정이 계속됩니다. 이 모드에서 앱 화면은 결과를 **표시만** 하고 판정은 서버가 담당합니다.

판정 규칙은 두 방식이 동일하므로, 모드를 바꿔도 같은 데이터에서 같은 결과가 나옵니다.

알아 둘 점:

- **설정을 바꾸면 다시 저장해야 반영됩니다.** 타이머는 저장 시점의 설정으로 동작합니다.
- **ROLLUP이 있는 테이블만 판정합니다.** 롤업이 없는 테이블의 태그는 서버 감시에서 조용히 제외되므로, 그런 태그는 앱 감시로 확인합니다.
- **서버 모드를 끄면 타이머가 삭제됩니다.** 패키지를 제거할 때도 함께 정리됩니다.
- **감시할 태그가 없으면 타이머를 만들지 않습니다.**

## 판정 주기와 구간

알람 설정의 첫 항목은 한 문장으로 되어 있습니다.

> 직전 **[RMS 구간]** 구간의 데이터를 **[판정 주기]** 마다 판정

| 설정 | 선택지 | 뜻 |
| :--- | :--- | :--- |
| RMS 구간 | 3초 · 10초 · 30초 · 1분 · 5분 · 10분 · 30분 · 1시간 · 직접 입력 | 한 번 판정할 때 얼마나 긴 데이터를 볼지 |
| 판정 주기 | 1초 · 3초 · 5초 · 10초 · 30초 · 1분 | 얼마나 자주 판정할지 |

- 구간이 **길수록** 짧은 출렁임이 하나로 합쳐져 오경보가 줄고, 대신 반응이 느려집니다.
- 구간이 판정 주기보다 짧으면 그 사이 데이터가 판정에 들어가지 않습니다 — 이 조합은 선택할 수 없게 막히고 경고가 표시됩니다.
- 부하가 주기적으로 변하는 설비라면 그 변동 주기보다 긴 구간을 잡으십시오. 짧으면 부하 변화가 이상으로 잡힙니다.
- 태그 수가 많고 주기가 짧으면 부하 경고가 표시됩니다.

이 설정은 알람뿐 아니라 **모니터링 카드의 현재 등급**에도 그대로 적용됩니다. 화면에 보이는 등급과 알람이 판정한 등급은 항상 같은 정의를 씁니다.

## 알람 동작

순간 스파이크와 경계 오르내림(플래핑)으로 인한 소음을 줄이는 설정입니다.

| 설정 | 선택지 | 뜻 |
| :--- | :--- | :--- |
| 진입 확인 시간 | 즉시 · 30초 · 1분 · 2분 · 5분 | 등급이 **나빠진** 상태가 이 시간 이상 지속돼야 알람 |
| 복귀 유지 시간 | 즉시 · 1분 · 5분 · 10분 | 정상으로 돌아온 뒤 이 시간 이상 유지돼야 복귀 알람 |
| 지속 재알림 | 끔 · 30분 · 1시간 · 2시간 · 6시간 | 비정상 상태가 계속될 때 다시 알릴 주기 (심각도별) |

지속 재알림을 **끔**으로 두면 상태가 변할 때만 알립니다.

알람이 예상보다 적게 온다면 진입 확인 시간을, 너무 자주 온다면 복귀 유지 시간과 재알림 주기를 먼저 확인하십시오.

## 대역 에너지 감시 (선택)

전체 진동은 거의 안 움직이는데 특정 주파수 대역만 뛰는 변화 — 대표적으로 초기 베어링 결함 — 를 잡으려면 대역 에너지 감시를 켭니다. **설정 → 판정 기준 → 대역 에너지 추세**에 있습니다.

사용 순서는 다음과 같습니다.

1. **대역 추출**을 켜고 추출 주기를 정합니다. 주기가 짧을수록 표본이 빨리 쌓입니다.
2. 표본이 부족하면 **과거 데이터 채우기**로 이미 DB에 있는 원시 데이터를 소급 계산합니다.
3. 표본이 충분해지면 **학습**으로 대역별 정상 기준을 만듭니다.
4. 학습된 대역이 한계를 넘으면 **대역 이탈** 이벤트가 생성됩니다.

채널별 학습 상태에 `학습됨 4/5`처럼 표시됩니다. 샘플레이트가 낮은 센서는 상위 대역을 측정할 수 없어 5개를 다 채울 수 없으며, 이는 정상입니다.

> 학습은 **정상 운전이 확실할 때** 하십시오. 결함이 이미 진행 중이면 그 결함이 정상 기준이 됩니다.

## 이벤트

판정 결과는 Neo에 이벤트로 쌓이며, 앱을 다시 열거나 타이머가 다시 돌아도 이어집니다.

이벤트는 **모니터링** 탭 아래쪽 목록에서 확인합니다. 기간 칩과 태그·유형 필터로 좁혀 볼 수 있고, 각 행을 누르면 그 시점의 상세분석으로 이동합니다.

유형별 의미와 기록 규칙은 [이상 판정 원리](./detection.kr.md)를 참고하십시오.

- 목록은 최근 **200건**까지 표시합니다. 전체 이력은 **저장**(내보내기)에서 기간을 지정해 CSV·JSON으로 받습니다.
- 이벤트는 자동으로 삭제되지 않습니다.

## 알림

이벤트가 발생했을 때 통지할 채널과 심각도별 발송 정책을 지정합니다.

### 채널

| 채널 | 상태 | 대상 |
| :--- | :--- | :--- |
| 웹훅 | 사용 가능 | Slack · Teams · Discord · 자체 엔드포인트 URL |
| 이메일 | 준비 중 | 사내 SMTP 릴레이 경유 |
| SMS | 준비 중 | 공급자 API 경유 |

웹훅 URL을 넣고 **테스트**를 누르면 실제로 한 건 보내 연결을 확인할 수 있습니다. 메시지 형식은 URL을 보고 대상 서비스에 맞춰 조립되므로, Slack·Teams·Discord는 URL만 넣으면 됩니다. 자체 엔드포인트에는 제목·본문·구조화된 이벤트 데이터가 함께 전달됩니다.

### 심각도별 라우팅

심각도마다 어느 채널로 보낼지, 어떤 방식으로 보낼지(즉시 · 무시) 지정합니다.

- 기본값은 **위험 · 심각만 발송**이고 주의는 꺼져 있습니다.
- 통지 방식을 **무시**로 두면 이벤트는 기록되지만 알림은 나가지 않습니다.
- **복귀 알림**은 주의 · 위험 · 심각 중 하나라도 그 채널로 라우팅되어 있으면 발송됩니다. 알람을 받았다면 해제도 알아야 하기 때문입니다.
- 채널은 켜져 있는데 라우팅된 심각도가 하나도 없으면 화면에 경고가 표시됩니다.

## 감시 상태 확인

"이벤트가 없다"에는 두 가지 뜻이 있습니다 — 설비가 정상이거나, 감시가 돌지 않거나. 앱은 이 둘을 구분해 화면 상단에 알립니다.

| 표시 | 뜻 | 조치 |
| :--- | :--- | :--- |
| 감시 타이머가 등록되어 있지 않습니다 | 서버 감시가 등록되지 않음 | **다시 등록** 버튼 |
| 서버 감시가 멈춰 있습니다 | 타이머가 정지 상태 (사유 함께 표시) | **다시 등록** 버튼 |
| 마지막 판정이 N분 전입니다 | 타이머는 돌지만 판정이 멈춤 | **다시 등록** 버튼 |
| 판정 대상이 0개입니다 | 감시 태그에 새 데이터가 없음 | 데이터 수집 상태 확인 |
| 대역 추출이 멈춰 있습니다 | 대역 감시 타이머 정지 | **다시 등록** 버튼 |
| 앱 판정이 N분 동안 멈춰 있습니다 | 앱 모드에서 브라우저가 판정을 지연 | 탭을 다시 열거나 새로고침 |

또한 판정값이 짧은 간격으로 악화·개선을 반복하면 **플래핑 안내**가 표시됩니다. 이는 설비 이상이라기보다 RMS 구간이 그 설비의 부하 변동 주기보다 짧다는 신호이므로, 안내에 나온 값 이상으로 구간을 늘리십시오.

## 확인 순서

알람이 의도대로 도는지 볼 때는 이 순서로 확인합니다.

1. 헤더 알람 표시가 **켜짐**인지, 서버 모드라면 배지가 붙어 있는지.
2. 화면 상단에 감시 상태 경고가 없는지.
3. **모니터링 → 이벤트** 목록에 판정 결과가 쌓이는지. 유형·태그 필터로 좁혀 봅니다.
4. 알림이 안 오면 채널 **테스트**로 발송 경로를 먼저 분리해 확인합니다.
5. 서버 모드에서 특정 태그만 조용하면 그 테이블에 ROLLUP이 있는지 확인합니다.
