# 문제 해결

[English](./troubleshooting.en.md) | [한국어](./troubleshooting.kr.md) | [日本語](./troubleshooting.ja.md)

## 데이터베이스에 접근할 수 없다는 안내만 보임

로그인한 계정이 저장소(`NEO_BEARING_STORE`) 권한을 못 받은 상태입니다. 관리자(SYS)가 설정 →
데이터 소스의 **패키지 사용 계정 권한** 목록에서 그 계정 줄의 **권한 주기**를 누르면 됩니다. 들어갔는지는 그 줄의 상태(권한 있음)로 확인합니다.
받은 뒤 `상태 확인`을 누르면 새로고침 없이 이어집니다.

SYS인데도 이 안내가 보인다면 데이터베이스가 아직 없는 것입니다 — 같은 카드의 `만들기`를 누릅니다.

## 서버 감시를 켰는데 이벤트가 하나도 안 생김

먼저 모니터링 화면 맨 위의 감시 상태 경고를 확인합니다.

- **"판정 대상이 0개입니다"** — 타이머는 돌지만 전 태그를 건너뛰고 있습니다. 흔한 원인은 **데이터 테이블 권한**입니다. 목록과 화면은 보이더라도, 서버 감시는 그 테이블을 직접 조회하므로 등록한 계정에 `SELECT` 권한이 없으면 조용히 0건으로 끝납니다. 관리자에게 `GRANT SELECT ON MACHBASEDB.SYS.<테이블> TO <계정>;`을 요청하십시오. 테이블에 ROLLUP이 없거나 새 데이터가 안 들어오는 경우도 같은 경고가 뜹니다.
- **"N대를 훑었지만 결함 패턴을 잰 태그가 0입니다"** — 판정은 돌지만 등급을 켜는 축이 비어 있습니다. RPM·베어링 모델이 없거나, 판정 창에 표본이 모자랍니다. **설비 정보 열기** 버튼으로 이동해 채웁니다.
- 경고가 없다면 아래 [이벤트가 기록되지 않음](#이벤트가-기록되지-않음)을 확인합니다. 등급 이벤트는 추출 주기(기본 10분)마다, 그것도 두 회차 연속이라야 확정되므로 켜자마자 바로 생기지는 않습니다.

## 타이머 목록에 같은 이름이 여러 개

Neo는 타이머 이름 중복을 막지 않습니다. 앱은 등록 전에 같은 이름을 전부 지우고 정말 지워졌는지
확인하지만, 목록 조회가 실패하는 동안(예: DB 부하) 생긴 중복은 그때 못 막습니다.
부하가 풀린 뒤 **서버 감시를 껐다 켜면** 스스로 정리됩니다. 급하면 Neo 타이머 화면에서 직접 지웁니다 —
**멈춘 뒤 지워야** 합니다. 멈추지 않고 지우기만 하면 계속 실행될 수 있습니다.

## "설정을 불러오지 못했습니다" 화면이 뜸

앱이 켜질 때 저장된 설정을 읽지 못한 것입니다. 이때 앱은 탭을 열지 않습니다 — 기본값으로 화면을 띄운 채 저장하면 실제 설정을 덮어쓰기 때문입니다.

- **설정을 불러오지 못했습니다** — 대개 일시적인 연결 문제입니다. 설정은 DB에 그대로 있으니 **다시 시도**를 누릅니다.
- **<영역> 설정을 읽을 수 없습니다** — 저장 도중 연결이 끊겨 그 영역(예: 설비 정보)의 설정 일부가 손상된 경우입니다. 다시 시도해도 같다면 **<영역>만 기본값으로 열기**를 누릅니다. 나머지 설정은 그대로 불러오고 그 영역의 설정 화면으로 이동합니다. 누르는 것만으로는 아무것도 저장되지 않으니, 그 영역을 다시 설정한 뒤 저장하십시오.

## 설비 카드가 하나도 안 보임

- 앱이 "DB에서 TAG 테이블을 찾지 못했습니다"를 표시하면, Neo에 연결됐지만 TAG table이 없는 경우입니다. Neo 연결 상태와 TAG table 존재를 확인합니다. 이때 목데이터로 대체하지 않으므로 화면은 빈 상태로 남습니다.
- table은 있는데 카드가 없다면, **설정 → 데이터 소스**에서 아직 table을 선택하지 않은 것입니다. 분석할 table을 선택하고 저장합니다.
- "표시할 테이블을 하나도 고르지 않았습니다"가 보이면 모니터링 화면의 **테이블 필터**로 전부 숨긴 것입니다. **전체 표시**를 누릅니다(감시는 그대로 돌고 있습니다).
- "데이터 적재 실패"가 표시되면 선택한 table 조회 중 오류가 난 경우입니다. 메시지에 원인이 함께 표시됩니다.
- "데이터를 불러오지 못했습니다"가 표시되면 선택한 table을 조회하지 못한 것입니다. 선택은 그대로 남아 있고 자동으로 다시 시도합니다 — 아래 "데이터를 다시 불러오지 못했습니다"를 참고하십시오.

## "데이터를 다시 불러오지 못했습니다" 배너가 뜸

설정을 저장한 뒤나 새 태그가 감지됐을 때 데이터를 다시 읽다가 table 조회가 실패한 것입니다.

- 감시는 멈추지 않습니다. **마지막으로 불러온 데이터로 계속 감시**하면서 자동으로 다시 시도합니다(10초부터 간격을 두 배씩 늘려 최대 5분).
- 그 사이 **새로 고른 table은 감시되지 않습니다**(배너에 이름이 나옵니다). 선택에서 뺀 table은 저장 즉시 감시에서 빠집니다.
- 선택은 이미 저장되어 있으므로 다시 저장할 필요는 없습니다. 재시도가 한 번 성공하면 배너가 사라지고 정상 감시로 돌아옵니다. 기다리지 않으려면 **지금 다시 시도**를 누릅니다.
- 계속 실패하면(3회째부터 배너에 안내가 붙습니다) 배너에 적힌 table이 지워졌거나 권한이 회수됐는지 확인하고, 필요하면 **설정 → 데이터 소스**에서 선택을 해제하고 저장합니다.
- 실패하는 동안에는 서버 감시 타이머를 다시 만들지 않습니다. 불완전한 목록으로 타이머를 고치면 못 읽은 설비가 서버 감시에서도 빠지기 때문입니다.

## 태그가 일부만 보임

적재 상한 때문입니다 — **table당 태그 60개**, **전체 설비 100개**까지만 적재합니다. 쿼리 폭주를 막기 위한 제한입니다. 상한에 걸린 태그는 데이터 소스의 별칭 표에 **감시 제외** 배지가 붙습니다.

분석 대상 table만 선택해 범위를 좁히거나, 대상을 나눠 확인합니다.

## 데이터 소스에서 테이블을 선택할 수 없음

목록에서 흐리게 표시되고 체크가 안 되는 테이블은 컬럼 구성이 `NAME · TIME · VALUE`가 아닌 테이블입니다(사유가 함께 표시됩니다). 이 앱은 표준 컬럼명만 조회하므로 아직 지원하지 않습니다.

## 데이터 소스에 방금 넣은 태그가 안 뜸

- 데이터 소스 목록은 진입 시점 기준입니다. 태그를 새로 넣었다면 설정 화면을 다시 열어 목록을 갱신합니다.
- 모니터링 화면 상단에 데이터 소스 변동 배너가 떠 있으면 **다시 불러오기**를 누릅니다.

## 프리셋(1시간·6시간 등)이 비활성화됨

그 태그의 데이터가 프리셋 길이보다 짧다는 뜻입니다.

- 눌러 보면 "데이터가 부족합니다" 안내가 뜹니다.
- **전체** 프리셋으로 확인하면 그 태그의 데이터 전 구간을 볼 수 있습니다.
- 데이터가 더 쌓이면 프리셋은 자동으로 다시 켜집니다.

## 상세분석이 실시간으로 안 바뀜

정상입니다. 상세분석은 들어온 시점으로 고정되는 **스냅샷**입니다. 최신 상태를 보려면 **새로고침**을 누르거나, 상세분석에서 나갔다 다시 들어오거나, 태그를 바꿔 다시 캡처합니다.

## "신호 이상 — 센서 점검 필요" 경고가 뜸

클리핑(포화)·플랫라인·DC 드리프트·단발 스파이크처럼 **측정 자체가 의심되는 패턴**이 감지된 것입니다. 이때 진단은 **진단 보류** 상태가 되고, 모든 결함 후보의 근거 점수가 함께 낮아집니다.

- 신뢰도가 특정 후보만이 아니라 **전부** 내려갑니다. 측정이 흔들리면 스펙트럼 전체가 영향을 받기 때문에, 일부만 낮추면 검증되지 않은 후보가 오히려 1순위로 올라옵니다.
- 포화된 신호에서 읽은 진폭은 실제보다 **낮게** 나옵니다. 그 값은 실제 진폭의 하한으로 보십시오.
- 기계를 의심하기 전에 센서·케이블·마운팅·접지를 먼저 확인하세요.
- 경고 상자 없이 회색 "DC 성분" 안내만 있다면 이상이 아닙니다. 평균이 크지만 일정한 센서(MEMS 가속도계 중력축·근접 변위센서)이고 판정은 그대로 진행됩니다. 판정을 막는 것은 평균이 흔들리는 **DC 드리프트**뿐입니다.

## 카드에 "판정 보류" 배지가 뜸

그 설비에 지금 등급을 매기지 않는다는 뜻입니다. 배지에 마우스를 올리면 사유와 직전 확정 등급이 나옵니다.

| 사유 | 뜻 | 할 일 |
| :--- | :--- | :--- |
| 판정 못 함 | RPM이나 베어링 형상이 없어 결함 패턴을 세울 수 없습니다. 저널(sleeve) 베어링도 여기 해당합니다 | 설비 정보에서 RPM·베어링 모델 입력(저널 베어링은 등급 대상이 아닙니다) |
| 결함 패턴 첫 측정 대기 | 앱을 연 직후처럼 아직 한 번도 재지 않았습니다 | 첫 측정이 끝나면 풀립니다(보통 몇 초, 태그가 많으면 더 걸림) |
| 결함 패턴 측정 실패 | 원본 파형을 읽지 못했거나 표본이 모자랐습니다. 직전 등급을 유지합니다 | 다음 회차에 다시 잽니다. 계속되면 그 태그의 데이터 수집 확인 |
| 판정 대기 | 첫 판정 회차를 기다리는 중 | 잠시 기다립니다 |
| 정지 | 설비가 서 있어 판정을 동결했습니다 | 조치 불필요 — 운전이 재개되면 판정도 재개 |
| 신호 두절 | 데이터가 들어오지 않습니다 | 수집 경로 확인 |
| 계측 이상 | 파형을 믿을 수 없습니다 | 센서·케이블·마운팅 확인 |

측정을 못 한 회차를 "패턴 없음 = 양호"로 읽으면 알람 중인 설비가 거짓 "정상 복귀"로 확정되므로, 앱은 판정을 보류하고 직전 상태를 유지합니다.

## 앱을 다시 열었더니 알람이 꺼져 있음

- 헤더의 알람 표시는 누르는 즉시 저장됩니다. 다시 열었을 때 꺼져 있다면, **설정 탭의 알람 스위치**로 켜고 저장하지 않았거나(**버리고 이동** 포함), 저장이 실패했을 수 있습니다 — 저장이 실패하면 오류가 뜨고 표시가 원래대로 돌아갑니다.
- 헤더의 알람 표시를 눌러 다시 켭니다. 따로 저장할 필요는 없습니다.

## 헤더 배지가 "앱 · 보기 전용"으로 표시됨

같은 계정으로 다른 탭이나 PC에 앱이 열려 있어 그쪽이 판정·알림을 맡는 중입니다. 정상입니다 — 알림이 겹쳐 가지 않게 한 곳만 판정합니다.

- 이 탭에서도 설정 저장·학습·리포트는 그대로 됩니다. 저장하면 담당 탭이 10초 안에 반영합니다.
- 담당 탭을 닫으면 1분 안에 이 탭이 이어받아 배지가 **앱**으로 바뀝니다.

## "다른 계정으로 로그인되었습니다" 안내가 뜸

같은 브라우저에서 Neo 콘솔 로그인이 다른 계정으로 바뀌었습니다. 이 화면은 옛 계정용이라 저장·판정·조회를 모두 멈춘 상태입니다.

- 새 계정으로 쓰려면 **새로고침**을 누릅니다.
- 옛 계정으로 계속 쓰려면 그 계정으로 다시 로그인합니다 — 안내가 사라지고 이어서 동작합니다.

## 상세분석에 회전수가 스펙트럼에서 잰 값과 다르다는 경고가 뜸

입력한 RPM과 스펙트럼의 회전 피크가 2% 넘게 차이 납니다. 흔한 원인은 동기속도(1800·3600)를 넣은 경우입니다.

- 결함 패턴은 입력값으로 대조하고 허용오차가 1%라, 그대로 두면 결함을 놓칠 수 있습니다.
- 명판의 정격 회전수를 확인해 고치거나, **실측값 N rpm으로 저장** 버튼을 누릅니다(즉시 저장됩니다). 실측값은 측정 시점 부하 기준입니다.
- **벨트 종동측 센서**라면 경고가 "종동축 회전수 … 풀리 환산(또는 입력값)이 … 다릅니다"로 나옵니다. 벨트 슬립이나 풀리 지름(바깥지름이 아니라 **피치 지름**인지)을 확인하십시오. 이때 실측값 저장 버튼은 모터 RPM이 아니라 **종동축 회전수** 칸에 저장합니다.
- 2극 전동기처럼 회전 피크가 계통주파수(60·50 Hz)와 겹치면 실측을 하지 않아 이 경고도 뜨지 않습니다 — 명판값을 정확히 넣으십시오.

## 시각이 몇 시간 어긋나 보임

화면 시각은 **설정 → 데이터 소스 → 표시 시간대**를 따릅니다. 기본값은 이 브라우저의 시간이라, 다른 지역에서 열면 그 지역 시간으로 보입니다.

- 모두가 같은 시각을 봐야 한다면 표시 시간대를 공장 현지 시간 등으로 고정해 저장합니다.
- 데이터 자체는 시간대와 무관하게 조회되므로, 표시만 어긋나 보일 뿐 빠진 데이터는 없습니다.
- 서버 알림 문구의 시각은 서버 감시를 등록할 때의 오프셋을 씁니다. 서머타임이 바뀐 뒤에는 앱을 한 번 열면 새 오프셋으로 다시 등록됩니다.

## 이벤트가 기록되지 않음

먼저 화면 맨 위에 **감시 상태 경고**가 떠 있는지 확인합니다. 감시 자체가 멈춘 경우가 가장 흔하며, 대부분 그 자리의 **다시 등록** 버튼으로 해결됩니다.

경고가 없다면 다음을 확인합니다.

- **알람이 켜져 있는지** 확인합니다. 판정은 알람이 켜진 동안에만 동작합니다.
- **앱 감시 모드라면 앱이 열려 있어야** 합니다. 앱을 닫아도 감시가 이어져야 하면 **서버 상시 감시**로 바꿉니다.
- **양호가 계속되는 동안은 기록하지 않습니다.** 주의 이상, 그리고 나쁨에서 돌아온 복귀만 기록됩니다.
- **여전히 나쁜 상태로 좋아지는 중간 단계**(심각 → 위험 등)는 따로 기록되지 않습니다. 대신 상태 개선 이벤트 1건으로 대표됩니다.
- **등급은 두 회차 연속이라야 확정됩니다.** 한 회차만 뜬 건은 `관찰`로만 남습니다.
- **RPM·베어링 모델이 비어 있으면 등급 이벤트가 아예 안 납니다.** 등급을 켜는 축이 결함주파수 격자라, 회전수나 기하가 없으면 격자를 만들 수 없습니다. 카드에 **판정 보류**(판정 못 함)로 나타납니다.
- **진동이 높기만 한 상태로는 이벤트가 안 납니다.** 베어링 결함 근거가 서야 등급이 오릅니다. 불평형·정렬불량·풀림은 상세분석에 "베어링 결함 징후 없음 · 진동 수준 … 구간 — 불평형·정렬불량·풀림 등 베어링 외 원인 점검 권장"으로 표시만 됩니다.
- **베이스라인·대역은 이벤트를 만들지 않습니다.** 이탈해도 근거표에만 표시됩니다.
- **등급 판정은 추출 주기마다(기본 10분) 한 번입니다.** 방금 나빠진 설비는 다음 회차까지 기다려야 이벤트가 납니다.

## "판정 대상이 0개입니다" 경고

타이머는 정상적으로 돌고 있지만, 감시 대상 태그를 하나도 판정하지 못한 상태입니다. 타이머 상태만 보면 정상으로 보이기 때문에 따로 알립니다.

- 감시 태그에 **새 데이터가 들어오지 않는지** 데이터 수집 쪽(센서·수집기·적재 파이프라인)을 확인하십시오.
- 서버 상시 감시라면 그 테이블에 대한 **`SELECT` 권한**과 **ROLLUP** 유무도 확인하십시오 — 위 [서버 감시를 켰는데 이벤트가 하나도 안 생김](#서버-감시를-켰는데-이벤트가-하나도-안-생김) 참고.

## 설비가 멈췄는데 "정상 복귀" 알림이 안 옴

정상 동작입니다. 판정값이 평소의 20% 아래로 떨어지면 앱은 이를 **설비 정지**로 보고 판정을 동결합니다(카드: 정지 배지).

진동 결함은 스스로 낫지 않으므로, 설명되지 않는 하락은 대개 설비가 멈췄거나 센서를 잃은 것입니다. 여기서 "정상 복귀"를 알리면 설비가 고쳐진 줄 오해하게 됩니다.

동결 중에는 직전 상태를 그대로 유지하므로, 재가동하면 이전에 나빴다는 사실이 그대로 남아 있습니다.

## 상태가 짧은 간격으로 좋아졌다 나빠졌다 함

최근 2시간에 임계 초과가 3회 이상 반복되면 카드에 **등급 반복 N회** 배지가 붙습니다.

- 결함 근거가 채택 기준선 근처에서 오가는 상태입니다. 부하가 변하면 결함 신호가 켜졌다 꺼질 수 있고, 결함 초기일 수도 있습니다.
- 등급은 결함 패턴이 정하므로 RMS 구간을 늘려도 이 반복은 줄지 않습니다.
- 배지를 누르면 마지막 악화 시점의 상세분석이 열립니다. 결함 근거와 포락선 스펙트럼으로 실제 결함인지 확인하십시오.

## 서버 상시 감시인데 특정 태그만 이벤트가 없음

그 테이블에 **ROLLUP이 없을 가능성**이 높습니다. 서버 감시는 롤업이 있는 테이블만 판정하고, 없는 테이블의 태그는 조용히 제외합니다.

해당 테이블에 롤업을 만들거나, 그 태그는 앱 감시로 확인합니다.

## 판정 기준 화면에 "같은 설비 / 다른 설비" 확인이 뜸

지웠던 태그가 같은 이름으로 다시 나타났고, 그 이름으로 학습된 기준이 남아 있다는 뜻입니다.

같은 설비를 잠시 뺐다가 되돌린 것이라면 **같은 설비 — 유지**를, 같은 이름으로 다른 설비를 연결한 것이라면 **다른 설비 — 초기화**를 선택합니다. 여러 개라면 위쪽 **모두 같은 설비 — 유지**로 한 번에 답할 수 있습니다.

확인 전까지 그 태그의 베이스라인·대역 근거는 멈춥니다. 옛 기준을 그대로 쓰면 새 설비가 조용할 땐 이상을 못 잡고, 시끄러울 땐 이탈 표시가 계속 뜨는데 화면에는 그냥 "학습됨"으로 보이기 때문입니다. 등급 판정(결함 패턴·ISO 존)은 그동안에도 계속 동작합니다.

## 대역 학습이 분모를 다 못 채움 (예: 4/9)

정상입니다. 각 태그 줄의 `4/9 계열 학습됨`에서 분모는 그 태그에서 **측정 가능한 계열 수**로, 태그마다 다릅니다. (머리줄의 `학습됨 X/Y`는 학습을 마친 태그 수 / 전체 태그 수입니다.)

- 상위 대역은 1 kHz 이상을 봅니다 — 센서 샘플레이트가 낮으면 그 대역은 **애초에 측정되지 않습니다**.
- 포락선 계열은 샘플레이트나 마운팅 상한이 낮으면 빠집니다.
- 포락선 결함주파수(BPFO·BPFI·BSF) 계열은 **베어링 품번이 있어야** 쌓입니다 — 설비 정보에서 품번을 넣으면 그때부터 쌓이기 시작합니다.
- 학습 상태 옆 툴팁에 계열별로 왜 빠졌는지가 표시됩니다.

학습되지 않은 계열은 근거 표시에서 빠지고, 나머지 계열로 정상 동작합니다.

## 대역 표본이 부족해 학습이 안 됨

대역값은 추출 타이머가 주기마다 하나씩 쌓으므로, 학습에 필요한 양이 모이려면 시간이 걸립니다.

- **과거 데이터 채우기**로 이미 DB에 있는 원시 데이터를 소급 계산하면 즉시 표본을 확보할 수 있습니다.
- **추출 주기를 줄이면** 이후 표본이 더 빨리 쌓입니다.
- 대역 학습 기간을 늘리면 그만큼 더 많은 표본이 학습 대상이 됩니다.

현재 표본 수와 학습 가능 여부는 대역 학습 기간 옆에 표시됩니다.

## 알람 설정을 바꿨는데 서버 감시가 옛 기준으로 판정함

서버 감시와 앱 판정 모두 **저장한 설정으로 동작합니다.** 설정을 바꾼 뒤 **저장**을 눌러야 새 기준이 반영되고, 저장 전에는 모니터링 화면도 이전 기준으로 보입니다. 다른 탭으로 나갈 때 **버리고 이동**을 고르면 편집한 값은 버려집니다.

## 알림이 오지 않음

1. **설정 → 알람 설정 → 알림**에서 채널이 켜져 있고 대상(웹훅 URL)이 입력됐는지 확인합니다.
2. **테스트 발송**을 눌러 발송 경로만 따로 검증합니다. 여기서 실패하면 URL이나 네트워크 문제입니다.
3. **심각도별 알림**에서 그 심각도의 알림 방식이 **즉시**인지 확인합니다. 기본값은 주의·위험·심각·감시 이상 **네 줄 모두 즉시**입니다 — 누가 '알림 안 함'으로 바꿔 두었는지 봅니다.
4. 알림 방식이 **알림 안 함**이면 이벤트는 기록되지만 알림은 나가지 않습니다.
5. 발송 채널은 웹훅 하나입니다. 이메일·문자가 필요하면 n8n 같은 자동화 도구의 수신 URL을 넣어 중계합니다 — [알람과 이벤트](./alarms.kr.md) 참고.
6. 그래도 안 오면 **이벤트 자체가 났는지** 먼저 봅니다. 이벤트가 없다면 발송 문제가 아니라 판정 문제이므로 위 [이벤트가 기록되지 않음](#이벤트가-기록되지-않음)으로 가십시오. `관찰` 이벤트는 원래 알림이 가지 않습니다.
7. **신호 두절·계측 이상만 안 온다면** 심각도 표의 **감시 이상** 행을 확인합니다. 등급 세 줄과 별개 스위치입니다.
8. 한 번에 여러 대가 두절됐는데 알림이 **한 건만** 왔다면 정상입니다 — 같은 회차에 같은 유형·등급이 5건 이상이면 묶어서 보냅니다. 개별 이력은 이벤트 목록에 다 있습니다.
9. 화면에 "서버 감시가 알림 설정을 읽지 못해 이벤트 N건을 알리지 못했습니다"가 떠 있으면 **알림 설정 열기** → 알림 설정을 다시 저장합니다.

## 이벤트 목록에 오래된 이벤트가 안 보임

- 목록은 필터에 맞는 이벤트 중 최근 **200건**까지만 보여 줍니다. 유형·태그 필터로 좁히면 더 오래된 것까지 보입니다.
- 데이터 소스에서 선택을 해제한 테이블의 이벤트는 목록에서 빠집니다(지워지지는 않음).
- 전체 이력은 **저장**(내보내기)에서 기간을 지정해 CSV·JSON으로 확인합니다 — 해제한 테이블 이벤트도 포함됩니다.

## 이벤트 파일을 내려받을 때 "안전하지 않은 파일" 경고

브라우저가 CSV·JSON 다운로드에 대해 표시하는 일반적인 경고입니다. 파일 자체의 문제가 아니며, 다운로드를 유지하면 정상적으로 저장됩니다.

## 진단이 부정확하게 느껴짐

- **설비 정보**에 RPM·베어링 모델을 등록했는지 확인합니다. 없으면 등급 자체가 나오지 않습니다.
- **단위**가 센서와 맞는지 확인합니다. 비워 두면 속도(mm/s)로 간주하므로, 가속도·변위 센서는 값이 잘못 환산되어 등급 높이가 틀어집니다.
- **마운팅 방식**을 지정했는지 확인합니다. 자석 마운트는 보통 2\~5 kHz에서 공진하는데, 이 대역은 결함 패턴을 재는 1\~5 kHz와 겹칩니다. 마운팅을 지정하면 상한 위 대역이 대역별 충격성·대역 에너지 근거에서 따로 표시되지만, 결함 패턴 자체는 고정 대역에서 계산하므로 **자석 마운트 설비에서 결함 패턴이 잡히면 센서 부착 상태부터 확인**하십시오.
- 존 경계가 설비에 맞는지 **판정 기준**에서 확인합니다. 등급 높이는 Class별 속도(mm/s) 경계로 정해집니다. 가속도(`g`)·변위(`μm`) 행은 그 단위 센서의 추이 표시용 참고값입니다.
- 정상 상태를 학습해 두면 "평소 대비" 근거가 근거표에 함께 표시됩니다(등급은 바꾸지 않습니다).
- 진단은 단일 채널·단일 방향 측정에 위상 정보 없이 계산됩니다. 결함 메커니즘은 가설이며, 확정에는 다축·위상 측정이 필요합니다.

리포트의 결함 후보에 "이 측정으론 볼 수 없음"으로 표시된 항목이 있다면, 그 사유에 어떤 정보가 없어서 판정하지 못했는지 적혀 있습니다. 해당 항목을 **설비 정보**에 채우면 그 후보가 판정 대상으로 들어옵니다.

## 베이스라인 학습이 실패함

메시지에 따라 원인이 다릅니다.

- **"정상상태 표본 N개 (최소 30개 필요)"** — 학습 구간에서 정지·기동 구간을 제외하고 남은 표본이 부족합니다. 표본은 RMS 구간 단위로 묶어 세므로, 학습 기간을 늘리거나 알람 설정의 RMS 구간을 줄이거나, 데이터가 더 쌓인 뒤 다시 시도합니다.
- **"학습 구간이 정지↔운전 두 수준으로 갈라져 있습니다"** — 창의 대부분이 정지 구간입니다. 그대로 학습하면 정지 상태가 정상 기준이 되어 기계를 돌리기만 해도 이탈로 표시되므로, 학습을 거부합니다. 연속 운전이 대부분인 기간을 골라 다시 학습합니다.

학습에 성공해도 안내에 `제외 12개(정지 8·과도 4)`처럼 제외 내역이 표시될 수 있습니다. 이는 정상 동작이며, 제외 후 남은 표본으로 기준을 만들었다는 뜻입니다.

## 두 리포트의 숫자가 다름

리포트에 남는 **판정 지문**을 비교합니다.

- 지문이 **같다면** 판정 엔진은 동일합니다. 재현성 정보의 임계값(Thresholds) 칸도 같다면 **데이터가 달라진** 것입니다.
- 지문이 **다르다면** 그 사이 패키지(판정 엔진)가 바뀐 것입니다. 사용자가 바꾼 임계값은 지문이 아니라 Thresholds 칸에서 보입니다.

## LLM 소견이 생성되지 않음

- **설정 → LLM 연동**에 프로바이더가 하나 이상 설정됐는지 확인합니다. Claude · OpenAI · Gemini는 API 키가, Ollama는 URL이 필요합니다.
- **연결 테스트**로 키 또는 URL이 올바른지 확인합니다.
- 상세분석·리포트의 프로바이더 드롭다운에서 사용할 프로바이더가 선택됐는지 확인합니다.
- 모델명을 직접 입력했다면 그 프로바이더에 실제로 있는 모델인지 확인합니다. 비워 두면 기본 모델을 씁니다.
- LLM 소견은 선택 기능입니다. 연동하지 않아도 규칙 기반 진단과 리포트는 정상 동작합니다.
