# 이상 판정 원리

**한국어** | [English](./detection.en.md)

이 문서는 앱이 **무엇을 재고, 어떤 기준으로 등급을 매기고, 언제 이벤트를 남기는지**를 설명합니다.

설정 화면의 각 항목과 알림 받는 법은 [알람과 이벤트](./alarms.kr.md)에 있습니다. 이 문서는 그 설정이 실제로 무엇을 바꾸는지 이해하려는 분을 위한 것입니다.

## 한 줄 요약

> **결함 패턴이 등급을 켜고, ISO 존이 그 높이를 정합니다.**
> 베어링 결함주파수 자리에 근거가 서지 않으면 진동이 아무리 높아도 등급은 양호입니다 —
> 대신 "진폭은 높다"는 사실을 화면이 따로 적습니다.

**상세분석과 상시감시가 같은 규칙을 씁니다.** 창 길이와 주기만 다릅니다.

## 전체 흐름

감시는 **두 개의 주기**로 돕니다. 하나는 빠르고 싸고, 하나는 느리고 비쌉니다.

```
                     원시 진동 데이터
                            │
          ┌─────────────────┴─────────────────┐
          │                                   │
    10초마다 (싸다)                     10분마다 (비싸다)
    구간 RMS 하나                    FFT → 포락선 → 결함주파수 격자
          │                                   │
          ├── 운전 / 정지                     ├── 결함 패턴 (게이트)
          ├── 신호 두절                       ├── ISO 존   (높이) ← 같은 파형
          ├── 계측 게이트                     └── 대역 에너지 (근거)
          └── 베이스라인 이탈 (근거)                    │
                    │                                  ▼
                    │                          등급 = 패턴이 켤 때만 오른다
                    │                                  │
                    └──── 판정 동결 ────────────────────┤
                          (정지·두절·계측이상)          ▼
                                                진입 · 복귀 확인 시간
                                                       │
                                                       ▼
                                                이벤트 기록 → 알림
```

**이벤트는 오른쪽 축에서만 나옵니다.** 왼쪽 축은 판정을 **멈추는** 일(정지·두절·계측이상)과 **근거를 채우는** 일만 합니다.

### 왜 두 주기인가

| | 10초 축 | 10분 축 |
| :--- | :--- | :--- |
| 계산 | 롤업 RMS 1회 | 원시 파형 → FFT → 포락선 |
| 비용 | 태그당 0.3 ms | 태그당 311 ms (서버 기준) |
| 답하는 것 | "지금 돌고 있나 · 신호가 오나" | "무엇이 상했나" |

결함 패턴은 매 10초 돌리기엔 너무 비쌉니다. 91개 태그를 10분마다 도는 데 28초가 걸리는데(주기의 5%), 10초마다면 계산이 주기를 넘어섭니다.

그리고 **그럴 이유도 없습니다.** 베어링 결함은 시간·일 단위로 자랍니다. 초 단위로 터지는 사고는 10분 주기든 10초 주기든 어차피 사후입니다 — 그건 감시가 아니라 보호계전기의 일입니다.

### 왜 이벤트를 한쪽 축에서만 내는가

이전에는 베이스라인·대역도 각자 이벤트를 냈습니다. 지금은 안 냅니다. 두 가지 이유입니다.

**① 시간축이 다릅니다.** 베이스라인 판정값은 10초 축의 구간 RMS인데 등급은 10분 축의 결함 패턴이 정합니다. 둘을 같은 이벤트 흐름에 섞으면 **이벤트 시각이 무엇을 가리키는지 흐려집니다** — "10분마다 확인한 결과"라는 약속이 깨지고, 재알림 간격에도 두 주기가 뒤섞입니다.

**② 축이 늘면 오경보가 곱해집니다.** 대역은 8개 계열을 각각 한계와 대보고 하나라도 넘으면 켜는 구조라 그 자체가 작은 다중비교입니다(단독 오탐 13%).

두 축의 값은 **사라지지 않고 근거로 남습니다.** 카드와 근거표에 그대로 표시되고, "어느 대역이 움직였나"로 원인을 좁히는 데 쓰입니다. 알림만 안 갑니다.

> **대가는 분명합니다.** 베이스라인은 단독 오탐 0% · 검출 28%인 가장 깨끗한 축인데, 그게 알림에서 빠졌습니다. 베어링 결함이 아닌 원인(불평형·정렬불량·풀림)으로 진폭만 오르는 경우는 이제 **사람이 화면에서 봐야** 합니다. 알림으로 받으려면 아래 [한계와 대안](#한계와-대안)을 보십시오.

## ① 판정값 — 구간 RMS

10초 축의 판정값은 **한 구간 전체의 RMS 값 하나**입니다. 가장 최근에 들어온 한 점이 아닙니다.

진동은 순간마다 출렁이므로 한 점으로 판정하면 값이 계속 흔들립니다. 대신 "직전 10초 구간"처럼 일정 길이의 데이터를 하나의 실효값으로 합쳐서 봅니다.

여기서 **RMS 구간**과 **판정 주기**는 다른 설정입니다.

| 설정 | 뜻 | 기본값 |
| :--- | :--- | :--- |
| RMS 구간 | 얼마나 긴 데이터를 하나로 볼지 | 직전 10초 |
| 판정 주기 | 얼마나 자주 판정할지 | 10초마다 |
| 패턴·대역 추출 주기 | 결함 패턴을 얼마나 자주 계산할지 | **10분마다** |

앞의 둘은 조절할 수 있고, 지금 값이 하한입니다 — 더 짧게는 못 잡습니다. 세 번째도 조절할 수 있지만 **길게만** 권합니다(10분 ~ 1시간). 짧게 하면 서버 계산이 주기를 못 따라갑니다.

구간이 **길수록** 짧은 출렁임이 하나의 상태로 합쳐집니다 — 반응이 느려지는 대신 안정됩니다. 구간이 판정 주기보다 짧으면 그 사이 데이터가 판정에 들어가지 않으므로 화면이 경고합니다.

부하가 주기적으로 변하는 설비라면 그 변동 주기보다 긴 구간을 잡는 것이 좋습니다. 짧으면 부하 변화 자체가 이상으로 잡힙니다.

## ② 결함 패턴 — 등급을 켜는 축

### 무엇을 보는가

베어링은 상한 자리에 따라 **구르는 주기가 정해져 있습니다.** 회전수와 베어링 기하(볼 개수·볼 지름·피치 지름·접촉각)를 알면 그 주기를 계산할 수 있습니다.

| 이름 | 무엇 | 대략 |
| :--- | :--- | :--- |
| **BPFO** | 외륜 결함 | 회전주파수 × 볼수 × 0.4 |
| **BPFI** | 내륜 결함 | 회전주파수 × 볼수 × 0.6 |
| **BSF** | 구름체 결함 | 회전주파수 × 2~3 |
| **FTF** | 케이지 | 회전주파수 × 0.4 |

결함이 있으면 그 주파수와 배음(2×·3×·4×) 자리에 에너지가 섭니다. **그 격자와 실제 스펙트럼을 대조**하는 것이 이 축입니다.

### 어떻게 보는가 — 포락선

결함 충격은 **저주파 진동으로 직접 나타나지 않습니다.** 충격이 베어링·하우징의 고주파 공진을 때리고, 그 공진이 결함 주기로 **얻어맞은 만큼 커졌다 작아집니다**. 신호는 고주파인데 정보는 그 크기 변화(포락선)에 있습니다.

```
   원시 파형 → 1~5 kHz 대역만 남김 → 해석 신호 |x + i·H{x}| → 저주파 스펙트럼
                     (대역통과)          (힐베르트 변환)        (여기에 격자를 댄다)
```

**대역은 1~5 kHz로 고정**입니다. 첨도가 가장 높은 대역을 자동으로 고르는 방식(커토그램)을 써 봤는데 검출이 54% → 6~11%로 무너졌습니다 — 첨도 최대화가 안티에일리어싱 잡음과 인버터 스위칭 대역에 붙잡히기 때문입니다. 고정 대역이 훨씬 낫습니다.

> **대형 설비 주의** — 1~5 kHz는 검증 풀(소형~중형 시험대)의 공진 대역입니다. 실제로 이 대역에 자주 걸리는 것은 **가속도계 마운팅 공진**(부착 방식에 따라 수 kHz)이고, 베어링 링 자체의 굴곡 모드는 설비가 커질수록 **낮아집니다**. 큰 저속 설비에서는 대역이 안 맞을 수 있는데, 검증 풀에 그런 설비가 없어 **어느 쪽으로 틀리는지 아직 모릅니다.**

### 언제 켜지는가

격자 자리의 에너지가 주변 잡음층(전역 중앙값) 대비 몇 배인지로 점수를 냅니다. 그 점수가 임계를 넘으면 게이트가 켜집니다.

| | 창 길이 | 채택 임계 |
| :--- | :--- | :--- |
| **상세분석** | 100회전 | 4.0 |
| **상시감시** | **25회전** | **3.0** |

감시가 짧은 창을 쓰는 이유는 서버 계산 비용입니다. 서버 타이머(goja)가 브라우저보다 100~400배 느려서, 100회전이면 91태그 한 회차가 756초로 10분 주기를 넘습니다(126%). 25회전이면 167초(28%)입니다.

**대가는 검출 66% → 59%로 7%p입니다.** 창이 짧으면 점수 분포가 통째로 내려가므로 임계도 같이 낮춥니다(같은 오탐률 기준: 100회전 3.88 · 25회전 3.03).

감시는 **트리거**이고 확정은 상세분석이 100회전으로 합니다 — 놓치지만 않으면 짧아도 됩니다.

### 판정할 수 없는 경우

회전수나 베어링 기하를 모르면 격자를 만들 수 없습니다. 이때 등급은 **오르지 않습니다** — 그런데 그건 "정상"이 아니라 "판정 못 함"입니다.

화면이 이것을 커버리지로 드러냅니다. 회전수·품번이 비어 있으면 설정 화면이 안내합니다.

> **회전수를 추정하지 않습니다.** 예전에는 값이 없으면 1800 rpm으로 가정했는데, 2극(3600)·6극(1200) 설비에서 격자가 통째로 어긋나면서도 화면은 평소처럼 등급을 냈습니다 — 조용히 틀리는 최악의 형태라 없앴습니다.

## ③ ISO 존 — 높이를 정하는 축

ISO 10816 규격이 정한 진동 심각도 존(A 양호 → D 심각)입니다. 설비 종류(머신 클래스)와 센서 단위에 따라 경계값이 달라집니다.

| 단위 | 양호↔주의 | 주의↔위험 | 위험↔심각 |
| :--- | ---: | ---: | ---: |
| mm/s · Class I (소형 ≤15kW) | 0.71 | 1.8 | 4.5 |
| mm/s · Class II (중형 15–75kW) | 1.12 | 2.8 | 7.1 |
| mm/s · Class III (대형·강성 기초) | 1.8 | 4.5 | 11.2 |
| mm/s · Class IV (대형·연성 기초) | 2.8 | 7.1 | 18.0 |
| g (가속도) | 0.5 | 1.0 | 2.0 |
| μm (변위) | 12 | 25 | 50 |

속도(mm/s) 값은 ISO 10816 기준값입니다. 가속도·변위는 규격이 정의한 물리량이 아니므로 **일반 참고값**이며, 설비에 맞게 조정해 쓰는 것을 전제로 합니다. 값은 판정 기준 화면에서 직접 바꿀 수 있습니다.

> **대역제한** — ISO 존 판정은 10–1000 Hz 구간만 남겨서 잽니다. 규격의 존 경계 자체가 그 대역에서 측정한 값으로 정해진 숫자이기 때문입니다. 고주파 성분이 많은 센서에서는 전대역 값과 ISO 값이 상당히 다를 수 있는데, 이 경우 존 판정에 쓰는 쪽이 규격에 맞는 값입니다.

### ISO를 독립 축으로 두지 않는 이유

검증 풀 383 케이스에서 축별로 갈라 재면 이렇습니다.

| 축 | 단독 오탐 | 단독 검출 |
| :--- | ---: | ---: |
| **결함 패턴** | **3%** | 65% |
| 베이스라인 | 0% | 28% |
| 대역 | 13% | 41% |
| **ISO 존** | **69%** | 37% |
| 네 축을 OR로 묶으면 | **69%** | 74% |

**오탐은 사실상 ISO 축 하나가 만듭니다.** 그리고 최댓값 방식에서는 축이 늘면 등급이 올라가기만 하므로, ISO를 넣는 순간 그 69%가 그대로 화면 등급이 됩니다.

게이트로 바꾸면 **69% → 3%**입니다. 검출은 74% → 66%로 8%p 줍니다.

덤이 하나 있습니다 — **머신 클래스를 잘못 잡아도 오탐이 안 흔들립니다**(Class I·II·III 전부 3~4%). ISO가 경보를 켜지 않으니까요. 예전에는 클래스 하나 잘못 고르면 오탐이 49%~75%로 요동쳤습니다.

> **이 69%는 실기 설비의 오탐률이 아닙니다.** 검증 풀은 전부 가속수명시험대입니다 — 건전한 시험대가 고하중으로 돌아 진동이 원래 높고, 결함 초기 베어링은 광대역 속도가 낮습니다. 그래서 이 풀에서는 **정상의 ISO 중앙값(1.33 mm/s)이 결함의 중앙값(1.21)보다 높습니다.** 클래스 문제가 아니라 규격 적용 대상이 아닌 것입니다. 자세한 것은 [이 도구가 하는 일](./scope.kr.md)에 있습니다.

### 높이를 재는 파형

감시에서 ISO 값은 **결함 패턴을 잰 바로 그 파형**에서 잽니다. 10초 축의 최신 ISO를 쓰면 등급이 10초마다 움직여, 10분 주기인 패턴과 시간축이 어긋납니다.

패턴 계산 때 ISO를 못 쟀으면 10초 축 값으로 물러섭니다 — 등급을 0으로 떨어뜨리지는 않습니다.

## ④ 근거 축 — 등급을 안 만드는 두 가지

### 베이스라인 — 평소 대비

설비가 정상일 때의 상태를 학습해 두고, 거기서 얼마나 벗어났는지 봅니다.

```
한계 = 평소 수준(μ) + k × 평소 변동폭(σ)
```

절대값이 아직 양호 존이어도 **평소보다 뚜렷하게 올라갔으면** 잡아냅니다. `k`는 민감도입니다 — 작을수록 민감하고, 크면 확실할 때만 반응합니다.

평소 변동이 거의 없는 아주 안정된 설비에서는 한계가 평소 수준에 지나치게 붙을 수 있어, **최소한 평소의 +20%는 올라야** 이탈로 봅니다.

이탈해도 **등급은 오르지 않고 이벤트도 나지 않습니다.** 카드와 근거표에 "평소 대비 급증"으로 표시됩니다.

### 대역 에너지 — 주파수 대역별

전체 RMS로는 안 보이는 변화를 잡습니다. 베어링 결함이 자라도 전체 진동은 거의 안 움직이는데, 그 결함이 나타나는 주파수 대역만 보면 몇 배로 뜁니다.

대역은 회전주파수(1×)를 기준으로 다섯 구간으로 나눕니다. 이 중 초고주파는 옥타브 단위 4개 대역(vh1~vh4)으로 세분되어, 실제로 저장·판정되는 대역은 8개입니다.

| 대역 | 범위 | 주로 나타나는 것 |
| :--- | :--- | :--- |
| 서브동기 | 2 Hz ~ 0.5× | 오일 훨 · 풀림 · 벨트 |
| 1× 대역 | 0.5× ~ 1.5× | 불평형 · 정렬 불량 |
| 결함 대역 | 1.5× ~ 10× (최대 1 kHz) | 베어링 결함주파수 · 기어 |
| 고주파 | ~ 1 kHz | 초기 베어링 결함 |
| 초고주파 | 1 kHz 이상 | 충격성 · 마찰 |

대역마다 베이스라인과 같은 방식으로 정상 기준을 학습하고, **한계 대비 몇 배인지**를 근거표에 적습니다.

> 샘플레이트가 낮은 센서에서는 상위 대역이 측정 범위를 벗어나 학습되지 않고, 베어링 품번이 없으면 포락선 결함주파수 계열이 쌓이지 않습니다. 학습되지 않은 계열은 제외되며, 화면에 "4/9 계열 학습됨"처럼 표시됩니다.

### 왜 학습 축을 게이트에 안 넣는가

상세분석에서 특히 중요합니다. 학습 축을 게이트에 넣으면 **같은 태그가 학습 여부에 따라 다른 등급**을 냅니다 — 실측으로 학습 전 오탐 3%가 학습 후 15%가 됐습니다.

일회성 분석은 "지금 이 신호가 무엇처럼 보이나"에 답하는 도구이므로 학습 상태에 매이면 안 됩니다.

### Crest는 등급을 올리지 않습니다

Crest(첨두/실효 비)도 등급에 들어가지 않습니다. 진폭이 낮은 구간에서는 분모가 작아 스파이크 하나에도 크게 튀기 때문입니다.

대신 **판정 문구**에 반영됩니다. 진폭은 정상인데 Crest가 기준을 넘으면 판정이 "정상 운전"이라고 단정하지 않습니다.

낮은 RMS에 높은 Crest는 **국부 결함 초기의 시그니처이면서 동시에 계측 스파이크(ESD·케이블·접촉)의 시그니처**이기도 합니다. 이 값 하나로는 갈리지 않으므로 등급을 움직이지 않고 사실만 적습니다. 둘을 가르는 것은 충격이 **반복되는지**입니다 — 포락선에서 결함주파수에 정렬되면 결함, 흩어져 있으면 계측 쪽입니다. 권고 문구가 이 확인을 지시합니다.

계측 게이트(클리핑·DC 드리프트 등)가 걸린 상태에서는 게이트 문구가 우선합니다. 이미 계측 확인을 지시하고 있기 때문입니다.

## ⑤ 등급 결정

```
등급 = 결함 패턴이 켜졌는가?  →  아니오 : 양호
                              →  예     : max(주의, ISO 존 등급)
```

패턴이 켜졌는데 ISO가 양호면 **주의**입니다. 원인을 지목해 놓고 등급이 양호로 남으면 화면이 스스로 어긋나기 때문입니다.

등급을 안 올린 축도 **사실은 남깁니다.** 화면이 "양호"만 말하면 거짓이 됩니다.

| 상황 | 등급 | 화면 문구 |
| :--- | :--- | :--- |
| 패턴 ○ · ISO 위험 | 위험 | 외륜 결함 근거 · 진폭 위험 존 |
| 패턴 ○ · ISO 양호 | **주의** | 외륜 결함 근거 · 진폭은 아직 낮음 |
| 패턴 ✕ · ISO 위험 | **양호** | **진폭이 높으나 베어링 결함 근거 없음** — 불평형·정렬·풀림 확인 |
| 패턴 ✕ · 베이스라인 이탈 | 양호 | 평소 대비 급증 |
| 패턴 ✕ · 대역 이탈 | 양호 | 고주파 대역 이탈 |
| 회전수·기하 미입력 | 양호 | **판정 못 함** (커버리지에 표시) |

세 번째 줄이 이 설계의 핵심 트레이드오프입니다. **베어링이 아닌 고장은 등급이 안 오릅니다** — 이 도구는 베어링 진단 도구이고, 불평형·정렬불량은 위상(타코)·축방향 채널 없이는 원리적으로 판별할 수 없기 때문입니다. 숨기지는 않고 문구로 밝힙니다.

## ⑥ 이벤트

판정 결과 중 **상태가 바뀐 순간만** 이벤트로 남습니다. 같은 상태가 유지되는 동안은 기록하지 않습니다.

| 유형 | 언제 생기는가 | 어느 축 |
| :--- | :--- | :--- |
| **임계 초과** | 등급이 나빠졌을 때 | 10분 (패턴) |
| **상태 지속** | 나쁜 상태가 계속될 때, 재알림 주기마다 | 10분 (패턴) |
| **상태 개선** | 알람 수준에서는 벗어났지만 아직 양호는 아닐 때 | 10분 (패턴) |
| **정상 복귀** | 완전히 양호로 돌아왔을 때 | 10분 (패턴) |
| **계측 이상** | 클리핑 · DC 드리프트 · 플랫라인 등 | 10초 |
| **신호 두절** | 데이터가 들어오지 않을 때 | 10초 |

아래 두 개는 진동 등급이 아니라 **"감시가 제대로 되고 있나"**를 알립니다. 성격이 달라 남겨 뒀습니다 — 화면이 마지막 값을 들고 계속 정상으로 보이는 것이 가장 나쁜 실패 모드이기 때문입니다.

**베이스라인·대역은 이벤트를 내지 않습니다.** 상태는 계속 추적되어 근거표에 표시됩니다.

### 개선과 복귀의 차이

한 번의 이상 상황에서 좋아지는 과정은 두 단계로 나뉩니다.

| | 뜻 | 대응 |
| :--- | :--- | :--- |
| 상태 개선 | 급한 불은 껐다 | 우선순위 하향, 긴급 대응 해제 |
| 정상 복귀 | 완전히 정상이다 | 작업지시 종료 |

둘을 나누는 이유는 실무 대응이 다르기 때문입니다. 또 존 경계 근처에서 운전하는 설비는 완전한 양호에 좀처럼 도달하지 않는데, 그런 설비도 "개선됐다"는 신호는 받을 수 있어야 합니다.

각 단계는 한 번의 이상 상황마다 **한 건씩만** 기록됩니다. 심각 → 위험 → 주의 → 양호로 단계적으로 좋아져도 개선 1건, 복귀 1건입니다.

### 기록 규칙

- **양호가 계속되는 동안은 아무것도 기록하지 않습니다.** 나쁨에서 돌아온 정상 복귀만 1건 남습니다.
- **여전히 나쁜 상태로 좋아지는 중간 단계**(심각 → 위험 등)는 따로 기록하지 않습니다. 상태 개선으로 대표됩니다.
- **처음 보는 태그가 이미 나쁘면 즉시 기록합니다.** 확인 시간을 기다리지 않습니다.
- **이벤트는 자동으로 삭제되지 않습니다.** 이력도 데이터이므로 보존됩니다.

### 이벤트 값 읽기

이벤트 목록의 "지표값 vs 기준"은 유형에 따라 의미가 다릅니다.

| 유형 | 지표값 | 기준 |
| :--- | :--- | :--- |
| 임계 초과 · 상태 지속 · 개선 · 복귀 | 패턴을 잰 파형의 ISO 값 | 넘어선 존 경계 |
| 계측 이상 · 신호 두절 | — | — |

## ⑦ 알람이 바로 안 나는 경우

등급이 바뀌자마자 알람이 나가지는 않습니다. 방향에 따라 확인 시간을 요구합니다.

| | 설정 | 목적 |
| :--- | :--- | :--- |
| 나빠질 때 | 진입 확인 시간 | 일시적 변동 무시 |
| 좋아질 때 | 복귀 유지 시간 | 경계 오르내림(플래핑) 방지 |

> **판정이 10분 주기가 되면서 이 설정의 뜻이 달라졌습니다.** 진입 확인 시간이 10분보다 짧으면 사실상 "다음 회차에 바로 확정"입니다 — 그 사이에 판정이 한 번도 안 일어나기 때문입니다. 실제로 지연을 주려면 **10분의 배수**로 잡아야 합니다(20분 = 2회차 연속 확인).
>
> 복귀 유지 시간은 여전히 유효합니다. 등급이 경계를 오르내릴 때 복귀 이벤트가 반복되는 것을 막습니다.

## 정지와 신호 두절

값이 갑자기 낮아졌다고 해서 좋아진 것은 아닙니다.

- **설비 정지** — 판정값이 평소의 20% 아래로 떨어지면 정지로 보고 판정을 **동결**합니다. 진동 결함은 스스로 낫지 않으므로, 설명되지 않는 하락은 대개 설비가 멈췄거나 센서를 잃은 것입니다. 이때 "정상 복귀" 알림이 나가면 설비가 고쳐진 줄 오해하게 됩니다. 동결 중에는 직전 상태를 유지하므로, 재가동하면 이전에 나빴다는 사실이 그대로 남아 있습니다.
- **신호 두절** — 새 데이터가 판정 주기의 여러 배가 지나도록 들어오지 않으면 두절로 보고 이벤트를 남깁니다.

## 표본이 모자라는 태그

결함 패턴은 **표본 수**로 창을 잡습니다 — 시간이 아닙니다.

적재 시 타임스탬프가 퍼진 태그(재생 데이터·간헐 수집)는 벽시계 밀도가 샘플레이트와 다릅니다. 예를 들어 20,480 표본이 1분에 퍼져 있으면 초당 341개인데, 25회전이 0.75초인 설비에서 시간으로만 조회하면 **256 표본**밖에 안 들어옵니다.

이 경우 창을 넓혀 다시 읽고(최대 2회), 그래도 4096 표본이 안 되면 그 회차의 패턴 판정을 건너뜁니다. 넘치면 최신 쪽만 씁니다 — 창이 길어지면 운전 상태가 섞이기 때문입니다.

> 이 처리가 없으면 밀도가 낮은 태그는 **에러 없이 판정이 통째로 건너뛰어집니다.** 화면은 평소처럼 양호로 보입니다.

## 베이스라인 학습

### 무엇을 배우는가

정상 운전 구간의 **평소 수준(μ)** 과 **평소 변동폭(σ)** 입니다. 학습 기간(1시간 / 6시간 / 24시간)을 고르고 학습을 실행하면 그 구간의 데이터로 기준이 만들어집니다.

추정에는 스파이크에 흔들리지 않는 중앙값 방식을 씁니다. 정상 운전 중에도 순간 충격은 섞이는데, 단순 평균은 그것까지 흡수해 기준을 부풀립니다.

### 자동으로 걸러지는 구간

학습 구간에 정지나 기동이 섞여 있으면 기준이 낮게 잡힙니다. 그래서 학습 전에 자동으로 제외합니다.

- **정지·아이들 구간** — 운전 수준의 20% 미만
- **기동·정지 과도 구간** — 값이 급격히 변하는 구간

학습에 성공해도 `제외 12 (정지 8 · 과도 4)`처럼 제외 내역이 표시됩니다. 남은 데이터로 학습했다는 뜻이며 정상입니다.

### 학습이 거부되는 경우

| 상황 | 안내 | 대응 |
| :--- | :--- | :--- |
| 표본 부족 | 정상 구간 표본이 최소 개수에 못 미침 | 학습 기간을 늘리거나 데이터가 더 쌓인 뒤 재시도 |
| 정지↔운전 두 수준 | 학습 구간 대부분이 정지 | 연속 운전이 대부분인 기간으로 다시 학습 |

두 번째는 특히 중요합니다. 정지 수준을 정상 기준으로 잡으면 **설비를 돌리기만 해도 이탈로 표시됩니다.**

### 자동 재학습을 하지 않는 이유

학습한 지 오래되면 화면이 알려 주지만, 자동으로 갱신하지는 않습니다. 결함이 자라는 중에 재학습하면 **그 결함을 정상으로 흡수**해 버리기 때문입니다.

정비를 했거나 운전 조건이 바뀌었다면 그때 사람이 다시 학습시키는 것이 맞습니다.

### 태그를 지웠다 다시 만든 경우

학습값은 `테이블:태그` 이름을 키로 저장됩니다. 태그를 지워도 학습값은 남아 있어서, 나중에 **같은 이름으로 다른 설비를 붙이면 옛 기준이 그대로 적용**됩니다.

데이터만으로는 같은 설비인지 알 수 없으므로 앱이 확인을 요청합니다. 판정 기준 화면에 **같은 설비 — 유지** / **다른 설비 — 초기화** 선택이 나타나며, 확인 전까지 그 태그의 베이스라인·대역 표시는 멈춥니다. 결함 패턴과 ISO 존은 학습이 필요 없으므로 그동안에도 계속 동작합니다.

## 대역 에너지 추출

대역별 값은 원시 데이터를 주파수 분석해야 얻어지므로, 결함 패턴과 **같은 타이머·같은 주기**로 계산해 쌓습니다. 둘 다 원시 파형을 읽기 때문입니다.

- 계산은 서버에서 이뤄집니다. 앱이 닫혀 있어도 추세가 이어집니다.
- 정지된 설비의 옛 구간을 긁지 않도록, 항상 그 태그의 최신 데이터 시각을 기준으로 계산합니다.

### 과거 데이터 채우기

학습에 필요한 표본이 쌓이려면 시간이 걸립니다. 이미 DB에 원시 데이터가 있다면 **과거 채우기**로 소급해 계산할 수 있습니다.

계산 방식이 타이머와 동일하므로 채운 값과 이후 쌓이는 값을 이어서 학습해도 됩니다. 진행 상황과 예상 소요 시간이 표시되고, 중간에 멈춰도 채운 만큼은 그대로 쓰입니다.

## 상세분석과 감시의 차이

같은 규칙인데 **창·주기·앵커**가 다릅니다.

| | 상세분석 | 상시감시 |
| :--- | :--- | :--- |
| 등급 공식 | 패턴이 켜고 ISO가 높이 | **동일** |
| 패턴 창 | 100회전 | 25회전 |
| 채택 임계 | 4.0 | 3.0 |
| 언제 | 사람이 기간을 고를 때 | 10분마다 자동 |
| 어느 시점 | 기간을 8등분해 **가장 나쁜 곳** | 지금 |
| 실측 오탐 / 검출 | 3% / 66% | 4% / 59% |
| 학습 필요 | 없음 | 없음 (근거 표시에만) |

### 왜 상세분석은 8곳을 재는가

기간의 **끝**만 재면 그 순간의 상태가 기간 전체를 대표하게 됩니다. 실제로 외륜이 파손된 베어링에서, 선택한 창의 끝이 이미 정지 구간이라 등급이 양호로 나온 사례가 있었습니다.

그래서 기간을 8등분해 각 지점에서 판정하고 **가장 나쁜 것**을 씁니다. 데이터가 없는 지점은 앞으로 당겨 붙이고 중복은 제거합니다. 어느 지점이 선택됐는지는 화면에 표시됩니다.

"1시간을 고르면 그 1시간 중 가장 상태가 나빴던 순간"이 등급이 됩니다 — 전 기간의 최악이 아닙니다.

## 한계와 대안

| 원하는 것 | 지금 | 대안 |
| :--- | :--- | :--- |
| 진폭 상승을 알림으로 받기 | 근거 표시만 | 카드·근거표를 주기적으로 확인 |
| 베어링 아닌 고장(불평형·정렬) 판정 | 안 함 | 위상·축방향 채널이 필요 — 원리적 한계 |
| 초 단위 대응 | 안 함 | 보호계전기·인터록의 영역 |
| 내륜 조기 검출 | **못 잡음** | [고장 유형](./faults.kr.md) 참고 |

## 판정 지문

생성된 리포트에는 **판정 지문**이 함께 기록됩니다. 판정에 쓰인 임계값과 기준에서 계산된 짧은 문자열입니다.

두 리포트의 숫자가 다를 때 원인을 가릅니다.

- 지문이 **같다** → 판정 기준은 동일하고, **데이터가 달라진** 것
- 지문이 **다르다** → 그 사이 **판정 기준 설정이 바뀐** 것
