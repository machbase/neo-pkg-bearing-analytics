# 첫 설정

**한국어** | [English](./first-setup.en.md)

앱을 처음 열면 **설정** 화면에서 분석 대상을 지정합니다. 설정은 왼쪽의 여섯 개 섹션으로 나뉩니다.

| 섹션 | 내용 | 필수 |
| :--- | :--- | :---: |
| 데이터 소스 | 분석할 TAG table·태그 선택, 별칭 | 예 |
| 설비 정보 | 단위 · Class · **RPM · 베어링 모델** · 계측·구동 정보 | **예** |
| 판정 기준 | 머신 클래스, 심각도 임계값, 베이스라인 학습 | 선택 |
| 알람 설정 | 감시 방식, 평가 주기·윈도우, 알람 동작, 알림 | 선택 |
| LLM 연동 | 리포트·이벤트 소견용 프로바이더 | 선택 |
| 데이터 관리 | 저장 용량 확인, 기간·태그별 데이터 삭제 | 선택 |

설정을 바꾸면 화면 아래에 저장 안내가 뜨고, **저장**을 누르면 실데이터가 다시 적재됩니다. 저장하지 않고 다른 탭으로 나가려 하면 확인 창이 뜹니다. 설정이 필요한 항목이 남아 있으면 헤더의 ⚙ 버튼에 주황 점이 표시됩니다.

## 데이터 소스

가장 먼저 어떤 데이터를 분석할지 고릅니다.

1. Neo에서 감지된 table 목록이 종류 배지와 함께 표시됩니다.
2. 분석할 table을 선택합니다. **여러 개를 동시에 선택**할 수 있습니다.
3. 선택한 table의 태그가 아래 별칭 표에 나타납니다.

처음에는 아무것도 선택되어 있지 않습니다. 실제로 분석할 table만 직접 선택합니다.

### 컬럼 구성

Machbase TAG table의 표준 컬럼명(`NAME` · `TIME` · `VALUE`) 기준으로 조회합니다. 다른 컬럼명을 쓰는 TAG table은 아직 지원하지 않습니다.

### 별칭

태그는 `별칭 (태그명)` 형태로 표시됩니다. 원래 태그명이 길거나 코드성이면 별칭을 지정해 알아보기 쉽게 만들 수 있습니다. 별칭은 모니터링 카드·상세분석·리포트·알림 문구에 함께 쓰입니다. 비워 두면 원래 태그명(`NAME`)이 그대로 표시됩니다. 태그가 많으면 검색으로 찾습니다.

### 적재 상한

쿼리 폭주를 막기 위해 **table당 태그 60개**, **전체 설비 100개**까지 적재합니다. 태그가 이보다 많으면 일부가 화면에 나타나지 않으므로, 분석 대상 table만 선택해 범위를 좁히는 편이 좋습니다.

### 데이터 소스 변동 감지

선택한 table이나 태그가 DB에서 제거되거나 비면, 모니터링 화면 상단에 변동 감지 배너가 뜹니다. **다시 불러오기**로 갱신하거나 **무시**로 닫을 수 있습니다.

## 설비 정보

각 태그가 어떤 설비인지 알려 주어야 판정이 나옵니다. 미설정 태그에는 주황 점이 표시됩니다.

> **RPM과 베어링 모델은 필수입니다.** 등급을 켜는 축이 결함주파수 격자인데, 회전수와 베어링 기하가 없으면 그 격자를 만들 수 없습니다. 둘 중 하나라도 비면 그 태그는 **등급이 오르지 않습니다** — 그건 "정상"이 아니라 "판정 못 함"이고, 카드의 커버리지 표시에 그렇게 나타납니다.
>
> 나머지 항목(단위·Class·계측·구동)은 없어도 판정은 돌아갑니다.

| 항목 | 설명 |
| :--- | :--- |
| 단위 | `mm/s`(속도) · `g`(가속도) · `μm`(변위). 어느 임계값 표를 상속할지 결정합니다 |
| Class | 설비 Class(I~IV). ISO 10816 심각도 존이 적용됩니다 |
| **RPM** | 회전 속도. 결함주파수 격자의 기준입니다 — **비우면 판정이 안 됩니다**(추정하지 않습니다) |
| **베어링 모델** | 카탈로그에서 고르면 형상값과 결함 주파수가 자동 계산됩니다 — **비우면 판정이 안 됩니다** |

각 항목 이름 옆의 <kbd>?</kbd>에 마우스를 올리면 그 값이 무엇인지, 어디서 확인하는지, 비워 두면 어떻게 되는지가 표시됩니다.

**모르는 항목은 비워 두세요.** 그 항목으로 판정하는 결함만 "이 측정으론 볼 수 없음"으로 남고 나머지 진단은 그대로 진행됩니다. 추측해서 채우면 그 추측이 판정 근거가 되므로 오히려 위험합니다.

이 원칙이 RPM에도 그대로 적용됩니다. 예전에는 비어 있으면 1800 rpm으로 가정했는데, 2극(3600 rpm)·6극(1200 rpm) 설비에서 격자가 통째로 어긋나면서도 화면은 평소처럼 등급을 냈습니다 — 조용히 틀리는 최악의 형태라 없앴습니다. **명판에서 확인해 정확히 넣거나, 비워 두고 "판정 못 함"으로 남기십시오.**

### ISO Class 기준

| Class | 대상 |
| :---: | :--- |
| I | 소형 기계 (≤ 15 kW) |
| II | 중형 기계 (15–75 kW) |
| III | 대형 기계 · 강성 기초 |
| IV | 대형 기계 · 연성 기초 |

### 베어링과 결함 주파수

베어링 모델을 카탈로그에서 선택하면 형상값(볼 수·볼경·피치경·접촉각)이 자동 입력되고 BPFO / BPFI / BSF / FTF 결함 주파수가 RPM과 함께 계산됩니다. 표 오른쪽의 **설정** 버튼을 누르면 계산된 값을 확인할 수 있습니다.

- **카탈로그에 없는 베어링** — 설정 창에서 볼 수 `n`, 볼경 `Bd`, 피치경 `Pd`, 접촉각 `φ`를 직접 입력합니다.
- **저널(sleeve) 베어링** — 구름요소가 없어 BPFO/BPFI/BSF/FTF가 정의되지 않습니다. 1×·2× 회전주파수 기준으로만 진단합니다.

베어링을 등록하면 상세분석 FFT에 결함 주파수 마커가 표시되어, 어떤 피크가 어떤 결함인지 대조할 수 있습니다.

### 계측·구동 정보

표 오른쪽의 **설정** 버튼을 누르면 결함 주파수·형상값과 함께 계측·구동 정보를 입력하는 칸이 열립니다. 버튼에 표시되는 `n/N`은 입력 완성도입니다.

| 항목 | 진단에서 하는 일 |
| :--- | :--- |
| 마운팅 방식 | 측정이 유효한 주파수 상한을 정합니다 — 스터드 10 · 접착 5 · 자석 2 · 핸드프로브 1 kHz |
| 구동방식 | 직결 · 벨트 · 기어. 벨트면 풀리비로 종동축 회전수가 계산됩니다 |
| 날개수 · 잇수 | 날개수 × 회전주파수 = 베인 통과 주파수 |
| 벨트 제원 | 풀리경 D1·D2와 벨트 길이. 벨트 자체 결함(균열·결손) 판정에 쓰입니다 |

전부 선택 입력입니다. 다만 **마운팅 방식은 되도록 지정하는 편이 좋습니다.**

가속도계는 부착 방식에 따라 신뢰할 수 있는 주파수 상한이 크게 다릅니다. 이 패키지는 어느 주파수 대역에 충격성이 가장 강한지 자동으로 찾아 그 대역에서 포락선 분석을 하는데, 자석 마운트의 공진(보통 2~5 kHz)은 그 탐색에서 **결함처럼 보입니다**. 마운팅을 지정하면 상한을 넘는 대역이 탐색에서 제외되어, 마운팅이 울린 것을 베어링 결함으로 읽는 오류가 사라집니다. 비워 두면 상한 없이 전 대역을 그대로 신뢰합니다.

제외된 대역이 있으면 리포트의 진단 근거에 그 사실이 함께 인쇄됩니다.

### 전원 계통주파수

전기적 결함은 계통주파수의 2배(60 Hz 계통이면 120 Hz)에서 나타나며, 회전수가 변해도 움직이지 않는 것이 기계적 결함과의 구분점입니다. 국내는 60 Hz 단일 계통이라 기본값으로 고정되어 있고, 설정 칸은 평소 표시되지 않습니다. 입력된 RPM이 다른 계통의 동기속도(50 Hz면 3000·1500·1000 rpm 계열)에 맞으면 경고와 함께 선택 칸이 나타납니다.

## 판정 기준

심각도(양호 · 주의 · 위험 · 심각)를 나누는 두 가지 기준을 설정합니다.

- **절대 임계** — ISO 10816 머신 클래스로 정하는 존 경계. 항상 적용됩니다.
- **상대 기준(베이스라인)** — 설비별 정상 상태를 학습한 값. 학습한 태그에만 추가로 적용됩니다.

### 머신 클래스와 존 경계

머신 클래스를 고르면 선택한 클래스의 존 경계가 미리보기로 표시됩니다. 각 태그는 자신의 Class(속도 `mm/s`) 또는 단위(`g` · `μm`) 행의 임계값을 상속합니다.

- 속도(`mm/s`)의 기본값은 **ISO 10816 기준값**입니다.
- 가속도(`g`) · 변위(`μm`)의 기본값은 **일반 참고값**입니다 — 규격이 정의한 물리량이 아니므로 설비에 맞게 조정해 쓰는 것을 전제로 합니다.

임계값은 표에서 직접 수정할 수 있고, **기본값으로 초기화**로 되돌릴 수 있습니다.

### 베이스라인 학습

임계값은 **항상** 적용됩니다. 여기에 더해, 설비가 정상일 때의 상태를 학습시키면 상대 기준이 한 층 추가됩니다.

정상 운전 구간 RMS의 중심(μ)과 평소 변동(σ)을 학습해, 한계를 넘으면 **평소 대비 급증**으로 표시합니다. 절대값이 양호 존이어도 잡아냅니다. 다만 이 축은 **등급도 알림도 만들지 않습니다** — 카드와 근거표에서 눈으로 확인하는 근거입니다.

| 설정 | 값 | 설명 |
| :--- | :--- | :--- |
| 정상 학습 기간 | 최근 1시간 / 6시간 / 24시간 | 길수록 다양한 정상 상태를 포함해 기준이 견고해집니다 |
| k (σ 배수) | 숫자 | 이탈 판정 민감도. `k=3`이면 정상 데이터의 약 99.7%가 한계 안에 들어옵니다. 확신이 없으면 3을 그대로 두세요 |

- 태그별로 **학습**하거나 **전체 학습**으로 한 번에 처리합니다. 학습된 값은 **삭제**할 수 있습니다.
- 데이터가 학습 기간보다 짧으면 있는 만큼만 학습합니다.
- 학습은 알람의 **RMS 구간과 같은 단위**로 이루어집니다. 판정에 쓰는 값과 같은 방식으로 배워야 그 기준이 실제 판정값의 분포를 설명하기 때문입니다. 구간을 바꾸면 기준도 다시 학습하는 편이 좋습니다.
- 미학습 태그가 있으면 화면 상단에 개수가 표시됩니다. 학습 전에도 임계 감지는 정상 동작합니다.

#### 기준이 오래됐을 때

학습한 지 한 달이 넘은 태그가 있으면 화면 상단에 알림이 뜨고, 각 행에 학습 시점 배지가 붙습니다.

앱은 **자동으로 재학습하지 않습니다.** 결함이 자라는 중에 다시 배우면 그 결함이 정상 기준으로 흡수되기 때문입니다. 정비를 했거나 운전 조건이 바뀌었다면 그때 직접 **학습**을 눌러 갱신하십시오.

#### 태그를 지웠다 다시 만든 경우

학습값은 `테이블:태그` 이름을 키로 저장되므로, 같은 이름으로 다른 설비를 붙이면 옛 기준이 그대로 적용됩니다. 새 설비가 더 조용하면 이상을 못 잡고, 더 시끄러우면 알람이 계속 터지는데 화면에는 그냥 "학습됨"으로 보입니다.

앱이 이 상황을 감지하면 해당 행에 **같은 설비 — 유지** / **다른 설비 — 초기화** 선택이 나타납니다. 확인 전까지 그 태그의 베이스라인 판정은 멈추며, ISO 존 판정은 그동안에도 계속 동작합니다.

#### 학습 데이터가 깨끗하지 않을 때

학습 구간에는 보통 정상 운전만 들어 있지 않습니다. 그래서 학습은 다음 세 가지를 자동으로 처리합니다.

**순간 스파이크에 흔들리지 않습니다.** 중심과 변동을 평균·표준편차가 아니라 중앙값 계열로 추정합니다. 60개 구간에 스파이크가 3개만 섞여도 표준편차 방식은 한계가 정상값의 서너 배까지 부풀어, **이탈을 잡으라고 만든 기준이 오히려 이탈을 덮습니다.** 중앙값 방식은 표본의 절반이 오염돼도 유지됩니다.

**정지·기동 구간은 제외합니다.** 운전 수준의 20% 아래로 떨어진 구간(정지·아이들)과 앞뒤로 급변하는 구간(기동·정지 램프)을 학습에서 뺍니다. 무엇을 제외했는지는 학습 완료 안내와 상태 줄에 `제외 12(정지 8·과도 4)` 형태로 표시됩니다.

**정지가 대부분인 구간은 학습을 거부합니다.** 창의 대부분이 정지면 "정지 상태"가 정상으로 학습되어, 기계를 돌리기만 해도 이탈 알람이 울립니다. 이 경우 학습이 실패하고 정상 운전이 대부분인 기간으로 다시 학습하라는 안내가 뜹니다.

여기에 더해, 거의 흔들리지 않는 신호에서는 한계가 μ에 너무 붙지 않도록 **최소 μ의 1.2배**로 유지합니다 — 노이즈 수준의 변동에 알람이 반복되는 것을 막기 위해서입니다.

> 이 처리는 결함이 이미 진행 중인 기간을 걸러 주지는 못합니다. 그 구간으로 학습하면 결함 상태가 정상 기준이 됩니다. **정상 운전이 확실한 기간**을 고르는 것은 여전히 사용자의 몫입니다.

### 대역 에너지 추세 (선택)

전체 RMS는 거의 안 움직이는데 특정 주파수 대역만 뛰는 변화 — 대표적으로 초기 베어링 결함 — 를 잡는 세 번째 기준입니다. 판정 기준 화면 맨 아래에 있습니다.

대역은 회전주파수(1×) 기준으로 다섯 구간(서브동기 · 1× 대역 · 결함 대역 · 고주파 · 초고주파)으로 나뉘고, 초고주파는 옥타브 단위 4개 대역으로 세분되어 실제 저장·판정되는 대역은 8개입니다. 각 대역이 평소 대비 몇 배로 올랐는지를 봅니다.

설정은 세 단계입니다.

1. **대역 추출** — 켜고 추출 주기(10분 ~ 1시간)를 정합니다. 원시 데이터를 주파수 분석해야 얻어지는 값이라, 판정과는 별도의 주기로 서버에서 계산해 쌓습니다. 주기가 짧을수록 표본이 빨리 모입니다.
2. **과거 데이터 채우기** — 표본이 쌓이길 기다리지 않고, 이미 DB에 있는 원시 데이터로 과거 구간을 소급 계산합니다. 진행률과 예상 소요 시간이 표시되며, 중간에 멈춰도 채운 만큼은 그대로 쓰입니다.
3. **정상 기준 학습** — 표본이 충분해지면 대역별로 학습합니다. 전체 RMS 학습과 같은 방식이며, 같은 자동 필터가 적용됩니다.

채널별 학습 상태에 `학습됨 4/9`처럼 표시됩니다. 분모는 그 태그에서 측정 가능한 계열 수입니다 — 샘플레이트가 낮으면 상위 대역이 빠지고, 베어링 품번이 없으면 결함주파수 계열이 빠지며, 이는 정상입니다. 학습되지 않은 계열은 판정에서 제외됩니다.

> 대역 학습도 **정상 운전이 확실할 때** 하십시오. 결함이 이미 진행 중이면 그 결함이 정상 기준이 됩니다.

## 알람 설정

감시 방식(앱 감시 · 서버 상시 감시), 판정 주기와 RMS 구간, 그리고 알림(진입/복귀 확인 시간, 웹훅 채널, 심각도별 알림 방식과 재알림)을 정합니다. 웹훅 설정 방법은 [알람과 이벤트](./alarms.kr.md)의 가이드를 참고하십시오.

이 섹션은 다룰 내용이 많아 별도 문서로 정리했습니다 → [알람과 이벤트](./alarms.kr.md)

## LLM 연동

리포트와 이벤트에 서술형 소견을 덧붙이려면 프로바이더를 하나 이상 설정합니다. 이 기능은 선택이며, 연결하지 않아도 나머지는 모두 동작합니다.

1. 프로바이더(Claude · OpenAI · Gemini · Ollama)를 고릅니다.
2. **API 키**와 **모델**을 입력합니다. 모델을 비워 두면 프로바이더별 기본 모델을 씁니다.
3. Ollama는 API 키 대신 **Ollama URL**을 입력합니다.
4. **연결 테스트**로 설정이 올바른지 확인합니다.

여러 프로바이더를 설정해 두고, 상세분석·리포트 화면의 드롭다운에서 그때그때 골라 쓸 수 있습니다. 연결 테스트는 검증용일 뿐, 기능을 켜는 조건은 "설정이 존재하는가"입니다.

> 소견의 논조와 판정 규칙은 패키지의 `persona/` 문서에 정의되어 있습니다. 자세한 내용은 [사용 방법 › LLM 소견](./usage.kr.md#llm-소견-선택)을 참고하세요.
