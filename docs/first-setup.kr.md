# 첫 설정

**한국어** | [English](./first-setup.en.md)

앱을 처음 열면 **설정** 화면에서 분석 대상을 지정합니다. 설정은 왼쪽의 다섯 개 섹션으로 나뉩니다.

| 섹션 | 내용 | 필수 |
| :--- | :--- | :---: |
| 데이터 소스 | 분석할 TAG table·태그 선택, 별칭 | 예 |
| 설비 정보 | RPM · 베어링 모델 · ISO Class | 권장 |
| 판정 기준 | 심각도 임계값, 정상 상태 학습 | 선택 |
| 알람 설정 | 심각도별 통지 라우팅 | 선택 |
| LLM 연동 | 리포트·이벤트 소견용 프로바이더 | 선택 |

설정을 바꾸면 화면 상단에 저장 안내가 뜨고, 저장하면 실데이터가 다시 적재됩니다.

## 데이터 소스

가장 먼저 어떤 데이터를 분석할지 고릅니다.

1. Neo에서 감지된 TAG table 목록이 표시됩니다.
2. 분석할 table을 선택합니다.
3. 그 table의 태그 목록에서 감시할 태그를 고릅니다.

처음에는 아무것도 선택되어 있지 않습니다. 실제로 분석할 태그만 직접 선택합니다.

### 별칭

태그는 `별칭 (태그명)` 형태로 표시됩니다. 원래 태그명이 길거나 코드성이면 별칭을 지정해 알아보기 쉽게 만들 수 있습니다. 별칭은 모니터링 카드·상세분석·리포트에 함께 쓰입니다.

### 데이터 소스 변동 감지

선택한 table이나 태그가 DB에서 제거되거나 비면, 상단에 변동 감지 배너가 뜹니다. 이때 데이터 소스에서 선택을 갱신합니다.

## 설비 정보

각 태그가 어떤 설비인지 알려 주면 진단 정확도가 올라갑니다. 등록하지 않아도 동작하지만, 다음 값을 넣으면 판정과 진단이 더 정밀해집니다.

- **RPM** — 회전 속도. 1× 주파수와 베어링 결함 주파수 계산의 기준입니다.
- **베어링 모델** — 카탈로그에서 고르면 형상값과 BPFO / BPFI / BSF / FTF 결함 주파수가 자동 계산됩니다.
- **ISO Class** — 설비 Class(I~IV)를 고르면 ISO 10816 심각도 존이 적용됩니다.

베어링을 등록하면 상세분석 FFT에 결함 주파수 마커가 표시되어, 어떤 피크가 어떤 결함인지 대조할 수 있습니다.

## 판정 기준

심각도(양호 · 주의 · 위험 · 심각)를 나누는 임계값을 확인·조정하는 화면입니다.

- 각 태그는 자신의 Class 또는 단위 행의 임계값을 상속합니다.
- 기본값은 ISO 10816을 따르며, 필요하면 직접 임계값을 덮어쓸 수 있습니다.

### 정상 상태 학습 (베이스라인)

임계값은 **항상** 적용됩니다. 여기에 더해, 설비가 정상일 때의 상태를 학습시키면 **상대 기준(베이스라인)**이 한 층 추가됩니다.

- 학습 전 — 임계 초과만으로 이벤트·알람을 판정합니다.
- 학습 후 — 임계 초과 **또는** 베이스라인 이탈을 함께 판정합니다.

정상 상태 학습은 절대 임계로는 잡기 어려운 "평소와 다른" 변화를 잡아내기 위한 것입니다. 학습이 안 된 태그는 설정 화면에 미학습 표시가 남습니다.

## 알람 설정

이벤트가 발생했을 때 어떤 심각도를 어느 채널로 통지할지 라우팅을 지정합니다. 심각도별로 이메일 · Slack · SMS 대상을 켜고, 통지 방식을 고를 수 있습니다.

> 알람 판정 자체는 앱이 열려 있는 동안 동작합니다. 자세한 동작은 [사용 방법 › 알람과 이벤트](./usage.kr.md#알람과-이벤트)를 참고하세요.

## LLM 연동

리포트와 이벤트에 서술형 소견을 덧붙이려면 프로바이더를 하나 이상 설정합니다. 이 기능은 선택이며, 연결하지 않아도 나머지는 모두 동작합니다.

- Claude · OpenAI · Gemini는 API Key를, Ollama는 `base_url`을 입력합니다.
- 여러 프로바이더를 설정한 경우, 드롭다운에서 사용할 프로바이더를 고릅니다.
- **연결 테스트**로 설정이 올바른지 확인할 수 있습니다. 테스트는 검증용일 뿐, 기능을 켜는 조건은 "설정이 존재하는가"입니다.
