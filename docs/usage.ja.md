# 使い方

[English](./usage.en.md) | [한국어](./usage.kr.md) | [日本語](./usage.ja.md)

設定が済んだら、3つのメインタブ — モニタリング・詳細分析・レポート作成 — で作業します。アプリの画面は韓国語のため、必要に応じて韓国語の表示名を括弧内に併記します。

## モニタリング

全設備の状態をひと目で確認する画面です。

### サマリーバー

上部のサマリーバーには次の欄があります。

| 欄 | 内容 |
| :--- | :--- |
| 総設備数 | 画面に表示されている設備の数。クリックすると等級フィルターが解除されます |
| 良好・注意・危険・重大（양호 · 주의 · 위험 · 심각） | 等級別の設備数。クリックするとその等級の設備だけをカードに絞り込んで表示し、もう一度クリックすると解除されます |
| **判定保留**（판정 보류） | 現在、等級を付けていない設備の数。マウスを重ねると理由別の内訳（計測異常・信号途絶・停止・判定不可・欠陥パターン測定待ち/失敗・判定待ち）が表示され、クリックするとその設備だけに絞り込みます |
| 最新イベント | 最も新しいイベント。下のイベント一覧のフィルターとは関係ありません |

### 設備カード

選択したタグごとにカードが1枚ずつ作られます。カードをクリックすると、そのタグの**詳細分析**に移動します。

| カードの要素 | 意味 |
| :--- | :--- |
| 別名・タグ名 | データソースが2つ以上ある場合、タグ名の横にテーブル名が付きます |
| 等級バッジ | 良好・注意・危険・重大。末尾の表示 `N시간째` は確定してからの経過時間、`1회차`・`2회차` はまだ確定前の候補、`복귀 N회차` は復帰を確認中であることを示します |
| 大きな数字 | 等級の高さを決めるISO振動値（10\~1000 Hz帯域のRMS。単位の横に `10~1000 Hz` と表示）。加速度・変位センサーは、同じ帯域の値を元の単位で表示します。まだ値がない場合は区間RMSを表示し、その測定帯域を示します |
| 数字にマウスを重ねる | 欠陥パターンの検出有無（グリッドスコア）、ベースライン・帯域の限界値に対する倍率、ISO値と全帯域値の差 |
| スパークライン | 直近1分間の振動の推移 |
| 下の行 | 最終受信時刻・Class |

- 既定の並び順は**等級の重い順**です。カードをドラッグ＆ドロップすると好きな順に並べ替えられ、その順序は保存されて次に開いたときも維持されます。
- **カードサイズ**スライダーでグリッドの密度を調整できます。
- カードの等級はアラームと**同じルール**で付けられます — 欠陥パターンの抽出周期（既定10分）ごとに、欠陥パターンが等級のスイッチを入れ、ISOゾーンがその高さを決めます。アラーム設定のRMS区間は、運転/停止・信号途絶・計測異常の判断と、平常比の根拠に使われます。

#### カードバッジ

| バッジ | 位置 | 意味 | 対応 |
| :--- | :--- | :--- | :--- |
| **判定保留**（판정 보류） | 等級の位置 | 現在は等級を付けていません。マウスを重ねると理由と直前の確定等級が表示されます | 理由に応じて下記を参照 |
| 停止（정지） | グラフの上 | 設備が止まっているため、判定を止めています（直前の状態を維持） | 対応不要 — 運転が再開されると判定も再開されます |
| 信号途絶（신호 두절） | グラフの上 | データが入ってきていません。グラフの線が薄く表示されます | 収集経路を確認 |
| 計測異常（계측 이상） | グラフの上 | クリッピング・DCドリフトなどにより、波形が信頼できません | センサー・ケーブル・マウンティングを確認 |
| 等級反復 N回（등급 반복 N회） | 右上 | 直近2時間に等級の悪化（しきい値超過）が3回以上繰り返されました | クリックすると、最後に悪化した時点の詳細分析が開きます |

判定保留の理由には、上の3つ（停止・信号途絶・計測異常）のほかに次のものがあります。

- **判定不可**（판정 못 함） — RPMやベアリング形状が登録されていないため、欠陥パターンを組み立てられません（ジャーナルベアリングを含む）。設備情報を入力してください。
- **判定待ち**（판정 대기） — アプリを開いた直後で、最初の判定を待っている状態です。
- **欠陥パターン初回測定待ち / 欠陥パターン測定失敗** — 今回の判定回で欠陥パターンを測定できなかったため、直前の等級を維持しています。次の判定回で再測定します。

### テーブルフィルター

データソースを2つ以上選ぶと、「設備モニタリング」の見出しの横に**テーブルフィルター**（테이블 필터）が表示されます。見たいテーブルだけを選んで、カードとサマリーバーを絞り込めます。

- 変わるのは画面の表示だけです。監視・アラームの対象はそのままです（恒久的に外すには、設定 → データソースで選択を解除します）。
- すべて非表示にすると、「表示するテーブルが1つも選ばれていません」という案内と**すべて表示**ボタンが表示されます。

### 監視状態の通知

監視が正しく動いていない場合、画面の一番上に警告が表示されます。タイマーが止まった場合、動いてはいるものの判定対象がない場合、アプリの判定が遅れている場合です。ほとんどは**再登録**ボタンですぐに対処できます。

「イベントがない」ことが、設備が正常だという意味なのか、監視が止まっているという意味なのかを区別するための仕組みです。表示ごとの意味と対処は、[アラームとイベント › 監視状態の確認](./alarms.ja.md#監視状態の確認)を参照してください。

### イベント一覧

下部のイベント一覧には、記録されたイベントが**時刻・タグ・種類・詳細・等級**で表示されます。各行をクリックすると、そのイベントが発生した時点の詳細分析に移動します。

**詳細**欄には、種類に応じて次の内容が記載されます。

| 種類 | 詳細欄 |
| :--- | :--- |
| 等級イベント（観察・しきい値超過・状態継続・状態改善・正常復帰）、速度（mm/s）センサー | 等級の高さを決めたISO値・超えたゾーン境界（例：`3.2 mm/s · 기준 2.8`） |
| 等級イベント、加速度（g）・変位（μm）センサー | 元の単位の値・等級の根拠（例：`0.077 g · ISO 위험 구간 · 결함 패턴 외륜(BPFO)`） — 等級は速度に換算したISO値で付けるため、元の単位での基準値はありません |
| 信号途絶 | 無受信の時間（例：`6분 무수신`） |
| 計測異常・計測復帰 | 理由（例：`플랫라인`、`계측 정상 복귀`） — マウスを重ねると説明が表示されます。振動値ではないため、数値は記載しません |

欠陥パターンのグリッドスコア・部位・判定回（例：`격자 3.2 · 외륜(BPFO) · 2회 연속 확정`）は、[エクスポート](#イベントのエクスポート)ファイルの「詳細」列と通知文に記載されます。

- 期間チップ（今日・7日・全体）と**タグ・種類**のドロップダウンで、一覧を絞り込めます。フィルターに合うイベントのうち直近の**200件**を表示し、件数はフィルターに合うイベント全体の数です。それ以上はエクスポートで確認します。
- 一覧は30秒ごとに読み直されます — サーバー監視や別のタブが記録したイベントも、再読み込みなしで表示されます。表示されるのは現在監視中のタグのイベントだけで、選択を解除したテーブルのイベントはエクスポートで確認します。
- 種類は8つです — 設備等級：**観察**（1回目・通知なし）・しきい値超過・状態継続・状態改善・正常復帰、監視状態：計測異常・計測復帰・信号途絶。各種類の意味は[異常判定の仕組み › イベント](./detection.ja.md#イベント)にあります。

> **ベースライン・帯域はイベントを作りません。** 逸脱しても一覧には表示されず、カードと根拠表に表示されるだけです。等級イベントは、欠陥パターンの抽出周期（既定10分）ごとに発生します。

### イベントのエクスポート

イベント一覧の**保存**（저장）ボタンをクリックすると、期間とファイル形式（CSV・JSON）を選ぶ画面が開きます。指定した期間のイベントをファイルとしてダウンロードできます。一覧と違い、選択を解除したテーブルのイベントもすべて含まれます。

CSVの列は、時刻・テーブル・タグ・別名・種類・等級・指標値・基準値・詳細です。

> アラーム判定がいつ、どのようにイベントを作るかは、[アラームとイベント](./alarms.ja.md)で説明しています。

## 詳細分析

1つのタグを深く掘り下げて見る画面です。モニタリングのカードやイベントの行から開きます。

詳細分析は**スナップショット**です — 開いた時点のデータで固定され、画面がリアルタイムに更新され続けることはありません。最新の状態で取り直すには、**更新**をクリックするか、タグ・期間を変更します。開いた後に監視側で見た計測状態が変わると、画面の上にその旨と**更新**ボタンが表示されます。

### タグ・期間の選択

- 画面上部のドロップダウンで、分析するタグを切り替えられます。
- 照会期間はプリセットで選びます — 1時間・6時間・24時間・全体、または横のカレンダーで直接指定します。プリセットは、そのタグの最新データを基準に設定されます。
- そのタグのデータがプリセットの長さより短い場合、そのプリセットは無効になります。クリックすると「データが不足しています」という案内が表示されるので、その場合は**全体**で確認します。
- 直接指定は日付単位です（開始日 00:00 \~ 終了日 23:59）。プリセットから切り替えると、直前のプリセットの区間の日付があらかじめ選択されます。

チャートの時間軸は、選択した期間全体に広がります。データのない区間は空白のまま残るため、実際にどこにデータがあるかがそのまま分かります。

### 計測有効性の警告

信号にクリッピング（飽和）・フラットライン・DCドリフト・単発スパイクといった計測異常が検出されると、画面の上に**信号異常 — センサー点検が必要**（신호 이상 — 센서 점검 필요）という警告が表示され、診断は**診断保留**の状態になります。

飽和した信号は振幅を実際より低く見せ、時間領域の単発インパルスはスペクトル全体を広帯域に汚染します。そのため、この警告が出ている間は、特定の候補だけでなく**すべての根拠の信頼度**が一緒に下がります。機械を疑う前に、まずセンサー・ケーブル・マウンティングを確認してください。

警告ボックスがなく、灰色の**DC成分**（DC 성분）の案内が1行だけある場合は、異常ではありません。平均値は大きいものの一定しているセンサー（MEMS加速度計の重力軸、近接変位センサーなど）であることを示す参考情報で、判定はそのまま行われます。レポートにも同じ灰色の案内が入ります。

### 重大度評価

上部のカードに総合等級とゾーン境界のバーが表示され、等級の横に**判定基準時刻**（「期間内8か所のうち最も悪い箇所」など）が記載されます。RPMやベアリングが登録されていない場合は、「判定基準 n/N（… 未適用）」も一緒に表示されます。

**この等級は、横に表示されている振動の大きさ（ISO）が決めるものではありません。** 等級のスイッチを入れるのは**欠陥パターンただ1つ**です — [包絡線（エンベロープ）](./glossary.ja.md#包絡線エンベロープ復調)で、ベアリングの欠陥周波数（BPFO・BPFI・BSF・FTF）の位置に根拠が成立したかどうかです。その根拠が成立して初めて等級が上がり、ISOゾーンは**上がった等級の高さ**を決めます。

そのため、**振動が大きくても欠陥パターンがなければ等級は良好のまま**で、逆に振動が普通でもパターンがはっきりしていれば等級は上がります（振幅にまだ現れない初期のベアリング欠陥がこれに当たります）。ベースライン・帯域の値は等級を動かさず、**根拠としてのみ**一緒に表示されます。

その下にある代表指標4種のカード（値・基準・変化量）は**期間統計**です — 選択した期間全体から算出した値で、等級ではありません。

モニタリングのカードと**同じ判定ルール**を使うため、2つの画面の等級が食い違うことはありません（詳細分析では、より長いウィンドウで期間内の複数の地点を測定します）。詳しい原理は[異常判定の仕組み](./detection.ja.md)にあります。

### 表示単位の切り替え

同じ振動信号でも、**加速度（g）・速度（mm/s）・変位（μm）のどれ**で見るかによって、現れる欠陥が変わります。「スペクトル分析」の見出し行にある**表示物理量**（표시 물리량）ボタンで切り替えられ、センサーが実際に測定した単位には `(원본)`（元の単位）の表示が付きます。

| 単位 | 強調されるもの |
| :--- | :--- |
| 加速度 `g` | 高周波 — ベアリング・衝撃性の欠陥 |
| 速度 `mm/s` | 中間帯域 — ISO判定の基準 |
| 変位 `μm` | 低周波 — アンバランス・ミスアライメント |

ベアリング欠陥が疑われるのに速度波形ではよく見えない場合は、加速度に切り替えてみてください。切り替えは波形・FFT・スペクトログラム・ケプストラム・診断指標（時間領域）の表示に適用され、レポートを作成するときも、いま選んでいる単位が使われます。包絡線は判定の入力なので常にセンサー本来の単位で計算し、トレンドと等級判定には影響しません。

### 尖度飽和の警告

尖度の推移がピークから下がっているのに、RMSが維持または上昇している場合、チャートの下に警告が表示されます。

尖度の低下は通常「良くなった」と読まれますが、この組み合わせは、欠陥が進行して**衝撃が常態化した状態**である可能性があります。初期のベアリング欠陥は鋭い衝撃で尖度を上げ、欠陥が広がると衝撃が途切れなく続くようになり、尖度が再び下がります。尖度だけを見て回復と判断しないでください。

### チャート

| チャート | 見るもの |
| :--- | :--- |
| 統計サマリー | 期間内の代表的な統計 |
| RMS推移 | 振動エネルギーの時間変化・ISOゾーンの基準線 |
| Peak-to-Peak・Crest Factor・尖度の推移 | 瞬間的な衝撃の大きさと、波形の鋭さの変化 |
| 欠陥帯域エネルギーの推移 | 周波数帯域ごとのエネルギーの変化。帯域抽出をオンにすると、包絡線系列（周期性・欠陥周波数）も一緒に描画されます。凡例をクリックすると、その系列を非表示にしたり再表示したりできます。**アラーム基準で表示**（알람 기준으로 보기）をクリックすると、各系列を学習済みの限界値で割った比率の軸に切り替わります — 1.0が学習済みの限界線なので、どの系列がどれだけ近づいているかがひと目で分かります（帯域ベースラインの学習が必要。帯域は通知を出さず、根拠としてのみ使います） |
| 生波形 | 時間領域の振動波形（ホイールで拡大・縮小、ドラッグで移動、ダブルクリックでリセット） |
| FFTスペクトル | 周波数成分。ベアリング登録時は1×/2×/3×、BPFO/BPFI/BSF/FTFのマーカーを表示 |
| ↳ 範囲 | 既定では低周波を中心に表示し、**全帯域**（전대역）に切り替えると、センサーが測定できる最大周波数まで広げます |
| スペクトログラム | 時間-周波数の変化 — 欠陥帯域がいつから大きくなったか |
| 帯域別衝撃性（カートグラム） | どの周波数帯域の衝撃性が最も大きいかを示す**参考表示**です。包絡線分析はこの帯域ではなく、1\~5 kHzの固定帯域で行います。マウンティング方式を指定した場合、その上限より上の帯域は探索から除外されます |
| 包絡線分析 | 衝撃性の欠陥が作る変調成分 — 欠陥パターンを測るチャート |
| ケプストラム | 高調波・側帯波の周期成分 |
| 診断指標（時間領域） | 生波形の区間から算出した、衝撃・エネルギー特性の指標 |

### 診断と推奨措置

**総合分析を展開**（종합 분석 펼치기）をクリックすると、ルールベースの診断が表示されます。アンバランス・ミスアライメント・ベアリング内輪/外輪・ゆるみ・ギアなどの欠陥を判定し、**判定根拠**（どの指標から得た根拠かという出所付き）と**優先順位付きの推奨措置**を一緒に示します。

> この判定は、単一チャンネル・単一方向の測定に基づき、位相情報なしで、銘板記載の回転数を基準に計算されます。欠陥のメカニズムは**仮説**であり、確定診断には多軸・位相の測定と、保全担当者による確認が必要です。

### LLM所見（任意）

LLMを連携している場合は、総合分析の下にある**LLM詳細所見を生成**（LLM 상세 소견 생성）で、記述形式の専門家所見を作成できます。所見は、画面に表示されたチャートの実測値だけを根拠にします。プロバイダーはボタン横のドロップダウンで選び、生成に使われたモデル名が所見の下に残ります。

所見の論調と判定ルールは、アプリがLLMに送る指示文に含まれています。LLMは、エンジンがすでに出した判定を記述するだけです — エンジンが渡した値だけを引用し（欠陥周波数・スコアを新たに計算したり、順位を覆したりしない）、計測異常の警告が出ている場合は結論を暫定とし、「探したが見つからなかった」という陰性所見を省かず、原理的に判別できない項目はスコアの代わりに「測定不可」と書き、等級を誇張しません。

LLMを連携していなくても、ルールベースの診断だけで十分に機能します。

## レポート作成

分析結果を文書として残す画面です。

1. レポートに含める**対象タグ**を選びます。（既定は未選択。全選択に対応）
2. **期間**を選びます — プリセット（1時間・6時間・24時間・全体）は**タグごとに、そのタグの最新データを基準に**設定され、カレンダーで直接指定した区間は、選択したすべてのタグにそのまま適用されます。直接指定した期間にデータがないタグがある場合は、警告とともにそのタグのデータ区間が案内されます。
3. 必要に応じて**LLM所見を含める**をオンにし、プロバイダーを選びます。
4. **レポート作成**をクリックします。

**選択したタグごとにレポートファイルが1つずつ**作成されます。ファイル名は `タグ名_作成日時.html` の形式です。

作成は、データ照会 → 指標計算 → 所見生成 → 保存 の4段階で進み、進行状況が表示されます。時間がかかる場合は、**生成中止**で取り消せます。完成したレポートは、ログインしているアカウントのフォルダー（`<アカウント>/vibration-reports/`、アカウント名は小文字）に保存されます。

### レポートの構成

| セクション | 内容 |
| :--- | :--- |
| 振動重大度評価 | 等級判定と、ゾーンに対する位置 |
| 総合振動レベル | 代表指標の全体的な水準 |
| 統計サマリー・指標サマリー | 期間内の統計と指標値 |
| 欠陥根拠の強さ | 欠陥候補ごとの根拠スコア（0\~100）・高い順 = 優先順位 |
| 深層分析 | LLM所見（連携時） |
| 総合所見と推奨事項 | 結論と措置 |

レポート上部の **サマリー**（요약）・**全体**（전체）ボタンで表示を切り替えます（サマリーボックス内の **全体表示**（전체 보기）リンクも同じです）。サマリーは30秒で読み取るためのもので、全体表示はすべてのチャートと根拠を展開します。印刷すると、全体の内容が一緒に出力されます。

> **印刷はレポート上部の印刷ボタン**（印刷・PDFとして保存）で行ってください。アプリから開いたレポートは、コンソールから隔離された枠の中に表示されるため（レポートファイルがログイン情報にアクセスできないようにするため）、ブラウザーのCtrl+Pでは外側の枠だけが印刷されます。

保存されたレポートは、外部参照のない**自己完結型のHTMLファイル**でありながら、チャートは画像ではなく操作できる状態のまま保存されています — ホイールズーム・ドラッグ・ツールチップが動作し、テーマの切り替えに合わせて再描画されます。ファイルを1つ渡すだけで、相手も同じように詳しく見ることができます。

各レポートには**判定フィンガープリント**が残ります。判定エンジンのルールから計算されるため、フィンガープリントとしきい値（Thresholds）欄が同じなのに数値が異なる場合はデータが変わったということであり、フィンガープリントが異なる場合はパッケージ（判定エンジン）が変わったということです。

### 保管庫

右側の保管庫には、保存されたレポートが次の列で表示されます。

| 列 | 内容 |
| :--- | :--- |
| 作成日時（생성일시） | レポートを作成した時刻 |
| レポート名（리포트명） | ファイル名（`タグ名_作成日時`）。マウスを重ねると対象タグが表示されます |
| 期間（기간） | レポートが対象とした期間 |
| 種類（유형） | **LLM 소견**（所見付き）または**지표만**（指標のみ） |

各行の目のアイコンのボタンでプレビュー、ごみ箱のボタンで削除します（確認画面が表示され、元に戻せません）。件数が多い場合は、ページを送って表示します。

## 使い方のヒント

- 最初はタグを1\~2個だけ選んで動作を確認してから、対象を広げます。
- 等級を出すには、**設備情報**にRPMとベアリングモデルが登録されている必要があります。加速度・変位センサーの場合は、単位も必ず正しく選んでください — 空欄のままにすると速度（mm/s）とみなされ、等級の高さがずれます。
- 「平常時と異なる」変化まで根拠として見るには、正常なときに**ベースライン学習**をしておきます。
- アプリを閉じても監視を続ける必要がある場合は、**サーバー常時監視**に切り替えます。
- イベントが溜まったら、定期的に**保存**でエクスポートして別途保管します。
- 極端な指標を見たときは、まず計測有効性の警告を確認します — 誤診の多くは、機械ではなくセンサー側に原因があります。
