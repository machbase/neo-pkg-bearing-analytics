# 사용 방법

**한국어** | [English](./usage.en.md)

설정을 마치면 세 개의 주 탭 — 모니터링 · 상세분석 · 리포트 생성 — 으로 작업합니다.

## 모니터링

전체 설비 상태를 한눈에 보는 화면입니다.

### 요약 바

상단 요약 바에는 전체 설비 수와 심각도별(양호 · 주의 · 위험 · 심각) 개수, 최근 이벤트가 표시됩니다. 심각도 칸을 누르면 그 등급의 설비만 카드 그리드에 걸러 보여 주고, 다시 누르면 필터가 풀립니다. 총 설비 칸을 누르면 필터가 초기화됩니다.

### 설비 카드

선택한 태그마다 카드가 하나씩 생깁니다. 각 카드에는 별칭과 태그명, 심각도 등급 배지, 최근 RMS 값과 단위, 스파크라인, 마지막 수신 시각, Class가 표시됩니다. 카드를 누르면 그 태그의 **상세분석**으로 이동합니다.

- 기본 정렬은 **위험 등급순**입니다. 카드를 끌어다 놓으면 원하는 순서로 바꿀 수 있고, 그 순서는 저장되어 다음에 열 때도 유지됩니다.
- **카드 크기** 슬라이더로 그리드 밀도를 조절할 수 있습니다.
- 카드의 등급은 **설정 → 알람 설정**에서 정한 RMS 구간을 그대로 씁니다 — 화면에 보이는 등급과 알람이 판정한 등급은 항상 같습니다. 어떤 기준인지는 그리드 우측에 표시됩니다.

### 감시 상태 알림

감시가 제대로 돌지 않으면 화면 맨 위에 경고가 표시됩니다. 타이머가 멈췄거나, 돌고는 있는데 판정 대상이 없거나, 앱 판정이 지연된 경우입니다. 대부분 **다시 등록** 버튼으로 바로 조치할 수 있습니다.

"이벤트가 없다"가 설비가 정상이라는 뜻인지 감시가 죽었다는 뜻인지 구분하기 위한 장치입니다. 자세한 내용은 [알람과 이벤트](./alarms.kr.md)를 참고하세요.

### 이벤트 목록

아래쪽 이벤트 목록에는 기록된 이벤트가 시각 · 태그 · 유형 · 지표값 대비 기준 · 등급으로 표시됩니다. 각 행을 누르면 그 이벤트가 발생한 시점의 상세분석으로 이동합니다.

값은 설비의 원본 단위로 적습니다. 가속도(g)·변위(μm) 센서 설비는 등급을 속도로 변환한 ISO 값으로 매기므로, 원본 단위로 나타낼 기준 숫자가 없습니다. 그래서 이 설비의 등급 이벤트는 원본 단위 값 옆에 기준 숫자 대신 등급 근거를 적습니다(예: `0.077 g · ISO 위험 구간 · 결함 패턴 외륜(BPFO)`). 알림 문구와 내보내기 파일의 기준값 칸도 같습니다.

- 기간 칩과 **태그 · 유형** 드롭다운으로 목록을 좁힐 수 있습니다.
- 목록은 최근 **200건**까지만 렌더합니다. 그 이상은 내보내기로 확인합니다.
- 유형은 **관찰**(단발 · 알림 안 감) · 임계 초과 · 상태 지속 · 상태 개선 · 정상 복귀 · 계측 이상 · 신호 두절이 있습니다. 각 유형의 뜻은 [이상 판정 원리](./detection.kr.md)에 정리돼 있습니다.

> **베이스라인·대역은 이벤트를 만들지 않습니다.** 이탈해도 목록에는 안 뜨고, 카드와 근거표에 표시만 됩니다. 이벤트는 10분 주기의 결함 패턴 축에서만 나옵니다.

### 이벤트 내보내기

이벤트 목록의 **저장** 버튼을 누르면 기간과 파일 형식(CSV · JSON)을 고르는 팝업이 뜹니다. 지정한 기간의 이벤트를 파일로 내려받을 수 있습니다.

> 알람 판정이 언제 어떻게 이벤트를 만드는지는 [알람과 이벤트](./alarms.kr.md)에서 다룹니다.

## 상세분석

한 태그를 깊이 들여다보는 화면입니다. 모니터링 카드나 이벤트 행에서 들어옵니다.

상세분석은 **스냅샷**입니다 — 들어온 시점의 데이터로 고정되며, 화면이 실시간으로 계속 바뀌지 않습니다. 최신 상태로 다시 캡처하려면 **새로고침**을 누르거나, 태그·기간을 바꿉니다.

### 태그·기간 선택

- 화면 상단의 드롭다운으로 분석할 태그를 바꿀 수 있습니다.
- 조회 기간은 프리셋으로 고릅니다 — 1시간 · 6시간 · 24시간 · 전체 · 직접 입력. 기본은 1시간입니다.
- 그 태그의 데이터가 프리셋 길이보다 짧으면 해당 프리셋은 비활성화됩니다. 누르면 "데이터가 부족합니다" 안내가 뜨며, 이때는 **전체**로 확인합니다.
- **직접 입력**은 시작·종료 일시를 분 단위까지 지정합니다. 프리셋에서 직접 입력으로 넘어가면 직전 프리셋 구간이 그대로 채워집니다.

차트의 시간축은 선택한 기간 전체를 채웁니다. 데이터가 없는 구간은 빈 곳으로 남아, 실제로 어디에 데이터가 있는지 그대로 보입니다.

### 계측 유효성 경고

신호에서 클리핑(포화) 같은 계측 이상이 감지되면 화면 최상단에 **신호 이상 — 센서 점검 필요** 경고가 뜨고, 진단은 **진단 보류** 상태가 됩니다.

포화된 신호는 진폭을 실제보다 낮게 보이게 하고, 시간영역의 단발 임펄스는 스펙트럼 전체를 광대역으로 오염시킵니다. 그래서 이 경고가 떠 있는 동안은 특정 후보만 아니라 **모든 근거의 신뢰도**가 함께 내려갑니다. 기계를 의심하기 전에 센서·케이블·마운팅을 먼저 확인하세요.

### 심각도 평가

상단 카드에 종합 위험도 등급과 존 경계 막대가 표시되고, 그 아래에 대표 지표 4종이 각각 값 · 임계 · 변화량과 함께 나옵니다.

**이 등급은 옆에 보이는 진동 크기(ISO)가 정하는 것이 아닙니다.** 등급을 켜는 것은 **결함 패턴 하나**입니다 — [포락선](./glossary.kr.md#포락선엔벨로프-복조)에서 베어링 결함주파수(BPFO·BPFI·BSF·FTF) 자리에 근거가 섰는가. 그 근거가 서야 등급이 오르고, ISO 존은 **오른 등급의 높이**를 정합니다.

그래서 **진동이 커도 결함 패턴이 없으면 등급은 오르지 않고**, 반대로 진동이 평범해도 패턴이 뚜렷하면 오릅니다(진폭에 아직 안 나타나는 초기 베어링 결함이 그 구간입니다). 베이스라인·대역 값은 등급을 움직이지 않고 **근거로만** 함께 표시됩니다.

모니터링 카드와 **같은 검출기**를 쓰므로 두 화면의 등급이 어긋나지 않습니다. 자세한 원리는 [이상 판정 원리](./detection.kr.md)에 있습니다.

### 표시 단위 바꾸기

같은 진동 신호도 **가속도(g) · 속도(mm/s) · 변위(μm)** 중 무엇으로 보느냐에 따라 드러나는 결함이 달라집니다. 화면 상단의 단위 버튼으로 전환할 수 있으며, 센서가 실제로 측정한 단위에는 `(원본)` 표시가 붙습니다.

| 단위 | 강조되는 것 |
| :--- | :--- |
| 가속도 `g` | 고주파 — 베어링·충격성 결함 |
| 속도 `mm/s` | 중간 대역 — ISO 판정 기준 |
| 변위 `μm` | 저주파 — 불평형·정렬 |

베어링 결함이 의심되는데 속도 파형에서 잘 안 보이면 가속도로 바꿔 보십시오. 전환은 화면 표시에만 적용되며, 등급 판정은 원본 단위 기준으로 유지됩니다.

### 첨도 포화 경고

첨도 추이가 고점에서 내려오는데 RMS는 유지되거나 오르는 경우, 차트 아래에 경고가 표시됩니다.

첨도 하락은 보통 "좋아졌다"로 읽히지만, 이 조합은 결함이 진행돼 **충격이 상시화된 상태**일 수 있습니다. 초기 베어링 결함은 뾰족한 충격으로 첨도를 올리고, 결함이 퍼지면 충격이 이어져 첨도가 다시 내려갑니다. 첨도만 보고 회복으로 판단하지 마십시오.

### 차트

| 차트 | 보는 것 |
| :--- | :--- |
| 원시 파형 | 시간 영역 진동 파형 |
| RMS · Peak-to-Peak · Crest Factor · 첨도 추이 | 시간에 따른 대표 지표 변화 (RMS 추이에는 ISO 존 기준선 표시) |
| 결함 대역 에너지 추이 | 주파수 대역별 에너지 변화. 대역 추출을 켜면 포락선 계열(주기성·결함주파수)도 함께 그려집니다. **알람 기준으로 보기**를 누르면 각 계열을 학습된 한계로 나눈 비율 축으로 바뀝니다 — 1.0이 알람선이라 어느 계열이 얼마나 가까운지 한눈에 보입니다(대역 베이스라인 학습 필요) |
| FFT 스펙트럼 | 주파수 성분. 베어링 등록 시 1×/2×/3×, BPFO/BPFI/BSF/FTF 마커 표시 |
| ↳ 주파수 범위 | 기본은 저주파 위주로 보여 주고, **전대역**으로 바꾸면 센서가 측정 가능한 최대 주파수까지 펼칩니다 |
| 스펙트로그램 | 시간-주파수 변화 |
| 결함 대역 탐색 | 어느 주파수 대역이 가장 충격성이 높은지 탐색 — 포락선 분석의 대역 선택 근거. 마운팅 방식을 지정했다면 그 상한 위 대역은 탐색에서 제외됩니다 |
| 포락선 (Envelope) | 충격성 결함이 만드는 변조 성분 |
| 켑스트럼 | 하모닉·측대역의 주기 성분 |

### 진단과 권고 조치

**종합 분석**을 펼치면 규칙 기반 진단이 표시됩니다. 불균형 · 정렬 불량 · 베어링 내륜/외륜 · 풀림 · 기어 등의 결함을 판정하고, **판정 근거**(어느 지표에서 나온 근거인지 출처와 함께)와 **우선순위가 매겨진 권고 조치**를 함께 제시합니다.

> 이 판정은 단일 채널·단일 방향 측정에 위상 정보 없이, 명판 회전속도를 기준으로 계산됩니다. 결함 메커니즘은 **가설**이며, 확정 진단에는 다축·위상 측정과 정비 담당자 확인이 필요합니다.

### LLM 소견 (선택)

LLM을 연동했다면 **LLM 상세 소견 생성**으로 서술형 전문가 소견을 만들 수 있습니다. 소견은 화면에 표시된 차트의 실측값만 근거로 삼습니다. 프로바이더는 버튼 옆 드롭다운에서 고르고, 생성에 쓰인 모델명이 소견 아래에 남습니다.

소견의 논조와 판정 규칙(계측을 먼저 의심할 것, 반증을 시도할 것, 판별 불가와 증거 부족을 구분할 것, 등급을 아껴 쓸 것 등)은 패키지의 `persona/` 문서에 정의되어 있습니다. 프롬프트에 복사해 쓰는 참조 문서이므로, 필요하면 현장 관행에 맞게 고쳐 쓸 수 있습니다.

LLM을 연동하지 않았으면 규칙 기반 진단만으로도 충분히 동작합니다.

## 리포트 생성

분석 결과를 문서로 남기는 화면입니다.

1. 리포트에 담을 **대상 태그**를 고릅니다. (기본은 미선택, 전체 선택 지원)
2. **기간**을 고릅니다 — 상세분석과 같은 프리셋(1시간 · 6시간 · 24시간 · 전체 · 직접 입력)이며, 선택한 태그 전부에 같은 구간이 적용됩니다.
3. 필요하면 **LLM 소견 포함**을 켜고 프로바이더를 고릅니다.
4. **리포트 생성**을 누릅니다.

생성은 데이터 조회 → 지표 계산 → 소견 생성 → 저장의 네 단계로 진행되며, 진행 상황이 표시됩니다. 오래 걸리면 **생성 중단**으로 취소할 수 있습니다. 완성된 리포트는 로그인한 계정의 폴더(`<계정>/vibration-reports/`)에 저장됩니다.

### 리포트 구성

| 섹션 | 내용 |
| :--- | :--- |
| 진동 심각도 평가 | 등급 판정과 존 대비 위치 |
| 종합 진동 레벨 | 대표 지표의 전체 수준 |
| 통계 요약 · 지표 요약 | 기간 내 통계와 지표 값 |
| 결함 근거 강도 | 결함 후보별 근거 점수(0~100) · 높은 순 = 우선순위 |
| 심층 분석 | LLM 소견 (연동 시) |
| 종합 소견 및 권고사항 | 결론과 조치 |

리포트 상단에서 **요약**과 **전체 보기**를 전환할 수 있습니다. 요약은 30초 안에 판독하는 용도이고, 전체 보기는 모든 차트와 근거를 펼칩니다. 인쇄하면 전체 내용이 함께 출력됩니다.

> **인쇄는 리포트 상단의 인쇄 버튼**(인쇄 · PDF로 저장)으로 하십시오. 앱에서 연 리포트는 콘솔과 격리된 틀 안에 떠 있어서(리포트 파일이 로그인 정보에 닿지 못하게), 브라우저의 Ctrl+P는 바깥 틀만 인쇄합니다.

저장된 리포트는 외부 참조가 없는 **자립형 HTML 파일**이면서, 차트가 그림이 아니라 살아 있습니다 — 휠 줌 · 드래그 · 툴팁이 동작하고, 테마 전환에 맞춰 다시 그려집니다. 파일 하나만 전달해도 상대가 같은 방식으로 들여다볼 수 있습니다.

각 리포트에는 **판정 지문**이 남습니다. 지문이 같은데 숫자가 다르면 데이터가 달라진 것이고, 지문이 다르면 판정 기준이 달라진 것입니다.

### 보관함

오른쪽 보관함에는 저장된 리포트가 생성일시 · 대상 태그 · 기간 · 유형(LLM 소견 포함 여부)으로 표시됩니다. 미리보기로 내용을 확인하거나 삭제할 수 있고, 건수가 많으면 페이지를 넘겨 봅니다.

## 사용 팁

- 처음에는 태그 한두 개만 선택해 동작을 확인한 뒤 대상을 넓힙니다.
- 진단 정확도를 높이려면 **설비 정보**에 단위·RPM·베어링 모델을 등록합니다. 단위를 안 정하면 어떤 임계값 표를 상속할지가 정해지지 않습니다.
- "평소와 다른" 변화까지 잡으려면 정상일 때 **베이스라인 학습**을 해 둡니다.
- 앱을 닫아도 감시가 이어져야 하면 **서버 상시 감시**로 바꿉니다.
- 이벤트가 쌓이면 주기적으로 **저장**으로 내보내 별도 보관합니다.
- 극단적인 지표를 봤을 때는 계측 유효성 경고를 먼저 확인합니다 — 오진의 상당수는 기계가 아니라 센서 쪽입니다.
