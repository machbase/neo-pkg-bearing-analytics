# 검증·실험 기록 (개발자용)

사용자 매뉴얼(`docs/`)에서 뺀 실험 과정·성능 수치·실패한 시도·운영 진단을 모은 문서입니다.
사용자 문서에는 "왜 이렇게 판정하나"를 납득시키는 결론 한 줄만 남기고, 근거 수치와 과정은 여기에 둡니다.

- 숫자는 **각 실험 당시의 검증 풀·설정 기준**입니다. 시점이 다른 값이 섞여 있으므로, 비교는 같은 표 안에서만 하십시오.
- 서로 맞지 않는 숫자는 맨 끝 [미해결 수치 불일치](#미해결-수치-불일치)에 모았습니다. 재측정 전까지는 사용자 문서에 인용하지 않습니다.
- 사용자 문서에서 이 문서로 링크하지 않습니다.

## 1. 검증 풀과 스냅샷 성적

공개 데이터셋 4종(CWRU · MFPT · Paderborn · XJTU-SY), **383 케이스(정상 100 · 결함 283)**.
기하(볼수·볼경·피치경·접촉각)가 1차 출처에 공개된 것만 골랐습니다.

| | 결과 |
| :--- | :--- |
| 정상 오탐 | 3/100 (3%) |
| 결함 검출 | 188/283 (66%) |
| 검출된 것 중 부위 적중 | 157/174 (90%) |
| 결함 전체 대비 부위까지 적중 | 157/283 (약 55%) |

- "검출된 것 중 90%"는 채택이 보수적일수록 좋아지는 조건부 값이라 단독 인용 금지.
- 분모 174는 검출 188건 중 부위를 단정한 건으로 보입니다(구름체는 "부위 미상"으로 나감). 원 기록에 정의가 없어 재확인이 필요합니다.
- 부위별: 외륜이 가장 잘 섬, 내륜 중간, 구름체는 라벨 적중 0 — 반대로 내륜·외륜 7건이 구름체로 잘못 갔음.

### 축별 단독 성적 (같은 383 케이스)

학습 두 축은 같은 데이터셋의 다른 정상 케이스로 학습(leave-one-out).

| 축 | 단독 오탐 | 단독 검출 |
| :--- | :--- | :--- |
| 결함 패턴 | 3/100 (3%) | 183/283 (65%) |
| 베이스라인 | 0/100 (0%) | 79/283 (28%) |
| 대역 | 13/100 (13%) | 117/283 (41%) |
| ISO 존 | 69/100 (69%) | 104/283 (37%) |
| 네 축 OR(옛 최댓값 방식) | 69/100 (69%) | 209/283 (74%) |
| 현행 — 패턴 게이트 · ISO 높이 | 3/100 (3%) | 188/283 (66%) |

- 옛 방식은 네 축의 최댓값을 등급으로 썼음. 축이 늘면 등급은 올라가기만 하므로 ISO 단독 오탐 69%가 그대로 화면 등급이 됨.
- 게이트 구조로 바꾼 뒤 머신 클래스를 잘못 잡아도 오탐이 거의 안 흔들림(Class I·II·III 전부 3~4%). 옛 방식에서는 클래스 하나 잘못 고르면 49%~75%로 요동.
- 학습 축을 게이트에 넣으면 같은 태그가 학습 여부에 따라 다른 등급을 냄 — 실측 오탐 3% → 15%.

### ISO 69%가 실기 오탐률이 아닌 이유

- 검증 풀은 전부 가속수명시험대. 건전한 시험대가 고하중으로 돌아 진동이 원래 높고, 결함 초기 베어링은 광대역 속도가 낮음.
- 정상의 ISO 중앙값 1.33 mm/s > 결함의 중앙값 1.21 mm/s — 이 풀에서 ISO 값은 손상 여부를 구분하지 못함.
- 클래스를 완화해도 안 됨: Class IV(2.80 mm/s)에서도 정상의 36%가 존 A를 넘음. 오탐 3%가 되려면 경계가 5.59 mm/s(ISO 최대의 2배)여야 하고, 그때 검출은 30%.
- ISO 10816/20816은 정상 운전 중인 실기 설비용 규격 — 위 표는 "규격 대상이 아닌 장비에 ISO를 걸면 어떻게 되나"를 잰 것.

## 2. 감시 창·임계와 계산 비용

| | 창 길이 | 채택 임계 | 같은 오탐률 기준 임계 |
| :--- | :--- | :--- | :--- |
| 상세분석 | 100회전 | 4.0 | 3.88 |
| 상시감시 | 25회전 | 3.0 | 3.03 |

- 서버 타이머 스크립트 엔진(goja)이 브라우저보다 100~400배 느림. 100회전이면 91태그 한 회차가 756초로 10분 주기 초과(126%), 25회전이면 167초(28%).
- 창이 짧으면 점수 분포가 통째로 내려가 임계도 같이 낮춤. 대가는 검출 66% → 59%.
- 감시 창 50회전은 25회전과 검출이 같고(59%) 계산 비용만 2배.
- 비용 기록(다른 측정 시점): 10초 축 롤업 RMS 1회 태그당 0.3 ms, 10분 축 원시 파형 → FFT → 포락선 태그당 311 ms(서버), "91개 태그를 10분마다 도는 데 28초(주기의 5%)" — 위 167초와 맞지 않음(불일치 목록 참고).
- 대역 추출 주기 도움말의 서버 부하 추정(40대 기준): 10분 5.5% · 30분 1.8% · 1시간 0.9%.

감시 채택 임계 3.0이 특정 데이터셋에 맞춰진 값인지 확인 — 데이터셋 하나씩 빼고 나머지로 임계를 고른 뒤 빼놓은 셋에서 오탐을 잼.

| 뺀 셋 | 고른 임계 | 그 셋의 오탐 |
| :--- | ---: | ---: |
| CWRU · MFPT · Paderborn · Paderborn(900rpm) | 3.05(네 폴드 일치) | 0/55 |

- 전체 풀에서 고른 값(3.03)과 다섯 폴드 중 넷이 일치 → 임계 안정.

## 5. 복조 대역 — 커토그램을 판정에 쓰지 않는 이유

판정용 포락선은 1~5 kHz 고정 대역에서 복조. 커토그램(대역별 충격성)은 계산해 화면에 표시만 함.

### 첫 번째 실패 — 안티에일리어싱 잡음

Nyquist 바로 아래는 필터가 신호를 죽인 구간이라 남은 수치 잡음의 첨도가 폭발하고, 커토그램이 늘 그쪽으로 끌려감.
상한이 없으면 결함 종류 적중 0/18, Nyquist의 80%로 자르니 7/18.

### 정식 스펙트럼 첨도(SK)로 고쳐도 같음

real 6% · 복소 절대값 6% · 복소 SK 7% — 셋 다 12~16 kHz대를 고름.
구현 결함이 아니라 목적함수 문제: 첨도는 톤성 대역을 구조적으로 깎음(순수 정현파 첨도 1.5 < 가우시안 3). 결함이 뚜렷할수록 그 대역을 피함.

### 두 번째 실패 — 전기 성분

인버터 구동 시험대(Paderborn)에서 커토그램이 정상·결함 구분 없이 12~19 kHz를 골랐고, 그 대역의 포락선이 한 성분에 덮여 있었음.

| 축 회전수 | 지배 차수 | 절대 주파수 |
| :--- | :--- | :--- |
| 1500 rpm | 2.10× | 52.5 Hz |
| 900 rpm | 3.50× | 52.8 Hz |

차수는 바뀌고 절대 주파수는 그대로 → 기계가 아니라 전기·구조 기원. 결함 검출 1/104(900 rpm에서는 0/84).

### 고정 대역으로 바꾼 결과(당시 기록)

383 케이스 전체에서 결함 검출 10% → 25%, 정상 오탐 2% → 3%, 종류 적중 90% → 95%.
(다른 문서의 "54% → 6~11%", 화면 힌트의 "57% → 6%"와 수치가 다름 — 불일치 목록 참고)

### 그 밖의 결정

- 샘플링이 낮아 1~5 kHz가 성립하지 않으면(Nyquist가 5 kHz에 못 닿으면) 전대역 해석 신호로 복조. 옛 버전은 이때 커토그램으로 되돌아갔는데 위 이유로 제거. 정류(절대값)로 물러서지 않는 것도 같은 이유 — 그 태그만 다른 방법으로 재면 판정 경로가 둘로 갈림. 이 경로는 검증 표본 없음.
- 아슬아슬했던 부분: 위 붙박이 성분(52.5 Hz, 2.10×)은 BSF(50.9 Hz, 2.04×)와 3% 차이. BSF 허용오차가 ±1%가 아니라 ±2%였다면 정상 베어링이 전부 볼 결함으로 오탐났을 것. 4극 1500 rpm 인버터 구동은 흔한 구성.
- 대형 설비: 1~5 kHz에 실제로 자주 걸리는 것은 가속도계 마운팅 공진이고, 베어링 링의 굴곡 모드는 설비가 커질수록 낮아짐. 검증 풀에 대형 설비가 없어 어느 방향으로 틀리는지 측정된 바 없음.

## 6. 시도했다가 물린 것

같은 오탐률에 고정하고 비교한 결과. 다시 시도하기 전에 이 표를 보십시오.
검출률은 시도 당시의 검증 풀·설정에서 잰 상대 비교값 — 현재 성적(66%)과 직접 비교하지 말고 같은 표의 "당시 현행"과만 비교.

| 시도 | 검출 | 왜 실패했나 |
| :--- | :--- | :--- |
| 당시 현행 | 54% | — |
| 커토그램으로 복조 대역 선택 | 6~11% | 첨도 최대화가 안티에일리어싱 잡음·인버터 스위칭 대역에 붙잡힘. 정식 SK로 고쳐도 마찬가지(real 6% · \|z\| 6% · 복소 SK 7%, 셋 다 12~16 kHz) |
| 실측 1× 기준 결함주파수 | 31% | 실측 흔들림이 BPFI(≈9×)에서 9배 증폭. 명판은 틀려도 일관되게 틀림 |
| 켑스트럼 프리화이트닝 | 29% | 대역통과가 이미 축 성분을 걸러, 남은 1×는 이산 성분이 아니라 변조 |
| 포락선 정수 차수 억제 | 45~48% | 16볼 BPFO가 7.09×라 정수와 1.3% 차이 — 축 계열을 지우면 근거도 지워짐 |
| 두 대역 하이브리드 | 동률 | Šidák 보정하면 이득이 사라짐 — 저역만으로 충분 |
| 롤업 RMS로 판정 앵커 지명 | 72% | 결함 근거는 진해지지만 건전 설비의 최대 순간 전이도 같이 찾음. 같은 오탐률에서 균등 배치가 89%로 이김 |
| 국소 잡음층 정규화 | 50% | 표적 주변 ±64빈 중앙값으로 나누면 강한 결함일수록 측대역이 잡음층을 부풀려 자기 근거를 깎음 |
| Stouffer z 결합 | 52% | 무정보 자리를 중립으로 만들어도 검출·내륜 모두 안 오름 |
| 제곱 포락선(SES) | 52% | 없는 하모닉을 만듦 — AM 합성에서 2차/1차 = 0.15 |
| 앵커 지속성 요건(K곳 이상) | 56~72% | 오탐은 눌리지만 단발로 서는 진짜 결함이 같이 죽음 |
| 저역 경계를 200 Hz로 낮춤 | 하락 | 축 회전 성분과 그 변조가 대역 안으로 들어와 격자에 우연히 맞음 |
| 네 축 최댓값(예전 방식) | 74% / 오탐 69% | 축이 늘면 등급은 올라가기만 해 ISO 축의 오탐이 그대로 화면에 나옴 |
| 학습 축을 게이트에 포함 | 오탐 3% → 15% | 같은 태그가 학습 여부에 따라 다른 등급 |
| 감시 창 50회전 | 검출 동일(59%) | 25회전과 같은데 비용만 2배 |

## 7. 회전수(RPM) 관련

- **1800 rpm 가정 제거**: 예전에는 RPM이 비면 1800 rpm으로 가정했음. 2극(3600)·6극(1200) 설비에서 격자가 통째로 어긋나면서도 화면은 평소처럼 등급을 냈음 — 조용히 틀리는 최악의 형태라 제거. 지금은 미입력이면 결함 패턴·대역 추출이 멈추고 "판정 못 함".
- **실측 1×를 대조에 바로 쓰지 않는 이유**: 공개 데이터셋 386건에서 실측 대조는 검출을 늘리지 못하고 정상 오탐만 100건당 2~3건 늘렸음(이 386건은 스냅샷 풀 383건과 구성이 다름 — 기록 확인 필요). 회전 피크가 약한 설비(가속도 센서 등)는 실측 자체가 잘 안 됨.
- **대역 추출 1× 실측 범위 ±5%**: 범위를 ±12%로 넓히면 벨트로 이어진 모터처럼 다른 회전체의 봉우리를 1×로 잡아 대역 경계가 통째로 밀림(NASA 122건 중 36건). 계통주파수(50/60 Hz) 봉우리는 제외.
- **종동축 회전수 오차**: 1.4% 오차에서 결함 부위 정답 99% → 85%. 풀리 바깥지름으로 환산하면 3~4% 틀리기 쉬움 → 피치 지름 사용 또는 잰 회전수 입력을 권고. 종동측인데 회전수가 없으면 0으로 처리(모터 회전수로 대조하면 엉뚱한 주파수가 우연히 맞아 부위 정답 2%).

## 8. 진단 근거 사례

- **진동 축과 베어링 축을 분리한 근거**: 실측에서 정상 베어링이 2~4 kHz 대역 ×3.97로 결함 베어링(×2.35)보다 높게 나옴 — 옆 베어링 결함이 축을 타고 그 센서에도 실림. 포락선 결함주파수만 보면 정상 최대 ×1.26 / 결함 최소 ×1.42로 갈림.
- **FTF를 점수에 넣지 않는 근거**: 정상 채널이 첫날부터 0.45× 하모닉 3개를 계속 냄.
- **종류를 단정하지 않는 근거**: BPFO ×1.42 / BSF ×1.39(2% 차)를 "외륜"으로 단정하던 사례가 있었음 → 1·2순위 근접 시 후보 나열 + "구분 불충분".
- **Crest 충격성 기준**: √(2·ln N) + 1 (N = 롤업 버킷 하나의 샘플 수, 1초 버킷·25.6 kHz면 약 5.5). √(2·ln N)은 잡음만 있을 때 버킷 최댓값의 기대값이라 여러 버킷의 P95와 견주면 정상 잡음도 늘 넘음. +1은 잡음만으로는 거의(0.1%) 넘지 않는 선. 버킷이 10초보다 길면 부하 변동만으로 최댓값이 커져 판단하지 않음.

## 9. 알림 설계 근거

- **확정을 분 단위가 아니라 회차로**: 예전에는 `진입 확인 시간`·`복귀 유지 시간`이라는 분 단위 설정이었음. 판정이 추출 주기(10분)로 돌아 1분·2분·5분이 전부 "다음 회차"가 되어 고르는 뜻이 없었고, 실측으로 확인한 뒤 제거.
- **'감시 이상' 행을 따로 둔 이유**: 예전에는 두절이 '주의' 라우팅을 탔고 주의의 기본값이 '알림 안 함'이라 한 건도 발송되지 않았음(이력 271건 · 발송 0건).
- **'주의' 기본 즉시**: ISO가 등급을 만들던 시절엔 정상 설비의 69%가 주의 이상이라 꺼 두는 게 맞았으나, 게이트 구조에서 주의는 오탐 3~4%짜리 결함 패턴 검출 신호.
- **계측 이상 확정 1분·복귀 5분을 설정으로 노출하지 않는 이유**: 실측에서 계측 이상이 22일에 4건 — 튜닝할 만한 빈도가 아님.
- **대역이 알림을 내지 않는 이유**: 8개 계열을 각각 한계와 대 보고 하나라도 넘으면 켜는 구조라 그 자체가 다중비교(단독 오탐 13%).
- **베이스라인이 알림을 내지 않는 이유**: 판정값이 10초 축 구간 RMS라 10분 축 등급 이벤트와 시간축이 섞임. 대가 — 단독 오탐 0%·검출 28%인 가장 깨끗한 축이 알림에서 빠짐.

## 10. 운영 진단 (관리자·개발자용)

### 서버 감시가 돌기는 하는데 아무것도 안 할 때 — 심박

```sql
SELECT K, VAL FROM NEO_BEARING_STORE.SYS.MONSTATE WHERE K='<계정>:__hb';
```

- `n` = 그 회차에 처리한 태그 수. 0이면 회차는 도는데 전 태그를 건너뛰는 중.
- 흔한 원인은 데이터 테이블 권한: 목록·화면은 GRANT로 동작하지만 감시 TQL은 롤업을 쓰므로 그 테이블에 `SELECT`가 없으면 조용히 0건.
- `ms`가 한 자릿수면 아무 조회도 못 한 것.

### 타이머 중복

Neo는 타이머 이름 중복을 막지 않음. 앱은 등록 전에 같은 이름을 전부 지우고 확인하지만, 목록 조회가 실패하는 동안 생긴 중복은 못 막음.
삭제만 하고 멈추지 않으면 러너가 남아 계속 실행됨 — 반드시 멈춘 뒤 삭제.
